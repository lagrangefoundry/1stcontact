I fixed this in the test setup only, with no production code changed. All four failing tests now load and pass, including from a checkout that is missing the `ai-ticketing.js` shim.

**Cause:** both Workers test files stopped at import with `Cannot find module ./generated/ai-ticketing.js`. Nothing in the tests or the product was wrong. There were two gaps in the setup that makes sure the generated shims exist:
1. **Incomplete list:** `REQUIRED` in `tests/global-setup-generated.ts` was kept by hand and named only six of the generated modules the control app imports. It was missing `ai-ticketing.js`, `ai-imagegen.js` and `auth-passwordless.js`, so a checkout holding older shims was never regenerated.
2. **Node project only:** the setup was registered only on the node vitest project, so a run of the Workers tests alone never generated anything.

**Changes:**
- **`tests/global-setup-generated.ts`:** the required list is now built at run time from the control app's own imports. It scans every source file under `apps/control-app/src/` and collects each import that points into `src/generated/`, treating a bare name as `<name>.js`. A new shim therefore can't be missed. If the scan finds no imports at all, the setup stops with an error rather than passing with an empty list. It still runs the real generator (`buildControlAppAssets`, the same as `1c assets`) and still checks afterwards that every required file was written.
- **`vitest.workers.config.mts`:** registers the same `globalSetup`, so a run of the Workers tests alone generates the shims too.

**Checks:**
- I deleted only `apps/control-app/src/generated/ai-ticketing.js` and ran just the AC2025 and AC2372 tests. The setup regenerated the file with the real generator, and all 4 failing tests passed.
- Both Workers files plus `tests/reconciliation-assistant-looking-surface.test.ts` (node project) then passed together: 3 files, 26 tests. That run covers the rest of the scope (AC2022, AC2023, AC2024, AC2030, AC2035, AC2373).
- I could not run lint or the typecheck on the two edited files. `npx eslint` failed because the sandbox blocks npm's registry, and there is no root `tsconfig.json`. The quality gate will be the first to check them.

No acceptance criteria or story changes were needed, since the behaviour was always correct.
