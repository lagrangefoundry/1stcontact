# Reference and reproduction read a linked icon's role from different nodes: 4 CRITICAL "missing" + 4 unpaired, which is all of unmeasured 8

Round: `repro-console:repro-www-bluelotusintegralhealing-com#3`. Bundle
`storage/references/www.bluelotusintegralhealing.com/index` (captured
2026-10-04T15:20:22.610Z). This is the only bundle I have evidence from.

**defect_class: `instrument-asymmetric`.** Both sides run the same extractor
(`extract.ts` `a11yRoleOf`/`semanticOf`) on two DOM shapes that mean the same thing,
and it returns `link` for one and `img` for the other. The 4 icons are drawn, in the
right place, and linked. The 8 deltas and unmeasured-8 come from the ruler, not from
the page.

## Evidence

`gate.json`: `unmeasured 8 — 0 axes, 0 bands, 8 populations, 0 probes`.
`values-diff.json`: `matched 50 · unmatched 4`, 4 × `{"text":"(link)","role":"link","property":"missing","expected":"present","actual":"absent","tier":"CRITICAL","severity":4060}`,
and `unpairedActual` = 4 records with `"role":"img"`, labels "Go to Facebook page",
"Go to Instagram page", "Go to Tiktok page" and "Go to Pinterest-p page".

They are the same four elements:

| | reference (`expected-manifest.json` #47) | reproduction (`actual-manifest.json` #48) |
|---|---|---|
| role / a11yRole | `link` / `link` | `img` / `img` |
| text / accessibleName | `(link)` / `""` | `Go to Facebook page` / `Go to Facebook page` (nameSource `alt`) |
| src | `assets/inline-svg-f21dae30.svg` | `…/assets/inline-svg-f21dae30.svg` |
| href | `https://www.facebook.com/profile.php?id=61559658360969` | the same |
| box | `(59.97, 2784.22) 24×24` | `(59.97, 2784.22) 24×24` |

The other three match the same way, at x 87.97 / 115.97 / 143.95.

The two DOMs are:
- reference `raw.html`: `<a href="https://www.facebook.com/…" title="Go to Facebook page" class="social-icons__link"><svg width="24" height="24" …>`
- reproduction `site/index.html`: `<a href="https://www.facebook.com/…" style="display:contents"><img class="l1-47" id="image-2" src="assets/inline-svg-f21dae30.svg" alt="Go to Facebook page" />`

In the reference, the recorded element is an `<svg>`, which isn't in
`SEMANTIC_ANCESTOR_SEL`, so `semanticOf` → `el.closest(SEL)` finds the `<a href>` and
`a11yRoleOf` returns `link`. In the reproduction, the recorded element is an `<img>`,
which IS in `SEMANTIC_ANCESTOR_SEL`, and `closest()` matches the element itself before
it reaches the anchor, so the result is `img`. Textless elements pair on
`a11yRole` + document order, so neither side finds a partner. This is REQ-302 issue 3
(role read on one node, href on another) again, for media inside a link. The actual
record shows the contradiction: it carries an `href` next to `a11yRole: "img"`.

There's a second, smaller asymmetry in the same records. The reference's accessible
name is `""` though the anchor has `title="Go to Facebook page"`, because
`accessibleNameOf` doesn't read `title`. The reproduction gets the same words from
`alt`. Once roles pair, the `name` parameter will mismatch for that reason.

## Proposed change

In `semanticOf`, media (`img`, an icon `svg`) whose nearest interactive ancestor is
`a[href]` resolves to the link, on both sides. That's the a11y tree's own answer
(a link named by its image). Read `title` as a fallback name source for a link with no
text. Re-capture after it lands, since the reference side is capture-time.

**This removes 8 unmeasured populations and should add comparisons.** The 4 icons'
box, src, objectFit and href will start being compared instead of reading as
missing/unpaired.

## What changed (implementation)

**Rule (capture, both sides).** Media — an `<img>` or an `<svg>` — that is the ONLY ink of a link (`a[href]` or `[role=link]`: the link holds no other `<img>`/`<svg>` and no text of its own) is that link:

- `a11yRole` is `link` (via `semanticOf` → new `linkedMediaHostOf`), so the reference `<a href><svg>` and the L1 reproduction `<a href style="display:contents"><img>` record the same role and pair.
- `accessibleName` is the link's name, in a11y order: the link's own `aria-label`/`aria-labelledby` → the media's own alternative text (`<img alt>`, or an `<svg>`'s `<title>`; `nameSource: 'alt'`) → the link's `title` attribute (new `nameSource: 'title'`). The reference's title-only icon link now names "Go to Facebook page", matching the reproduction's alt.
- A picture beside its link's own copy (`<a href><img>About us</a>`) is NOT covered — it keeps `a11yRole: 'img'` and its own alt.
- The sole-ink test is shared with REQ-380's `svgIconHostOf` (one `soleMediaHostOf(media, selector)`), not duplicated.

**values-diff.** Because a linked picture now reports `link`, "is this media?" no longer reads `a11yRole === 'img'`: an element is media when its role is `img` OR it carries `objectFit` (recorded only for `<img>` and inline-SVG icons). So paired linked icons get the image card and the media comparisons (`objectFit`, `objectPosition`, aspect) — e.g. a reproduction that crops an icon (`cover`) where the reference fits it (`contain`) is an `objectFit` delta. `nameSourceLabel` reads `title`.

**Capture schema 19 → 20.** The reference side changed, so a pre-20 bundle is behind: a new stale axis ("a linked icon's name, read off its link") is reported when the bundle holds an inline-SVG icon whose `alt` is set but whose `accessibleName` is empty. The bluelotus bundle needs a re-capture for the reference half of this fix to apply.
