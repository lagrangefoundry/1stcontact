## Symptom

After the dispatcher resync of `xgd-working` at 2026-11-04 11:30 PST (resync commit `53a51caa4c`, published tip `ab3f8d4aff`), the dev control-app worker no longer starts. `bin/deploy --env dev` and `bin/dev restart` both end with "The dev worker on port 8786 is not answering (connect ECONNREFUSED 127.0.0.1:8786)". `storage/tmp/dev/dev-worker.log` shows the migration guard refusing:

> The local database is behind this checkout — 3 migrations have not been applied: 0004_retire_site_slug.sql, 0014_dns_changes.sql, 0020_turn_log.sql

## Root cause

The resync (xgd BUG-1647) rebuilt `xgd-working` on main (`9437245023`) by replaying 34,543 non-merge commits since WM2 (`ad9e9a8860`, Jul 9). It skipped all 686 merge commits. Every edit made inside a merge commit since the previous successful resync (Aug 20) vanished from the tree:

- **Migration renumberings undone.** `0005_retire_site_slug` / `0017_dns_changes` / `0021_turn_log` went back to their pre-merge duplicate numbers `0004` / `0014` / `0020`. Every database (dev and prod) recorded the renumbered names, and `db/migrations/manifest.json` still lists them. So dev refuses to start, and a production deploy would re-run three already-applied migrations against live data.
- **Other merge-resolution edits lost**, e.g. `0001_baseline.sql` lost its ticket-change-log section, and ~300 code/test files (router, stores, AI host, builder CSS, wrangler.toml, vitest configs, …) went back to older or mixed versions.
- **Untracked files committed.** The resync commit also tracked three untracked media files in `example-businesses/ariels-arcwelding/` (`images/Eagle.png`, `images/Heron.png`, `old-scratch-fire.mp4`).

## Fix

One forward commit restoring the non-`.xgd/` tree. No reset, no history rewrite: other sessions have committed since. Paths resolve at file level against B = `b167abd969` (the Aug 20 common ancestor of the pre-resync tip O = `5c944771e2` and the resync base M = `9437245023`):

- A path changed **only on main** since B (O unchanged since B) takes main's version. These are reconcile-authored tests, FC→AC renames and test_fix edits that legitimately arrived through the resync.
- **Every other path takes O**, the pre-resync working state that dev and production were last deployed from. Main's hunks are not mixed in line by line: where both sides changed a file, main holds older cherry-picked versions of code O has since moved past, and a line-level merge would mix stale code into current files.
- The three swept-in media files stay tracked, so the merge does not delete the operator's files from disk. Untracking them is left to the operator.
- `.xgd/` is not touched.

Being an ordinary non-merge commit, this repair survives future resyncs' replay, which a merge-commit edit cannot.

## Acceptance

- `db/migrations/` matches `manifest.json` again (`0005_retire_site_slug`, `0017_dns_changes`, `0021_turn_log`). The dev worker starts after `bin/deploy --env dev` with the existing local database, and its migration guard passes.
- For every non-`.xgd/` path, the tree equals the rule above.

## Test plan

No new UATs. This restores content that is already covered and adds no behaviour. Evidence:
- The migration guard (existing) passes against the live dev database: `bin/deploy --env dev` brings the worker up on 8786.
- A scripted check that the committed tree equals the file-level rule for every path.
- Existing migration/manifest suites and a typecheck run on the repaired tree.


## Outcome (commit 25ea6e7f9e, merged into xgd-working as 57ce8be283)

- 171 paths restored to the pre-resync tip and 3 deleted (the misnumbered `0004_retire_site_slug` / `0014_dns_changes` / `0020_turn_log`). Measured against `5c944771e2`, the repaired tree differs only by 134 added files: 131 that never existed on the working branch (reconcile-authored tests, plus main's `.pnpm-store/v11/index.db` and two `dinas-diner` images) and the 3 swept-in media files.
- `db/migrations/` and `manifest.json` agree, and all 46 migration files match the dev database's `d1_migrations`, so the dev worker's migration guard passes.
- Migration suites `BUG-85_migration_path_guard`, `REQ-291_applied_migration_content_drift` and `BUG-273_attributed_models_migration` pass. `tsc -p apps/control-app` is clean. `tsc -p tools/generate` went from 11 errors before the repair to 2, and both remaining errors (`material-import.ts`, `zip-reader.ts`) also occur without it.

That is main's ancient migration, which the working branch deleted on 2026-09-05, so the test fails both with and without this repair.
