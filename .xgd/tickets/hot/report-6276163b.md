## Code changes

- **`tests/reconciliation-builder-markdown-readiness.test.ts`** — added the
  reconciliation UAT for AC-1819, in the same file as `test_UAT_AC1816_*` as the
  review's remediation directs:
  `test_UAT_AC1819_the_displayed_page_is_refetched_per_write_and_a_failed_refetch_keeps_the_reply`.
  It drives the real `mountBuilder` against the actually-installed `webui-chat`
  with only the HTTP transport injected, and covers all three of the criterion's
  claims:
  - *Per write, during the turn.* Two writes → the displayed page is fetched
    again twice. Strengthened beyond the FC suite's total-only assertion: the
    transport samples the re-fetch count immediately before each of the six
    events leaves the host, and the test asserts the exact sequence
    `[0, 0, 1, 1, 2, 2]`. A total alone cannot distinguish "edit by edit while
    the assistant is still working" from "once when it stops talking"; this
    sequence can, and it fails an implementation that waits for the reply.
  - *A question leaves the page alone.* No writes → count stays 0 across the
    whole turn, and the answer still arrives.
  - *A failed re-fetch never costs the reply.* The frame's `reload` throws on
    every call; both writes are still acted on (the second is not abandoned
    because the first threw) and the assistant's reply is still in the transcript
    in full.

  The seam is counted at `app.panel.frame.contentWindow.location.reload` — the
  same object and the same call the palette popup and the segment editor already
  make — because jsdom's own `contentWindow` cannot navigate. Each mount awaits
  the workspace's `markdownReady` before sending, since AC-1063 means nothing is
  painted (and no chat exists to send into) before the engines settle. The file
  header was updated to name plan item 10 and AC-1819 alongside item 9's
  AC-1063/AC-1816.
- **`tests/reconciliation-material-row-content-type.workers.test.ts`** and
  **`tests/test_UAT_FC_REQ-172_material_content_type.workers.test.ts`** — the
  literal NUL (and, in the second file, SOH) bytes embedded in the `bytesOf(...)`
  fixture strings replaced with the equivalent JavaScript unicode escapes, per the
  review's final Judgment Call. `file` reported both suites as `data` and `grep`
  skipped them as binary, which hid AC-1813's UAT from the review's own first
  sweep and would equally hide them from an orphan or coverage scan. The encoded
  bytes are unchanged (`TextEncoder` maps U+0000 and U+0001 to 0x00 and 0x01), so
  this is inert at runtime; both files now parse clean under esbuild and are
  visible to text tools.
