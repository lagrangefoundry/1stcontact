## What I built

The assistant now has three verbs over a **second ticket store, which is ours**: `ReportBug`, `RequestCapability`, `AddTicketDetail`. The client's store is untouched and still read-only to it. `WriteTickets` was never granted.

**Question 1 — which store, and how a Worker reaches it.** This was the real work. The surface takes a project handle; upstream's only shipped one spawns the xgd CLI, which workerd cannot do. So `1c builder` — the one Node process that lives exactly as long as the dev server — now starts a **loopback filing service** holding the real `XgdProject`, and the Worker holds an HTTP client to it, addressed by two `--var`s minted per run. Everything needing judgement (two-call read-back, xgd error translation, `WrittenButUnreadable`) stays upstream; both halves here are transport. This is the shape upstream anticipates — "the same three methods can be served over HTTP by a ticket server" — so a hosted server later is an address in `[vars]`, not a code change.

Consequence I decided and flagged: **filing is a development capability**. A deployed builder has no project to reach, so no address → no surface → the assistant has never heard of the verbs, rather than being offered tools that always fail.

**Question 2 — the barrier the other way.** One sentence appended to the shipped overview through `DevelopmentToolbox`'s own `declarationOverride` seam: name surfaces, operations, arguments, outcomes; don't carry their brief, material or conversation. As an overview amendment rather than a priming entry, so it exists precisely when the tool does.

**Question 3 — duplication.** No second registry. Reading REQ-256 first is what produced that: a console keeps a file because its rounds share no memory; a chat session is the opposite — the id comes back on filing, the transcript replays, and filing only happens when asked. `add_ticket_detail` covers the rest. No rate cap, because a cap could only refuse under codes that would lie about whether anything was filed.

**Question 4 — what the client sees.** Nothing, structurally: nothing on this path holds a `TicketStore`, a tenant or a business. A UAT asserts it against a real tenant store.
