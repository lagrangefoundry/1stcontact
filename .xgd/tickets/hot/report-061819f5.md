### FAILURE 2 — AC-1652 (story-a58a0974, in scope): red, and now decidable

Not executable here (workers project), reported red by report-ec36c19e. Its node
twin **AC-1318 fails identically and I observed that directly** this cycle:

```
AssertionError: expected [ 'KnowledgeChanges', …(4) ] to deeply equal
                         [ 'KnowledgeChunkSearch', …(2) ]
+ "KnowledgeChanges"     + "KnowledgeOutline"
```

Both assertions pin `READ_SET = ['KnowledgeChunkSearch', 'KnowledgeGet',
'KnowledgeSearch']` as an **equality**, deliberately, so an operation added
upstream cannot enter the grant unnoticed. Upstream widened the read group to
five. The grant is filled from the declaration
(`knowledgeInstanceConfig([SYSTEM_KB])`), so this is unpinned shared-store drift,
not a repository change.

**This review supplies the fact the previous two cycles were missing.** Both new
operations were read out of the upstream declaration
(`@lagrangefoundry/ai-knowledge/src/knowledge_surface.json`):

| Tool | Line | `effect` |
|---|---|---|
| `KnowledgeOutline` | 201–204 | `"read"` |
| `KnowledgeChanges` | 273–276 | `"read"` |

**Both are `effect: read`.** AC-1652's substantive claim — *the grant is
read-only and scoped to the system knowledge base on both axes* — is therefore
**still true against the current code**. What is stale is the assertion's
*mechanism*: an identity snapshot of a three-element list standing proxy for a
property.

**Remediation — this one is actionable now, and it is a test change, not a
matrix edit:** restate the assertion to assert the claim rather than the
snapshot — that *every* granted `Knowledge*` operation declares `effect: read`,
and that the grant names `SYSTEM_KB` and no other knowledge base. That is
strictly **stronger** than the current equality (it would still catch a write
operation entering the grant, which is the property the equality exists to
protect) and it is drift-proof against read-only additions. Widening the literal
list to five is the weaker alternative and is acceptable only if the
property-based form is rejected.

AC-1318 fails on the identical assertion but is **out of scope** for this bundle;
it should be filed against the framework-migration ticket alongside AC-1317 and
AC-1319, not repaired here.

  certified either.** Socket permission is a property of the session. They are

  and they include three of the bundle's load-bearing boundaries (the
  SSRF/redirect guard, identity admission and expiry, the republishable-rights

- **The last fix cycle made real progress and should not be undone.** 24
  criteria moved from unrunnable to green, two genuine SSRF defects were closed,
  and a missing D1 migration was transcribed. The direction is right.
