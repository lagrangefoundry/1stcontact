## Notes for the Editor

**Note 1 — the evidence was executed, not just read.**
`npm test -- tests/reconciliation-builder-private-access-gate.test.ts` → **10
passed**. `npm test -- tests/reconciliation-builder-private-access-automation.test.ts`
→ **3 passed, 1 failed**.

**Note 2 — the one failure is a sandbox artifact, not a defect, and is recorded
as such rather than as a finding.** `test_UAT_AC1453_...` timed out at 60s with
an uncaught `Error: listen EPERM: operation not permitted 127.0.0.1`. The
causal chain is unambiguous: `stubApi` calls `server.listen(0, '127.0.0.1', …)`,
this sandbox denies binding a loopback socket, the listen callback never fires,
so the `await stubApi(...)` promise never resolves and the test hangs to the
timeout. Subprocess spawning itself works — AC-1451's `bin/publish` runs passed
in the same file — so only the socket bind is denied. **I could not execute
AC-1453's assertions in this environment and am not claiming they pass.** The
test is nonetheless substantive by inspection: it drives `bin/access-token` as a
real process against a real HTTP stub and asserts on recorded requests, which is
exactly the shape the AC's own reconciliation note demands in place of the
source-pattern-matching it replaced. If a downstream fix loop needs AC-1453
green, it must run in an environment permitting `listen` on loopback.

**Note 3 — the evidence-validity rules are met throughout.** Neither file mocks
an internal component. The gate file stubs only `globalThis.fetch` (the team's
key publication — the network) and supplies `DB`/`SITES`/`ASSETS` as tripwires
that record being touched rather than as stand-ins for behaviour any assertion
depends on; every claim is about a `Response` from the real exported `fetch`
handler, and the JWTs are minted per-run rather than fixtures. The automation
file stubs only `fetch` (as a recorder) and stands a real `http` server where
Cloudflare's management API stands; the push claims go through `pushSite` and
the real `1c` `run` entry point, the operator scripts are spawned as processes,
and the policy record is read as a file.

**Note 4 — no `needs_review`.** No AC or story text names an abandoned,
deprecated or `wont_fix` ticket as a delivery vehicle, so Step 2.5's
stale-citation case does not arise. Every intent in the ledger is
`free_and_reconciled`.
