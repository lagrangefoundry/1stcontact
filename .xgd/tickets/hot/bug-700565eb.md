## Symptom

Every builder conversation fails to open. The chat shows:

> lib4.registerDefaults is not a function

On a new business it also leaves the ordinary text box showing instead of REQ-403's "Click here to start" button. REQ-403 is in the dev snapshot; the button never gets its chance because opening the conversation throws first. This blocks every builder session, not only new businesses: the consultant (site and business) and the settings assistant alike.

## Root cause

lagrange-framework **BUG-83** (`5a2f3f1906`, 2026-10-10, "a session-memory core every host gets, configured not replaced") changed how session memory reaches a host:

- the memory layers (memory charter, tool work-log note, summary, budget gauge, per-turn memory reminder) moved into a **framework-owned core** that the manager composes around every host's product, gated on a home ticket;
- they are configured through the product's **`memory:` block** (`MemoryConfig`), every layer on by default and off only by name, with unknown keys refused;
- the summary store is now **derived from the archive** (`TicketArchive.summary_store`), so the manager's `summary=` option is gone;
- `registerDefaults`, the default product files and the `transcript_pointer` / `summary_trigger` providers were **deleted**;
- **a host registry that rebinds a core-owned provider name is refused** (`CORE_PROVIDERS` in `memory.js`).

The shared `@lagrangefoundry/*` store is not version-pinned, so its next refresh delivered this, and nothing here was changed to match. `tools/generate/src/cli/ai/host-core.ts` still calls `lib.registerDefaults(...)` twice:

- ~line 1821, the consultant's manager — binding the tool-transcript note and its `hasToolTranscript` reader;
- ~line 2645, the settings manager — binding the occupancy gauge before `registerBudgetProvider` (REQ-296).

Note: earlier test runs cited bug-d672f592 (BUG-63) as tracking this. It does not — BUG-63 is the September `KnowledgeDocs` migration. Until this ticket, no ticket owned the BUG-83 adoption, and conversation suites have been run against a temporary pre-BUG-83 copy of the library, which hid the breakage.

## Fix

Adopt BUG-83's memory core rather than work around it.

1. **Remove both `registerDefaults` calls.**
2. **Configure memory through the product's `memory:` block**, for each role that has one (consultant, coordinator, settings, delegated builder), choosing deliberately which core layers each role keeps. Anything a role must not be told (e.g. the settings assistant has no `agent` surface, so it must not be told its turns are addressable by id — REQ-296) is switched off by name, not by omission.
3. **Resolve the provider-name collisions.** This host registers its own providers for names the core now owns — at least `session.summary` (REQ-283: the ledger in the chat ticket body plus the standing frame in `fields.frame`), and possibly `session.budget` and `session.tool_transcript_note`. Each one is either removed in favour of the core's, or kept under the core's configuration if `MemoryConfig` offers that. A rebinding the core refuses must not be left in place.
4. **Keep REQ-283's memory intact.** The consultant must still read back its decisions ledger (body, KB-indexed) and its standing frame (`fields.frame`, capped, an error never a truncation) every turn. If the core's archive-derived summary store can be pointed at that storage, use it; if it cannot, the gap is a lagrange-framework ticket, not a fork of the core here. Nothing already recorded in any chat ticket's ledger or frame may be lost or moved.
5. **The settings assistant keeps its occupancy gauge** (REQ-296) through the core's budget layer.
6. **Delegated builder sessions** get whatever the core gives a ticket-homed session, and nothing that grants them the project KB (they must never read the client conversation).

## Out of scope

- Pinning the shared `@lagrangefoundry/*` store to a framework version. Worth doing, separately.
- Reinstalling a pre-Oct-10 framework as a workaround — it would also roll back web search (LF REQ-206) and the empty-reasoning fix (LF BUG-81).

## Implementation (as landed)

The host no longer calls anything BUG-83 deleted and binds no core-owned provider name. The memory core is configured once, in `tools/generate/src/cli/ai/priming.json`'s new `memory` block, and loaded with the host's own product tier by `productConfig(lib, providers, entries)` in `roles.ts`.

**Per manager, not per role.** `MemoryConfig` lives on the manager's product, so it cannot differ between roles that share a manager. The consultant, the coordinator and the delegated builder share one manager; the settings assistant has its own. Both managers use the same `memory` block.

**What the `memory` block keeps, and why each other layer is off:**

- `charter` — **on**. Every ticket-homed session is told "This conversation is ticket <uid>". Its window line is overridden (`prose.memory_charter_window`) to drop the claim that older exchanges are "in your summary and your transcript": a delegated builder and the settings assistant have neither.
- `summary` — **off**. The core's summary reads a `chat_summary` comment that this host never writes. REQ-283's record (the standing note in `fields.frame` and the decisions ledger) is still delivered by the host's own provider, now under `memory.record`. Nothing stored moves.
- `transcript` — **off**. Through the Claude API adapter (`sessionGrant`) it would also give each session a second agent toolbox whose summary tools write that comment, next to the `agent` surface and `read_work_log` this host already grants. That would split the memory in two.
- `reminder` — **off**. Its wording names summary and transcript tools this host does not grant. The host's `memory-trigger` reminder, which names `set_standing_note` / `record_decision`, stays.
- `budget` — **off**. The framework deliberately does not restore occupancy when a session resumes, so on the Worker (where the manager is rebuilt per request) the core's gauge would always be blank. REQ-296's gauge reads the durable figure instead.

**The host's product tier** (`product_priming`) keeps the old tier's order under host-owned names: `memory.transcript_pointer` and `memory.work_log_note` before the cache boundary, then `memory.record` and `memory.budget` after it.

**Provider renames** (moved off names the core owns): `session.summary` → `memory.record`; `session.budget` → `memory.budget` (the settings role's reminder tier is updated to match); `session.transcript_pointer` → `memory.transcript_pointer`; the tool-transcript note becomes `memory.work_log_note`.

**Other changes:**

- The transcript pointer's wording is now the host's own (`templates.transcript-pointer`), because BUG-83 deleted the framework's `transcript_pointer` prose.
- `registerBudgetProvider(providers, measured, prose)` now renders the gauge itself, using the framework's own `DEFAULT_PROSE.budget` / `budget_no_window` text and the same digit grouping and half-up rounding. The core does not export its budget provider and cannot be given an occupancy source.
- `SessionMemorySource` gains `hasWorkLog(sessionId)`, so the work-log note is still bound only where the ledger surface is composed.
- No session's ledger or frame data is moved or rewritten.

**Gaps that belong to lagrange-framework (not forked here):** (a) the core's summary store cannot be pointed at a host's own storage; (b) the core's budget layer reads only in-memory occupancy, and `budgetProvider` is not exported. If either were supported, the matching layer could be switched back on.
