## Intent (Step 0)

Read from the bundle body and each source ticket. What the operator stated they
were building:

- **REQ-108** — a typed L1 axis that lights a band's grid teal under the cursor,
  following the shape REQ-100 (scroll reveal) established: one typed value bag
  plus one vetted renderer-owned script, fail-visible, round-trip-safe. Explicit
  scope note in the body: *"Nothing else changes: fills, grid colour, spacing and
  thickness are untouched"*, and *"those grids were pre-existing and were not
  added by this ticket"*. Two mid-implementation corrections recorded on the
  ticket: the operator asked for the `#problem`/`#close` grids to be removed
  (they became fully transparent patterns the accent redraws), and a bug — the
  accent died after a window focus change — was found and fixed.
- **REQ-109** — rendered output was not relocatable. Declared boundary: *"No
  change to the authored L1 schema or to any site definition"* and *"no base-path
  or host configuration on the renderer"*.
- **REQ-110** — R2 artifact store plus `1c deploy`. Declared frame: *"this ticket
  migrates serving, not the canonical store"*; no D1, no custom domains, no
  subdomain routing.
- **REQ-111** — the public-site Worker, behind a `SiteStore` seam phase 2 swaps
  for D1. No authentication (previews are unguessable-URL-private by decision),
  no apex marketing site.
- **REQ-113** — `1c serve` 404'd extensionless URLs. The ticket's own premise
  ("Cloudflare Pages is the deployment target") was later found **false** and the
  scope was extended on the ticket: the Worker serves everything, so the state
  was the *inverse* of the reported defect and the production half had to be
  fixed too.
- **BUG-30** — `relativizeUrl` turned `/#frag` into a same-page anchor. The
  ticket also asked for the rest of the sink to be checked while there; the
  implementation found and fixed a second case (a colon in the first segment
  re-admitting a `javascript:` URL the safety check had just refused).

  *delivery* — getting a rendered site off the operator's laptop and in front of
  a visitor. All 13 existing capabilities stop at the rendered bytes on disk.
- **Why 3 and 4 are not one story.** They are separated by the artifact contract,
  not by code layout: REQ-110 and REQ-111 were explicitly designed to be built in
  parallel against the R2 layout as a shared spec, and each is independently
  useful (a deploy with no server still produces a durable artifact; a server
  with no deploy still has a testable grammar). Merging them would produce a
  6-point story.
- **Why 5 is not folded into 4.** Its user-visible claim is *agreement between
  two environments*, and half of it lives in `1c serve`, which the Worker story
  has no business owning. The defect history is the argument: REQ-113 fixed one
  environment on a false premise about the other, and the ticket's stated goal
  was reached only when both were changed. A story naming both is what stops that
  recurring.
- **STORY-90 over STORY-83 for the pointer accent** — judgment call. The schema
  field is spread into the shared *surface* group (STORY-83's territory), but
  every load-bearing property of the capability is STORY-90's: a renderer-owned
  script, a marker gate armed on first interaction, fail-visible degradation,
  reduced-motion and headless-capture inertness, and no script when unused. Those
  are AC-820/823/825's exact claims extended to a third axis.
- **BUG-30's colon case is a security finding, not a cosmetic one.** `isSafeUrl`
  clears `/javascript:…` *because* the leading slash makes it relative; the strip
  handed the live scheme back. It is captured under STORY-83 rather than STORY-91
  because it is the emitter re-admitting a value the sink refused — AC-851's
  "independent lines of defence" claim — and because the same one rule guards all
  three sinks.
- **Uncertainty carried forward, from the tickets themselves, not invented here:**
  REQ-111's `wrangler dev` smoke check against the real bucket and the apex custom
  domain was never run (the UATs drive the Worker's real `fetch` against a faked
  R2 binding); the deploy-time reserved-`draft` gate is a standing invariant that
  no current site definition can trigger, tested at its own entry point; and
  REQ-109's full `1c l1-gate` re-run against `gigabytealchemy` was not possible in
  session, though the analytic gate is over the L1 document and never sees emitted
  URLs.
- **No FC-test obligation was supplied** with this anchor (`fc_tests` empty), but
  the suites the commits add are all `test_UAT_FC_*`-named — `req108`, `req109`,
  `req110`, `req111`, `req113` (×2), `bug30`. Each plan item above covers the
  behaviour of exactly one or two of those files, so the story cycle has a
  renaming target for every one.

  `l1-fold-full-language`) fail identically on a clean tree, verified on two of
