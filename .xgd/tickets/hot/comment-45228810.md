## What changed

**The discriminator** — `noBaseline?: boolean` on `RailReport`. I chose this over the ticket's alternative (`kind: 'unavailable'` on the phase) because "nothing was measured at all" is a property of the whole run, not of one phase. `runRail` sets it and changes nothing else on that path: `pass` stays `false`, the explanation stays on the phase as a failure, so `repro-rail` still exits 1 and `--json` consumers still read the reason where they always did.

**Three renderers read it:**
- `summarise` returns the not-available line *before* the phase loop — that ordering is the fix, since the loop is what prefixes every phase failure with `REGRESSED ·`.
- `runRailRound` returns `{ available: false, summary }` with `pass` left undefined — the exact shape the throw and `RAIL=off` paths already use. `rail.json` and the round prompt both come off that result, so one change fixes both.
- `formatRailReport` prints `NOT AVAILABLE` instead of `FAIL` followed by the missing baseline filed under *"what is worse than the recorded bar"*. This wasn't in the ticket's proposal; I included it because it's the same false claim in the terminal view. Exit code untouched, per the ticket.

**One superseded assertion.** `test_UAT_FC_REQ_256_the_rail_runs_read_only_and_its_result_is_shown` pinned `summary.split('\n')[0]` containing `REGRESSED` — precisely the behaviour this ticket declares wrong. Its surrounding intent ("never a green line nothing produced") is unchanged and still asserted, now in the new vocabulary. The supersession is recorded in the ticket body.
