## Symptom

On 2026-10-27, DOC-33 (the old 11-stage playbook) was taken out of the knowledge base: its `doc_kind` changed from `system_kb` to `architecture` at about 18:02 UTC. The operator then ran `bin/build`, and `1c kb ensure` reported "the index covers all N corpus document(s) … nothing to build".
- `kb/system/DOC-33.md` stayed on disk and stayed in the index.
- The 20:05 UTC dev deploy shipped it.
- At 20:12 the Site consultant's knowledge-base search on Dina's Diner 6 returned DOC-33's "Stage 2 — Positioning & differentiation", the method DOC-75 replaced.

## Root cause

`kbEnsure` (`tools/generate/src/cli/kb.ts`) decides whether to build only from `requireCoherentKb`. That check asks whether the index matches the files in `kb/system/` (`missing`, `stale`), whether the projections match their sources (`outdated`), and whether the awareness map covers the files.

It never asks whether the files in `kb/system/` still match the doc tickets. Only `exportCorpus` reads the tickets: it writes each `system_kb` ticket's file and deletes the files of tickets that left. But it runs only inside a build, which `ensure` never starts while the index agrees with the stale files. So these three changes are all invisible to `ensure`:
- a ticket leaving the knowledge base (DOC-33);
- a ticket joining it;
- a ticket's body or title being edited.

DOC-74 and DOC-75 only got in because a full build ran at 17:56 UTC.

## Fix

- `ensure` compares the corpus an export *would* write against `kb/system/`, without writing anything: files to add, files to remove, and files whose content would change.
- Any difference counts as skew. It's reported by document id and kind ("DOC-33: no longer system_kb, will be removed"), and it triggers a build: export, then index.
- The same comparison is part of what `1c assets` refuses to ship on, so a deploy can't ship a knowledge base that disagrees with the tickets. It's the same check in both places, as `requireCoherentKb` is today.
- An unchanged corpus still reports "nothing to build", and doesn't touch file stamps (`exportCorpus`'s byte comparison is kept).

## Test plan

- `test_UAT_FC_BUG-303_ensure_builds_when_a_doc_leaves_the_kb`: with a corpus and index that agree, change one ticket's `doc_kind` away from `system_kb`. `ensure` reports that document as to-be-removed and builds, and afterwards its file is gone from `kb/system/` and from both index manifests.
- `test_UAT_FC_BUG-303_ensure_builds_when_a_doc_joins_or_changes`: a new `system_kb` ticket, or an edit to an existing one's body, is reported and built.
- `test_UAT_FC_BUG-303_ensure_is_quiet_when_tickets_match`: tickets and corpus agree, so "nothing to build", and no file's mtime changes.
- `test_UAT_FC_BUG-303_assets_refuses_a_corpus_behind_its_tickets`: `1c assets` refuses while a ticket and its corpus file disagree, naming the document.

## What landed

- `corpusBehind(held, tickets)` in `tools/generate/src/cli/kb.ts` is a dry run of `exportCorpus`. It uses the same rendering (`corpusDocument`), the same membership (`inSystemKb`) and the same file namespace (`isExported`, now shared with the export's sweep). It returns one line per document an export would add, remove or rewrite:
  - `DOC-33: no longer system_kb (now architecture), will be removed`
  - `DOC-9: no doc ticket, will be removed`
  - `DOC-75: now system_kb, will be added`
  - `DOC-74: ticket changed, will be rewritten`
- `kbSkew` reads the doc tickets (one `xgd ticket list`) and compares them against the bundle's own text. That's a new `behind` list in `KbSkew`. A non-empty `behind` is skew, so `requireCoherentKb` throws. `kbEnsure` then builds, and `1c assets` (`writeKbModule`) refuses before writing anything. `kbSkewError` adds an opening sentence about the corpus no longer matching its tickets, and a `BEHIND its tickets` section listing those lines.
- The "nothing to build" line now starts with "the corpus matches its doc tickets", and the `1c kb` usage text describes the new trigger.
- An unchanged corpus is still `current` and no file is rewritten.
- No tickets are read when there is no index (`kb/system/` is gitignored, so CI has no bundle), because the comparison only runs on a bundle.

## Test fixtures

Suites that bring their own corpus now need a ticket store that agrees with it. Without one, they are read against this repository's real store. `tests/support/kb-fixture.ts` gains three helpers:
- `useTicketStore(tickets)`: an `xgd` shim on `PATH`; returns the undo.
- `writeTicketCorpus(root, tickets)`: writes each file exactly as the export would.
- `adoptCorpus(root)`: turns a hand-written fixture corpus into tickets and installs the store.

The BUG-48, BUG-156, REQ-322 and REQ-358 suites use these, and their literal `KbSkew` values gain `behind: []`.

The UATs are in `tests/test_UAT_FC_BUG-303_corpus_follows_its_tickets.test.ts`, as named in the test plan.
