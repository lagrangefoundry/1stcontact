## Symptom

Since REQ-451 moved `claude_builder` to `claude-haiku-5-5` (commit `69066798f9`, 2026-10-24), the cost reports show **every past build's builder spend as Claude Haiku 5.5**, and price it at Haiku 5.5's rates. Those builders ran on Claude Haiku 4.5, at ten times the per-token price. Old builds therefore appear several times cheaper than they were, and the console's per-model split ("did construction move to the cheap model") is wrong for all history. Reported by the operator in EPIC-20.

## Root cause

`attributedSpend()` (`tools/generate/src/cli/ai/spend-core.ts` ~726) reads the builder entries in `turn_spend.attributed`. The framework stores each entry with a backend name and no model, so the function fills the model in with `modelOfBackend(backend)`: **today's** `backends.json`. Its own comment says so ("it is the model configured today"). The cost is then priced from that model too. Every report that reads `attributed` inherits this: the console's delegated spend and `byModel` (`apps/control-app/src/spend.ts`) and the spend report (`spend-report-core.ts`).

Per-request rows (`request_spend`, BUG-254) store the model each request actually used and are correct. But builder entries older than 2026-10-23 exist only in `attributed`. In the dev store: 113 turns carry `attributed` entries. Every builder request before **2026-10-25T00:16:21Z** is `claude-haiku-4-5` (1,033 rows); the first `claude-haiku-5-5` request is at that time (19 rows, one tenant).

## Fix

**A stored record keeps the model it ran on; nothing is priced or labelled from current config.**

1. **At write time:** when the host merges a delegation's `attributed` entries into the turn record, it stamps each entry with the model its backend was bound to *at that moment*. That's the same resolution `SpendMeter` already does live.
2. **Reading:** `attributedSpend()` takes the entry's stored `model`. An entry with no stored model gets one from step 3. If one still has none, it is reported as "model not recorded" and **left unpriced**. It is never resolved from today's config. Delete the `modelOfBackend` fallback; don't keep it beside the new path.
3. **History:** a one-off migration stamps the model on every existing `attributed` entry that lacks one, from the configuration in force when its turn ran. For `claude_builder` that is `claude-haiku-4-5` for every turn before REQ-451 reached the running host. Take the cutover from the first `claude-haiku-5-5` row in `request_spend` for that environment (dev: 2026-10-25T00:16:21Z), never from the commit date. `claude_coordinator` is `claude-haiku-4-5` throughout. Apply it to the dev store and the remote store.
4. **Check the other readers** of stored spend for the same pattern (any `modelOfBackend` used to label or price a stored record rather than a live request) and fix them the same way. List them in the commit.

## Test plan

- UAT: a stored `attributed` entry written while `claude_builder` is configured as `claude-haiku-4-5` still reports `claude-haiku-4-5`, priced at Haiku 4.5 rates, after `backends.json` changes the builder to `claude-haiku-5-5`.
- UAT: a new delegation after the change records and reports `claude-haiku-5-5`, priced by its card (REQ-451).
- UAT: an entry with no stored model (and none supplied by the migration) is reported as "model not recorded" and unpriced, not as today's model.
- UAT: the migration stamps entries before the environment's cutover with `claude-haiku-4-5` and leaves entries that already carry a model untouched.


## Also: per-request rows drop the cache-write split

Found on the same review (2026-10-25). `request_spend.cache_write_5m_tokens` / `cache_write_1h_tokens` are null on **every** row, for every model: 1,033 Haiku 4.5, 19 Haiku 5.5 and 353 Opus 5.5 rows. Yet the framework reports the split (REQ-216): the older `attributed` entries carry `ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens`. With no split, a request's writes are all priced at one lifetime. The builder (system 1h, messages 5m) has every write priced at the 1-hour rate, overcharging its 5-minute message writes by 60% (Haiku 5.5: $0.20 vs $0.125 per million, below 100K). Fix with the rest of this ticket: store the split on each request row when the usage record carries it, and price each part at its own rate.

- UAT: a request whose usage reports `ephemeral_5m_input_tokens` 900 and `ephemeral_1h_input_tokens` 100 stores both on its `request_spend` row and is priced 900 at the 5-minute rate and 100 at the 1-hour rate.
