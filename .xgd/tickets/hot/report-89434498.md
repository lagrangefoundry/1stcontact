## Notes for the Editor

**Workspace caveat — read before acting on any of the above.** This assessment ran in the regression
worktree `regression-cb0dad9c`, which is **487 commits behind `main`** and predates BUNDLE-19's merge
at `b18b859d`. None of this capability's code or tests exists in the checked-out tree: there is no
`bin/build`, no `bin/deploy`, no `bin/smoke`, no `tools/generate/bin/smoke.mjs`, and no
`tests/reconciliation-platform-build-deploy-smoke.test.ts`. Everything above was read from `main`
(via `git show main:<path>`), which is also where the ticket CLI resolves the matrix — so the matrix
and the tests were compared at the same commit and the comparison is sound. Two consequences for
whoever picks this up:

- A `grep` for `test_UAT_AC133*` in the working tree returns nothing and would produce a false
  "no UATs exist" verdict. It is a stale checkout, not a coverage gap.
- `.xgd/uat_index.json` in this worktree has `acs: {}` — zero entries, for every AC in the project,
  not just these. It was useless for this assessment and the tests were located by reading the
  suite directly. Treat an all-zero index as an index problem, never as evidence of absent coverage.

**No fix workflow is warranted by coverage.** All three findings are warnings and none affects
pass/fail. Findings 1 and 3 are both `test_UAT_AC1337`; if they are actioned at all they should be
actioned in one edit to that test's breakage table — adding an `expects` field to each row and four
more rows covers both.
