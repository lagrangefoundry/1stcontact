`ai_site_assistant`), one story (STORY-103 / story-a58a0974, `story_kind =
upgrade`), 23 active ACs, 27 AC-named UATs across five suites.

**Why this is a FAIL, stated up front.** Nothing here is a missing test and
nothing is a badly written one. Three of the four knowledge UATs **error against
the shared assistant library that is actually installed**, and one of those three
errors because the production wiring it exercises is broken:
`tools/generate/src/cli/ai/host.ts:160` calls `bridge.KnowledgeDocs.open(...)`,
and `@lagrangefoundry/ai-knowledge` no longer exports `KnowledgeDocs`. A test
that throws is not evidence, so AC-1317, AC-1318 and AC-1319 currently have no
valid evidence — which is a coverage verdict even though the lever that fixes it
is production code and criterion text, not test authoring. See the findings.

**On `previous_attempt_count = 3`.** The only prior `uat_coverage_check` reports
for this capability are REPORT-2071 / 2073 / 2075 (2026-08-16), which assessed
**eleven** ACs — the tree before the 2026-08-20 knowledge ACs and the 2026-08-31
BUNDLE-20 / BUNDLE-21 ACs existed. Their PASS is why `uat_coverage: pass` was
still sitting on the capability, the story and AC-1051…AC-1061 when this call
started while twelve ACs carried no value at all. That stale aggregate was not
treated as evidence: all 23 ACs were re-derived from the ticket store and every
test body was read in this call.

**What was executed, and what was not.** This call ran what the sandbox permits.
`tests/reconciliation-assistant-conversation-artifact.test.ts` **passes 3/3**
(AC-1406, AC-1407, AC-1410 — live evidence, not a reading).
`tests/reconciliation-assistant-conversation-knowledge.test.ts` runs and **fails
3 of 4** (AC-1320 passes); those failures are the findings below and are real —
no network, no socket, no fixture of mine is involved. The remaining three suites
could not be executed here at all: `startBuilder` and the workerd pool both need
to listen on a socket and the sandbox refuses (`EPERM: listen 0.0.0.0`,
`builder.ts:363`), so `reconciliation-assistant-conversation.test.ts` reported
"12 skipped" after its `beforeAll` threw. The 20 `pass` verdicts on those suites
therefore rest on reading the test bodies against the criteria, which is what this
stage's Step 1b asks for — they are **not** claims that those suites are green
today. One thing bounds that risk usefully: the drift below is confined to
`@lagrangefoundry/ai-knowledge`. The artifact suite loaded
`@lagrangefoundry/ai`'s Workers rung live and found `Session`, `SessionManager`,
`Toolbox`, `ClaudeAPIBackend` and `memoryJunctions` all present, so the library
the conversation suites depend on is in sync.

## Notes for the Editor

- **One upstream package moved, and it is the whole of this report.** All three
  violations are the same event seen three ways: `@lagrangefoundry/ai-knowledge`
  has changed since 2026-08-20 — five declared read operations instead of three,
  provenance relocated from the operation to the knowledge base, and priming
  replaced by providers. Fix them as one pass against the installed package, not
  as three independent repairs.
- **The lever is production code and criterion text, not test authoring.** These
  four knowledge UATs are among the better-evidenced in the tree — real corpus,
  real `DocDirStore`, real index, real cosine search, real Toolbox with real
  gating and a real audit sink, with only the embedding model standing in at the
  single model boundary. They failed *because* they assert equalities instead of
  absences. Repair what they point at; do not relax them.
- **The dependency is not pinned by this repository.** The library is resolved
  through `webuiPackageDir` out of the shared `@lagrangefoundry` store that
  lagrange-framework's `bin/install` writes, so nothing in this checkout's
  lockfile holds it still and this drift can recur silently on any machine. Worth
  a note in the story's Technical Context; the framework-side change itself is
  another repository's business and must not be edited from here.
- **The twelve unset verdicts are now written.** AC-1317…AC-1320, AC-1404…AC-1410
  and AC-1456 carried no `uat_coverage` value before this call — REPORT-2075
  predates all of them. Every one of the 23 now carries a verdict, as do the story
  and the capability.
- **What this check could not do.** Three of the five suites cannot start under
  this sandbox (both `.workers.test.ts` files and the Node builder suite all need
  to bind a socket). Their 20 verdicts are reading-based, per Step 1b. If the
  execution stage can bind sockets, its result on those suites is the authority on
  whether they are green — this report claims only that each case exercises its
  criterion through real entry points, which they do: real HTTP against a real
  `startBuilder`, real workerd against real D1 and R2, the real session manager,
  the real tool loop, the real `edit.ts` write path, real SSE and real stored
  transcripts, with the Anthropic client — the network — as the single double, and
  since BUG-39 a double that speaks the streaming wire protocol the backend really
  consumes.
