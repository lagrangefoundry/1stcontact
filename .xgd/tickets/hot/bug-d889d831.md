## What happened
Builder workers added display fonts with `use_font`. Each page/look's page style `resources.fonts` lists an entry such as:
```
{"family": "Bebas Neue", "src": "/_fonts/bebasneue/BebasNeue-Regular.woff2", "style": "normal", "weight": 400}
```
Text elements set `axes.fontFamily` to `"Bebas Neue, sans-serif"` (and similarly `Alfa Slab One`, `DM Serif Display`).

None of these faces render:
- **`screenshot` of the draft**, at 1280px desktop: the Bebas Neue headings show as plain uppercase Helvetica/Arial (not condensed), Alfa Slab One shows as a plain sans, and DM Serif Display shows as a Times-like default serif.
- **The client's own browser**, opening the same looks through the preview's looks carousel: the same thing, "they look pretty ordinary - one is in caps, one is a serif font".

So it is not only the screenshot renderer: the font files are either not served at the `/_fonts/...` path, not declared as `@font-face` from `resources.fonts`, or declared under a family name that doesn't match `fontFamily`.

Also note: the builder worker asked to verify rendering reported `passed` ("the tall, narrow condensed capitals render as intended") when they did not. See BUG-225 on worker self-certification. A host-side check would help, e.g. comparing glyph metrics with `measure_drawing`, or a `describe_page` attention item "font requested but not loaded".

## Expected
A font fetched with `use_font` and listed in a page style's `resources.fonts` loads in the preview, the published site and screenshots, and any element whose `fontFamily` names it renders in it. If loading fails, `describe_page` should flag it (as it already flags "no font: paints the browser's face").

## Reproduce
1. `use_font` "Bebas Neue" (or "Alfa Slab One", or "DM Serif Display") on a page; confirm `get_page_style` shows it under `resources.fonts`.
2. Set a text element's `axes.fontFamily` to "Bebas Neue, sans-serif".
3. Take a `screenshot` of the draft, or open the preview in a browser: the text renders in a fallback face.

## Impact
Every type decision on the site is invisible. The client cannot choose a font from options, and the chosen "Bold & alive" look has never displayed its intended headings.


## Root cause (diagnosed 2026-10-18)

Two independent defects. The page data is correct: the stored looks declare the faces under `resources.fonts`, and the renderer emits matching `@font-face` rules with `src: url("_fonts/…")`. The dev log shows the preview answering those font requests with 200.

1. **The mirrored woff2 bytes are malformed. This breaks the preview, the published site and screenshots alike.** `sfntToWoff2` (`tools/generate/src/fonts/woff2.ts`) ends the file right after the Brotli stream, with no padding to a 4-byte boundary. The woff2 decoder in Chrome and Firefox (Google's, via OTS) rejects a file where `Round4(compressedOffset + compressedLength) > length`. Chromium was used to confirm this: `new FontFace(..., bytes).load()` fails with "Invalid font data" for BebasNeue-Regular (24717 bytes), AlfaSlabOne-Regular (39593) and DMSerifDisplay-Regular (34699). The same bytes padded to a multiple of 4, with the header `length` updated, load fine. 2680 of the 3566 mirrored files are unaligned (≈¾, as expected), so most platform fonts fail and roughly a quarter happen to work. The mirror's incremental carry keeps any staged file whose sha matches the manifest, so fixing the encoder alone would never rewrite the broken files.
2. **Screenshots cannot fetch platform fonts at all.** The screenshot browser is served in-process by `previewOriginResolver` (`tools/generate/src/cli/preview.ts`). It goes straight to the renderer, which holds no `_fonts/…` file, so every platform font 404s. Only the router's `/preview` route answers `_fonts/` (REQ-312's "every channel that serves a snapshot answers `_fonts/…` at its root" — this channel was missed).

## Fix

- **Encoder:** pad the compressed block with zeros to a 4-byte boundary; the header `length` includes the padding.
- **Decoder:** `woff2ToSfnt` refuses a misframed file (header `length` ≠ file length, or not 4-byte aligned) the way browsers do. That makes the mirror's own round-trip assertion catch this class of defect from now on.
- **Mirror:** a staged file that is not well-framed is not carried as "unchanged"; it is re-encoded. Re-running `1c fonts mirror` therefore rewrites exactly the broken files.
- **Screenshots:** `previewOriginResolver` answers `_fonts/…` from the same platform-font reader the `/preview` route uses, and `sessionFidelity` passes it that reader. The router resolves the reader in one place.

## Operational follow-up (operator)

The code fix does not repair bytes already staged or published. After it lands: `1c fonts mirror --repo <google/fonts checkout>` (re-encodes the misframed files), then `bin/deploy --fonts --env dev` (seeds local dev) and `bin/deploy --fonts --env production` (publishes).

## Not in this fix

A `describe_page` "font requested but not loaded" item. `describe_page`'s audit is static (nothing is rendered), and this failure only shows up when a browser decodes the bytes. With the bytes fixed and the decoder now refusing misframed output at mirror time, the class is closed at its source. Worker self-certification stays with BUG-225.

## Test plan

- `tests/test_UAT_FC_BUG-227_platform_fonts_load.test.ts` drives the real `fonts mirror` entry against a real TTF.
  - Every mirrored woff2 has its header length equal to its file size, is 4-byte aligned and still round-trips, and the manifest records the padded bytes and sha.
  - An unpadded (old-encoder) woff2 is refused by the decoder as "Misframed WOFF2".
  - A staged old-encoder file whose manifest entry matches is re-encoded on refresh instead of carried.
- `tests/test_UAT_FC_BUG-227_screenshot_serves_platform_fonts.workers.test.ts` drives the production `sessionFidelity` → `screenshot` assembly with the font in the real R2 binding at its published key. The draft's `_fonts/<slug>/<file>` request is fulfilled in-process with 200 and `font/woff2`, never sent to the network. A face the mirror doesn't hold is fulfilled as 404.
- Each new UAT was confirmed to fail with its fix removed.
- Regression scope: every suite touching `_fonts`, the font mirror, `sessionFidelity` or `previewOriginResolver`, plus REQ-157 and REQ-363: 21 files, 235 tests, all passing.
