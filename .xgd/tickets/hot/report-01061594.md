All 9 failing tests now pass (9/9 in `tests/reconciliation-client-knowledge-base.workers.test.ts`), which should also clear the 9 orphaned-AC entries for AC-1655 to AC-1657 and AC-1660 to AC-1665. I didn't re-run the full quality gate.

**Root cause:** the tests were written against an older version of `projectKnowledgeFor` that took the account id from `env.TENANT_ID`. The frozen code now has the signature `projectKnowledgeFor(env, scope, opts)` and takes the account from `scope.businessId` (`apps/control-app/src/knowledge.ts:659`). The tests passed the options object where the scope now goes, so `scope.businessId` was `undefined`. That produced `D1_TYPE_ERROR` inside `ticketStoreFor` for eight tests. In AC-1664 it produced a `TypeError` instead of `AiNotConfiguredError`.

**Test-only changes:**
- `knowledgeEnv()` no longer sets `TENANT_ID`. A new `scopeFor(accountId)` builds the account scope, and `openKb` passes it to `projectKnowledgeFor(env, scope, { embedder })`.
- AC-1664 now calls `projectKnowledgeFor(withoutModel, scopeFor(...))`. It also asserts that the refusal names the REST remedy (`CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN`) as well as the binding one, because AC-1664 requires both.

No production code changed, and no ACs or the story needed updating: the code does what they say.

I didn't commit the change; I've left it in the working tree for the reconcile workflow.
