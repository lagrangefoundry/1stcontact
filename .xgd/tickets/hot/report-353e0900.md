## Advisories (not blocking; recorded for the record)

### A — six AC-named UATs report *passed* while asserting nothing when Chromium is absent

`tests/bug27-nested-backdrop-capture.test.ts` Part A wraps its six capture UATs in a local helper that
returns early when the browser did not launch:

```ts
const itA = (name, fn) => it(name, () => { if (!capture) return /* Chromium unavailable */; fn(...) })
```

Chromium is **not** installed in this worktree (verified: `browserType.launch: Executable doesn't exist
at …/chromium_headless_shell-1228`), and 60+ other tests skip for the same reason — so the runner this
pipeline uses does not have one either. Under that condition `test_UAT_AC815_*` ×2 and
`test_UAT_AC816_*` ×4 execute no assertion yet are counted green. AC-816 retains four browser-free fold
UATs; **AC-815's only evidence is the two vacuous ones**, so deleting the band-extent fix would leave
the suite green on this runner.

Not raised as a blocking gap, for three reasons: the assertions themselves are strong and specific and
do run where Chromium exists; the logic under test lives inside the `page.evaluate` string
(`getBoundingClientRect` / `window.scrollX`) so browser-free coverage is not available without a
redesign; and the matrix already accepts browser-gated ACs (AC-683, AC-688 are active with only skipped
UATs). The defect is **reporting honesty**, not test design.

**Recommended (cheap, no AC change)**: replace the `itA` early-return with `it.skipIf(!browserOk)`, the
idiom the rest of the repo uses and the one this very fix pass applied to the `storage/references`
tests — so AC-815/816's capture half reads as *unproven here* rather than as *proven*.

### B — AC-871 has no passing UAT in a browser-less worktree

`test_UAT_AC871_fresh_site_shoots_without_hand_editing` is honestly `skipIf`-gated and skips here. Its
sibling AC-870 proves the render half browser-free; only the screenshot half is gated, which inherently
needs a browser. Consistent with the AC-683/AC-688 precedent, so accepted.

### C — the fix introduced production code during a reconcile

`packages/site-schema/src/issues.ts` (new) plus edits to both validators are runtime behaviour that no
free-coded commit in this bundle carried. It is intent-aligned — REQ-107 states the envelope's error
messages "exist to tell an AI author exactly what to fix, per DOC-8 §6", and the union collapse meant
that promise was unmet — and it was one of the two remedies REPORT-1383 explicitly named. Flagged so
the change is attributed to REQ-107's diagnostic clause rather than appearing as unattributed drift.

## Judgment Calls

- **Advisory A is not a FAIL.** The FAIL bar is "a UAT that would pass even if the AC's behavior were
  removed". AC-815's UATs meet that bar only *conditionally on a missing browser* — the same condition
  under which the matrix already tolerates AC-683 and AC-688. Failing here while those stand would be
  inconsistent, and the only in-loop remedy (honest `skipIf`) leaves AC-815 with zero passing UATs
  rather than more evidence. Recorded, not blocked.
- **Advisory C is attribution, not drift.** REQ-107's own text makes the actionable error message a
  declared property of the envelope; the change closes an intent-implementation gap that reconciliation
  surfaced, and the prior review authorised exactly this remedy.
- **AC-816's evidence mix accepted.** The fix mapped four *fold* UATs onto AC-816 alongside the four
  capture ones, which the fix report itself flagged as a judgment call. They are not redundant with
  AC-812: AC-812 proves the fold's placement in the background layer, while AC-816's fold UATs prove
  the band-edge bounding and the fill/veil carriage that the capture side feeds. Kept.
- **xgd.dev site-content criteria correctly absent** (REQ-104 AC4, REQ-103 AC6) — the plan's
  untracked-site caveat excludes site definition data from capability surface.
- **REQ-107's triage criteria (AC4/AC5) not carried as ACs** — one-time migration activity, not durable
  capability. Acceptable.
