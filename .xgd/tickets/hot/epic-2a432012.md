## Intent

Short (3–10 s), silent hero clips made from a site's existing still photo, generated by an AI image-to-video provider and placed by the builder as a typed L1 media node. Two motivating cases:

- **Dina's Diner, steak and eggs (reveal, plays once):** the clip opens on the plate without pepper, a grinder comes in and peppers the eggs, the camera moves a little way around the plate, and the clip ends on the real photo (about 2–3 s). The clip then stays on that last frame.
- **Ariel's Arc Welding, Old Scratch (seamless loop):** the fire from the mouth and horns and the smoke move realistically, and the sculpture and camera stay still. This replaces the hand-drawn SVG flicker overlay (`scratch-flicker-2.svg`, BUG-259) with real fire motion.

Background: the field study DOC-69 (Joyful Culinary Creations) found a hobbyist builder shipping AI image-to-video hero loops in a first draft. DOC-69 lesson 4 says still-to-loop video should be a typed L1 media primitive, not raw `<video>` HTML (Security Policy §3).

| Option | Fit | ~Price |
|---|---|---|
| **fal.ai** (one key; Kling, Veo 3.1, Seedance 2.0, Wan, MiniMax) | Image-to-video and first/last-frame endpoints (`end_image_url`). Kling v1.6 Pro on fal takes `static_mask_url` / `dynamic_mask_url` (motion brush) for "freeze everything but the fire" | Varies by model; Kling about $0.08–0.11/s, Wan much lower |
| Google Veo 3.1 direct (needs a **new** Google key; 1stcontact has none, and the LF imagegen `google` backend reads `GOOGLE_API_KEY` but nothing here sets it) | Strong realism; has a first-last-frame mode | Lite $0.05/s, Fast $0.10/s, Standard $0.40/s (audio included, which we strip) |
| Luma Ray | Has an explicit `loop: true` flag and `frame0`/`frame1` keyframes | about $0.30 per 5 s at 720p |
| Runway Gen-4 Turbo / 4.5 | Good camera control | $0.05–0.12/s |

**Third playback shape: ping-pong (boomerang).** On the Joyful draft, `hero-pack.mp4` (10 s, 242 frames) is a palindrome: frame *i* matches frame *N−1−i* at about 40 dB PSNR throughout, with the turnaround at the centre frame. The page plays it with a plain `<video muted loop playsInline>` and no script, so the reversal is **baked into the file**. (`hero-pour.mp4` is not a palindrome. Its first and last frames match, so it is a first-equals-last loop.) Ping-pong turns any short clip into a seamless loop without needing a model that takes a matching last frame, and it doubles the playing time we pay for. It suits camera moves and gentle motion. It is wrong for fire, smoke, pouring and falling pepper, which would visibly run backwards. Browsers can't reliably play `<video>` backwards (Chrome rejects a negative `playbackRate`), so the reversed half must be added when the file is processed, not when it plays.

**How each case maps onto the models:**
- **Loop:** use the source as both the first and last frame, or Luma's `loop` flag. Camera locked. An optional static mask freezes the subject.
- **Ping-pong:** generate a 2–5 s clip of any motion, then append the reversed frames when the file is processed.
- **Reveal:** the existing `EditImage` makes the start frame (the photo with the pepper removed), and the original photo is the end frame, in first/last-frame mode. Because the clip ends exactly on the original, the poster, the last frame and the reduced-motion fallback are all the real photo.

**Recommendation:** ship one backend first: fal.ai, model chosen per mode (Kling or Seedance for reveals, Kling with a mask for loops). It needs one new secret either way, and it also gives access to Veo. Add a direct provider only if quality or price needs it.

## Plan

### A. LF: `ai_videogen` component (mirrors `components/ai_imagegen`)
- Surface `videogen`, group `AnimateImages`, op `animate_image`. Inputs: source material id, motion prompt, `mode: loop | pingpong | reveal | free`, optional `start_frame` material (for reveal), duration 3–10 s, `camera: locked | slow_orbit | push_in`, optional freeze-mask material, 720p by default.
- Backend `components/videogen/js/src/backends/fal.js` follows the imagegen backend pattern. It submits the job, polls until done, and asks for no audio. Prices go in `pricing.js`, and the estimated cost is reported the way `describeGeneration` already does.
- Runaway-loop cap, like imagegen's `DEFAULT_BUDGET`.

### B. 1stcontact host wiring
- `apps/control-app/src/videogen.ts` mirrors `imagegen.ts`. It gets a new secret, `FAL_KEY`, via `bin/deploy.d/secrets/`; if the key is missing, the tool is left out. Results are stored as a `material` ticket with `kind: 'video'` and the bytes in BLOBS. When published, they appear at `/assets/*.mp4`.
- Add a `slow-tools.json` entry giving roughly 2–4 min, and use the REQ-205 progress heartbeat while polling.
- **Size budget:** silent H.264 MP4, aim for under ~1 MB, never autoplay audio. A processing step is **required**, not optional: it strips audio, re-encodes to the size budget, and for ping-pong appends the reversed frames. Workers can't run ffmpeg, so options are a fal.ai ffmpeg/compose endpoint, Cloudflare Media Transformations (resize/trim; reversing not confirmed), or a container. To be decided in the child ticket.
- **Spend:** video cost is per second, not per token. Add a non-token cost row path into `turn_spend`/`request_spend` (which today only counts tokens) so clips show in the REQ-292 reports. Add a per-site generation cap.
- **Disclosure:** the client's photo is sent to an AI provider (Architecture Policy 26). The client is told before the first generation.

### C. 1stcontact L1: typed `video` node
- New node type, sibling of `l1ImageSchema` (`packages/site-schema/src/l1/schema.ts`), `.strict()`:
  - `src` must be an `.mp4`/`.webm` that passes `isSafeUrl`.
  - `poster` (an image src) is **required**.
  - `playback: loop | once`, where `once` holds on the last frame. Ping-pong needs no renderer value of its own, because the file is already a palindrome and plays with `loop`.
  - `restMs` for `loop` clips: after each play, rest on the final frame for this long, then play again. Example: Lagrange Foundry's robot hands move a little, stop, wait 10 s, move again.
  - `replay: every_visit | once_per_session` for `once` clips. Both are needed and chosen per video. With `once_per_session`, a repeat view in the same browsing session shows the final frame (the poster) without playing. A session key per clip `src` is kept in sessionStorage.
  - `trigger: load | in-view`.
  - The same fit/zoom axes as image.
  - Muted and `playsinline` are always on and cannot be configured.
- Renderer (`packages/framework/src/l1/render.ts`) emits `<video muted playsinline autoplay [loop] preload poster>`. Under `prefers-reduced-motion` it renders the poster only. It never emits `controls` or audio.
- Capture round-trip (`capture(render(L1)) ≈ L1`, REQ-82) and REQ-82 envelope security/robustness UATs for the new node: unsafe src/poster rejected, unknown keys rejected.

### D. Consultant / builder guidance
- Teach when to offer motion: at most one hero clip per page, and subtle movement. Steer prompts towards reveal or loop. Show the cost before generating. The priming budget is near full (BUG-129), so keep this to op summaries.

### E. Pilot
- Generate Dina's pepper reveal and the Old Scratch fire loop on dev, place them, and compare against the SVG flicker overlay. Evidence is the pilot clips plus page captures.

## Motion survey and taste guide (from EPIC-19, 2026-10-26)

**Why:** motion is where we can beat a $20 Wix site. Fade-ins are a commodity, but a story-carrying
effect (Old Scratch's flames, the XGD SVG effect) isn't. The failure mode is overdoing it. The
consultant needs an earned opinion on **how to add wow tastefully**, and a list of ways to do it
that it can talk a client through.

**The survey:** 20–30 well-made small-business sites that use motion (barbers, restaurants, makers,
studios, musicians). For each, record the pattern, why it works or doesn't, and a screenshot or
clip. Output: a doc of patterns with dos and don'ts and examples. It becomes the consultant's
reference for finishing touches (the DOC-71 §9.2 stage guide), and possibly comparison-board
material.

**Starting examples:**
- **3L Barber Co (3lbarberco.com):**
  1. A black-and-white shopfront loop playing forward then back, with a slow pan or zoom, faded
     into the black background and sitting partly under the text. Believable (window reflections),
     very stylish.
  2. A black-and-white still of a shave with red steam billowing. Obviously artistic, and it
     carries the accent colour.
- **Sarah's new site:** two videos side by side on the home page. One is her unboxing containers of
  food (authentic, but dull). The other is a spoon with a big dollop falling off it (aspirational,
  "healthy decadence"). A legitimate attempt to pair authenticity with marketing style; unclear
  whether the pair works.
- **Our own:** Old Scratch's flames (Ariel 2: the ~50c clip was the best spend in the site's $71),
  the XGD SVG effect, and Dina's steak-and-eggs clip (below).

**Working tests (from the EPIC-19 discussion):**
1. The motion carries the story or the brand.
2. It's clearly real or clearly art, never the uncanny middle; and real must not be dull.
3. It respects the page: text contrast protected, and **one signature effect plus entrance reveals**
   as the baseline.

**Working vocabulary:**
- living hero (cinemagraph);
- ambient loop under the text;
- artistic accent in the brand colour;
- drawn SVG brand motion;
- product moment;
- craft clip, trimmed to its best seconds;
- entrance reveals (the baseline).

**Don'ts:**
- competing signature loops;
- motion behind body text without protected contrast;
- unconvincing AI that's meant to look real;
- motion unrelated to the story;
- motion on every section;
- heavy clips;
- sound.

**Lessons from Dina's steak-and-eggs clip (Dina 3, 2026-10-26):**
- **Generating from the finished photo adds to what's already there.** The pepper grinder added
  pepper to eggs that were already peppered, so there's too much pepper. The start frame (or the
  prompt) must account for the end state.
- **Unfinished actions ruin the last frame.** A salt sprinkle that never completes leaves
  motion-blur streaks on the final frame. The clip must end on a clean frame, ideally the original
  photo.
- **Two phases work: an eye-catcher, then subtle ongoing motion.** The operator added this: an
  opening action that **ends on the original image**, then a gentle ongoing loop (steam off the
  coffee). It catches the eye without becoming repetitive or annoying.
- **The subtle element needs room in the composition.** The coffee sits near the top edge, so its
  steam is cut off. Choose or reframe the image so the ongoing motion has space.
- **Strong continuous motion wears out fast.** Even Old Scratch: "I couldn't leave that page open."
  Ongoing motion should be subtle. The strong action plays once.

**Survey done (2026-10-26): [[DOC-72]].** It covers 33 live sites across food, grooming, makers and studios, with clips measured and frames inspected. In brief:
- the most common failure is file weight, not taste;
- nearly every loop measured hard-cuts back to its start, so seamless loops set us apart;
- near-still real footage (a living photo) is the most tasteful pattern;
- real footage must look *chosen*;
- photoreal AI of something that isn't the client's breaks trust;
- skilled sites fail by having too many good clips;
- test 3 is refined to "one motion language";
- a new test 4: it must work when the motion never plays (poster only).
**Decided (2026-10-26), DOC-72 §6:** WCAG 2.2.2 (Level A) requires a pause control on any autoplaying motion longer than 5 s. Endless loops get a **small pause button that appears on mouse-over** (always faintly visible on touch screens). Filed as **REQ-471**.

**Process (DOC-71 §12.9):** the signature effect moves into the first draft, **discussed with the
client first**. Ideally it brings their own images to life. Other finishing touches stay at the end.
