## Symptom

On production, 2026-10-28, the operator asked the Site consultant on the 1st Contact site (`site_c4bed79aeb647305a5e3098f70d6dca3`) to change two config keys on the `signin` account-chrome module on `home`: `businessesLabel` → "My businesses", `portalLabel` → "Your account", BUG-299's leftover overrides. The operator's own editor can't change them.

The consultant briefed a builder (scope `home.json`, those two keys only). The host refused before the builder opened:

    design_first: no first pass has landed and the site design has not been written

The site has built pages and published revisions. It was built before plans recorded first passes or sites had designs.

## Root cause

The first-build holds decide "this is the first draft" from the plan alone: no `milestones.first_pass_at`. Those holds are `design_first` (REQ-448), `structure_first` (REQ-460) and `effect_first` (BUG-306). A site built before those milestones existed never records one, so every `Delegate` on it is held as a first draft.
- Writing a design to get past the first hold risks re-rendering the whole site.
- It would then meet `structure_first`, which wants a page plan, and `effect_first`, which wants a hero signature-effect decision. None of that has anything to do with a config change.

## Fix

1. **A site that already has a built draft or a published revision is not on its first build.** The first-build holds apply only when the site has neither a first pass recorded, nor pages beyond the starter placeholder, nor any published revision. Settle the exact predicate here, reading the draft and revisions the host already has.
2. **On such a site, the plan's first-pass milestone is back-filled** from the existing draft or revision the first time the host sees it, so every reader of "first pass landed" agrees: holds, agenda, guides and hand-over.
3. **No first-draft machinery on an established site:** no first-draft stage guide, no hand-over lead, no signature-effect hold.

## After it lands (operator)

Ask the Site consultant again: "bc: set `businessesLabel` to "My businesses" and `portalLabel` to "Your account" on the `signin` module on home; change nothing else; don't publish". Then publish, so 1stcontact.io's links are fixed (BUG-299).

- `test_UAT_FC_BUG-311_built_site_delegate_is_not_held`: a site with built home sections and a published revision, but no `first_pass_at` and no design, accepts a scoped `Delegate`. None of `design_first`, `structure_first` or `effect_first` refuses it.
- `test_UAT_FC_BUG-311_fresh_site_still_held`: a site with only the starter placeholder and no revision is still held by `design_first` first, as today.
- `test_UAT_FC_BUG-311_first_pass_backfilled_for_a_built_site`: after the host first reads such a site, its plan records `first_pass_at`, and the first-draft guide and hand-over lead are not delivered.

## What landed

**The predicate, settled: a site with a published revision is past its first build.** On a consultant round, when the plan has no `first_pass_at` and `store.revisions(site)` is non-empty, the host back-fills the plan (`siteEstablished`, plan-core), at the start of every round in `firstPassFromSite` (host-core, the REQ-458 hook), before the consultant reads the plan or can call `Delegate`:

- `milestones.first_pass_at` = the first revision's `publishedAt`. This clears `design_first`, `structure_first` and `effect_first`, and every other "first pass landed" reader: agenda, stage guides, panel `drafted`, first-draft cut.
- `milestones.publish_opened_at` = the same, unless already set. The draft counts as reviewed, so neither the hand-over lead (`FIRST_DRAFT_LEAD`) nor "show the client the first draft" (`DRAFT_UNSEEN_LINE`) is delivered. The First draft stage ticks itself done, which keeps its guide from starting.
- The `checking` stage guide is recorded as passed, so it is never handed over.
- **Nothing falls due:** unlike a finished builder session, no `first_pass_complete` checks and no first-draft review (critique). `publish_opened_at` is written directly, so `before_publish` checks don't fall due either.

**Why not "pages beyond the starter":** the test seeds and `1c new` start from `starterHomePage` (a heading), which `nothingBuilt` already reads as built. Every fresh seeded site would then count as established. A site that was built but never published is still covered by REQ-458's existing rule (AI-written pages in the journal). Publishing is refused while `nothingBuilt` holds, so a published revision always means something was built.
