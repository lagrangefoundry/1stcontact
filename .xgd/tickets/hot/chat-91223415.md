## Weber web editor — behavior scope (free-coding)

The Weber design tool's **Design** view: a non-technical user edits a site's copy and
images directly on a live preview. Only copy, asset selection, and friendly parameters
(e.g. a colour picker) are ever exposed; framework tokens/dials are never shown; anything
sophisticated is delegated to the AI. Direct manipulation is a *second producer of the
same validated structured edits* the AI emits — never raw HTML/CSS.

Architecture decisions:
- Preview is **server-rendered HTML in an iframe** (per DOC-7 §2.4; DOC-8 §3.1 browser-render
  is withdrawn). Same origin, so the builder overlays hover/click onto the iframe document.
- Editing granularity is **per module block** (click a block → modal of its copy fields),
  enabled by a `data-fc-module`/`data-fc-type` hook stamped per instance at render time.
- Builder chrome is **vanilla ES modules on the vendored `webui-shell`** (not React/shadcn).

Milestones (all under CHAT-9):
- **M1 — render edit-hooks:** stamp `data-fc-module="<id>" data-fc-type="<type>"` on each
  module instance's root element in `tools/generate/src/render/render.ts`.
- **M2 — builder panel:** vendored shell → Design tab; toolbar (site selector, Edit/View
  toggle, open-in-new-tab); iframe of the served draft render; edit mode outlines blocks.
- **M3 — copy editor:** click block → modal form of its copy fields → validated structured
  edit → re-render → iframe refresh.
- **M4 — asset selector + editor:** click image block → asset picker + basic params
  (crop / scale / scrim), non-destructive structured fields.
