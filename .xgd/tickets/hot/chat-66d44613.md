# Design record — Cloudflare migration, phase 1 (2026-07-30)

## Decision: migrate serving, not storing

The migration splits into **serving** and **storing**, and only serving happens
now. Site definitions stay canonical on the laptop; authoring and modification
are unchanged.

Moving canonical storage to D1 while authoring is local would produce local files
that must sync bidirectionally with D1 — strictly worse than either endpoint, and
the genuinely throwaway work. The trigger for the store move is a **server-side
builder needing to read and write it**, not a date. Until control-app exists, D1
buys nothing and costs a sync problem.

What crosses the wire is the artifact [[DOC-12]] already defines: an immutable,
complete snapshot. `source/` ships alongside `out/`, so each R2 revision is a
complete DOC-12 revision and phase 2 becomes an *import from R2* rather than a
re-derivation from a laptop.

## URL scheme

```
https://1stcontact.io/site/gigabytealchemy/draft/<sha12>/    draft preview
https://1stcontact.io/site/gigabytealchemy/                   published
https://gigabytealchemy.1stcontact.io/                        later, additive
https://gigabytealchemy.ai/                                   later, custom domain
```

Path-based, not subdomain-based. This was only possible because REQ-109 makes the
artifact relocatable; the original blocker was root-absolute `/assets/…` inside
CSS `url()`, which `<base href>` does not fix. Path-based serving also removes a
dependency on proxied **wildcard** DNS, which is plan-dependent on Cloudflare.

Rejected: baking a base prefix into the render (kills content-addressing — promotion
would need a re-render rather than a pointer flip).

## What phase 2 changes

Only the `SiteStore` implementation (manifest.json → D1) and where rendering runs
(local `1c` → control-app). The route grammar, R2 `out/` layout, SHA addressing,
caching rules, deploy semantics, and DNS/TLS all survive unchanged. That is the
non-throwaway test.

## Decisions taken in session

- **Draft privacy**: unguessable URL is sufficient for v1. Gating publication on
  access control is not worth it; real ACLs (Google-Docs-style sharing) arrive
  with login. **[[DOC-12]] needs its "author only (private)" wording amended** —
  outstanding.
- **REQ-109 is in phase 1**, accepting fidelity-gate re-baselining on `xgd` and
  `gigabytealchemy` as the cost.
- **`1c deploy` renders first, always**, so stale bytes cannot ship; output names
  each stage explicitly and ends in the shareable URL.
- **Preview snapshots are not revisions** — immutable, garbage-collectable, never
  entering `history.json`. Preserves DOC-12's mutable-draft / immutable-revision
  split so previews can be shared freely.
- **Slug stays the platform identifier** (`gigabytealchemy`); custom domain is a
  separate site field later. Note `_` is illegal in a DNS label, so
  `gigabytealchemy_ai` could never have been a subdomain.
- **R2 + Worker, not Workers Static Assets** — closes the open question in
  [[DOC-7]] §11.3. Static Assets binds artifacts to a Worker *deployment*, so every
  publish and preview link would require a deploy; that does not go multi-tenant.
- **Zero new dependencies**: uploads shell out to `wrangler r2 object put` (sites
  are 4–13 files); Worker tests cover pure functions against a faked R2 binding.
