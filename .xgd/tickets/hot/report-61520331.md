## Root cause

The webui components are consumed from a shared artifact store that
`lagrange-framework`'s `bin/install` populates **beside** the checkout
(`/Users/martin/lagrangefoundry/node_modules/@gendevlabs/…`), found by Node's
ordinary upward resolution. That install never infers its target from a working
directory — the operator names one, and "the directory the consumer lives under"
means the repository.

A `git worktree` checkout is that same repository, parked at
`~/.xgd/worktrees/…` — outside the store's tree. The upward walk from there
reaches `/Users/martin` and stops, so every component resolved as absent:

    @gendevlabs/webui-shell        -> MODULE_NOT_FOUND   (from the worktree)
    @gendevlabs/webui-shell        -> …/node_modules/…   (from the main checkout)

`WEBUI_INSTALLED` therefore went false and the chrome suites skipped — the
correct, authored response to a machine that has not run the install, and
indistinguishable from one. The implementation was never wrong; the evidence was
simply unreachable, and would be on **every** develop / reconcile / regression
worktree, permanently.

Proof it was reachability and nothing else: symlinking the store into the
worktree's `node_modules` (diagnostic only, since removed) turned the same
unmodified tree from `1 passed | 9 skipped` into `10 passed`.
