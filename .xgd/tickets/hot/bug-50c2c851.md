## Symptom (Bob's Salon, 2026-10-17)

1. **The starter page shows "Your 1st Contact site".** REQ-403's grey placeholder gave way to the starter page at 22:01:08, when the client uploaded an image — change #1 — thirteen minutes before the consultant built any section. `nothingBuilt` (`tools/generate/src/cli/scaffold.ts`) requires the change counter to be 0, and an upload, a palette colour or a font change all move it. The heading confuses the client: it is not their site and reads as though it might be.

2. **The working line's timing is confusing.** Observed, in one turn:

   > *Building the first draft of Bob's Salon's home page — about 15 minutes.*
   > *Taking a screenshot — about a minute.*
   > *… I'm fixing that now. It will take about 5 minutes.*
   > *Taking a screenshot — about a minute.* (×2)
   > Your consultant is taking a screenshot · about 1 min · 16:34 so far

   plus a leaked line: *still working, elapsed 5 min — builder worker-builder-3-3br9qs on home.json, home.json#footer, home.json#header, … since 22:19 UTC*

## Causes

- **Estimate and timer measure different things.** `workingLineText` (`apps/control-app/src/builder/chat.js`) takes the estimate from the latest note and the elapsed time from the start of the turn, so "about 1 min · 16:34 so far" compares a one-minute step with a sixteen-minute turn.
- **The delegation heartbeat is passed through verbatim.** REQ-360 relays the framework's `still working, elapsed N min` progress record (lagrange-framework REQ-205), with the host's worker id, the files it holds, and a UTC time — internal plumbing reaching the client.
- **Every slow operation posts its own chat line** (REQ-386), so routine screenshots read as a stream of consultant messages.

## Fix

### A. The starter page is the grey page

- The seeded starter page itself renders as the grey placeholder with the existing text, *"Your site will appear here as it's created."* (`PREVIEW_PLACEHOLDER`). No heading, no navigation.
- "Your 1st Contact site" is removed from the starter page entirely. Recognising the starter uses a fixed marker on the page, not the heading text.
- The preview no longer depends on the change counter: an upload, a palette or a font change before any section exists still shows the grey page.
- Publish stays refused while the only page is the untouched starter.
- Accepted side effect (operator, 2026-10-17): if the consultant restyles the page before building, the grey page may take the new background. That is fine.

### B. The working line separates the turn from the step

- **Turn line:** the turn's opening announcement and its estimate stay for the whole turn, with the elapsed time since the turn started — *"Building the first draft · about 15 min · 16:34 so far"*.
- **Step line:** beneath it, the current step, timed from when that step started — *"now: fixing the photo on narrow screens · 1:37"*. A new step replaces it; the turn line is unchanged.
- An estimate is never shown against an elapsed time it does not describe.
- With no opening announcement, the turn line reads *"Working · <elapsed> so far"* as today.

### C. No plumbing reaches the client

- The delegation heartbeat never appears as text the client sees: no worker id, no file or section names, no UTC time. It may keep the working line alive; it posts nothing.

### D. Slow-operation notices show progression without crowding the chat

The operator wants to keep seeing that things are happening (*"there is something to be said for seeing the progression"*), so routine steps are not hidden — they are demoted:

- Slow-operation notices (screenshots, captures, image generation) appear as lightweight step lines — visibly lighter than a consultant message — not as consultant prose.
- Consecutive identical steps collapse into one line with a count (*"Taking a screenshot ×3"*).
- They also drive the step line in B.
- The consultant's own announcements (*"I'm fixing that now — about 5 minutes"*) stay as ordinary messages.

## What was built (2026-10-17)

### A — starter page
- `placeholderDocument()` / `placeholderHomePage(name)` (`tools/generate/src/cli/scaffold.ts`): a grey page (`#e5e7eb`, text `#4b5563`) with one centred line, `STARTER_PLACEHOLDER` (*"Your site will appear here as it's created."*). Provisioning (`identity.ts` `createStarterSite`) seeds it; `1c new` and `add_page` keep their slug/title starters.
- The marker is the text node's id, `STARTER_MARKER = 'starter-placeholder'`. `nothingBuilt` is true when the site has one page whose L1 root holds only that node and no modules. It no longer reads the change counter. `STARTER_HEADING` ("Your 1st Contact site") is deleted.
- The preview has no special case any more. REQ-403's `previewPlaceholder()` / `data-preview-placeholder` short-circuit is removed, and the starter renders through the ordinary renderer. Publish still refuses with `NOTHING_BUILT` while `nothingBuilt` holds.

### B — working line
- Each `working` frame carries `meta.scope` (`turn` | `step`), `meta.doing` (the note's words without the name) and an optional `meta.estimate`. The first `Delegate` of a turn (the announced one) is `turn`. Every slow call and every later `Delegate` is `step`. A frame with no scope is treated as `turn`.
- The working line (`chat.js`) has two parts:
  - `.builder-chat-working__turn`: the turn note and its estimate, timed against the turn clock (*"… · about 15 min · 16:34 so far"*), or *"Working · 0:42 so far"* when there is no turn note.
  - `.builder-chat-working__step`: shows *"now: taking a screenshot · about 1 min · 2:34"*, timed from when that step began. A new step replaces it.
- Estimates use the short form everywhere (`about 1/5/30 min`).

### C — heartbeat
- `progressEvent` (`progress-core.ts`) now sends `content: ''` and keeps only `meta.elapsed_s`, so the framework's text never goes over the wire.
- The panel no longer draws anything for `progress` frames. REQ-360's status line (`withProgressLine`, `.builder-chat-progress`) is deleted.
- REQ-397's "status line names the files builders hold" is withdrawn: `withHeldFiles`, `heldLine` and `isBuilderHolder` are deleted.

### D — slow-operation notices
- The cadence wrapper no longer yields a slow call's line as assistant text. Those lines are not in the transcript and the model does not read them back. The step's note is the whole notice. The wrapper yields an empty text delta at issue time so the host can put the `working` frame on the stream before the call runs (the manager never delivers `tool_issue`).
- In the conversation, the panel draws each step as a `.builder-chat-step` line (small, muted, a dot, no bubble) after the messages. When the same step repeats with nothing said in between, the line updates in place: *"Taking a screenshot ×3"*. The panel's open-asks count now goes only on the first `Delegate`'s announcement.
- The consultant's own words, including the first `Delegate`'s announcement, are still messages.

### Superseded tests adjusted
- REQ-403: the preview and publish tests moved here.
- REQ-360: `progress_line` suite deleted; the heartbeat wire test now expects empty content.
- REQ-386: the announcement test now asserts step notes, not text lines.
- REQ-397: the status-line test removed.
- REQ-390: the wire `meta` assertion updated.
- REQ-167, REQ-203 and BUG-210 now assert or seed the marker.
