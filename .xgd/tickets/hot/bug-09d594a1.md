# l1-gate probes: a self-surface button run is measured with its line-box top and its border-box height, so it "escapes" its own button

Round: `repro-console:repro-www-hearingzone510-com#2` · bundle `storage/references/www.hearingzone510.com/index`.

**defect_class `instrument-asymmetric`.** *Test run:* I compared the probe's box for the run with the fold's
pin and the oracle's own measurements. The probe's y comes from the fold's REQ-370 issue-4 placement (line
box), and its height comes from `measuredTextHeights` (`probes.ts:408`). That function takes
`row.box.height`, the captured border-box of a `surface.self` run. The two halves come from different
procedures, so the reported escape is the instrument's own.

## Evidence
`gate.json` `layout.findings`, onSample 320×768:
`'SCHEDULE AN APPOINTMENT' is no longer covered by its backing surface card-1 — 15px below its bottom edge`,
boxes run `{x 78.2, y 328.38, w 162.66, h 43}` and card `{x 78.2, y 313.88, w 162.66, h 43}`.
The offSample probe at 338px reports the identical boxes, and contentRobustness reports h **86** (58px below).
- `page.json`: card-1 320 keyframe `y 313.88 h 43`, border 3px. Its run `SCHEDULE AN APPOINTMENT` sits at
  `y 11.5` (`.l1-15 { top: 11.5px }`), `line-height 13.5px`, no height. 313.88 + 3 + 11.5 = 328.38.
- `multistate.json` 320×800: the run's `box` is `{y 313.875, h 43}` (= the button) and its
  `renderedTextBox` is `{y 328.625, h 13}`, `surface.self: true`. The real line ends at 341.6, inside the
  card's 356.88 bottom.

Counts: `SCHEDULE AN APPOINTMENT`/card-1 46 findings, `EXPLORE MORE SERVICES`/card-2 46. `510-865-8113`/
card-6 has 22, e.g. 1024×768 run `{y 305.69, h 56.30}` vs card `{y 299.84, h 56.3}` (6px), which is the
same shape. That makes **114 of 565** escape findings.

## Proposed change
In `measuredTextHeights`, for a row whose `surface.self` is true and that carries a `renderedTextBox`, use
`renderedTextBox.height`. This is the box `selfSurfaceLines` pins (REQ-370 issue 4: "its ownership height
is the line block"). Alternatively, have `oracleBoxes` emit the line block for such rows. Either way, the
probe's top and height then come from the same procedure.

## How to see it / how to know it is fixed
```
python3 -c "import json;f=json.load(open('storage/tmp/repro-console/repro-www-hearingzone510-com/iteration-2/diff/gate.json'))['layout']['findings'];print(sum(1 for x in f if x['kind']=='escape' and any(s in x['detail'] for s in ('SCHEDULE AN','EXPLORE MORE','510-865-8113'))))"
```
- **wrong now:** `114`.
- **right:** after the fix, `bin/1c l1-gate repro-www-hearingzone510-com --ref storage/references/www.hearingzone510.com/index --sandbox`
  (no browser flag needed) reports no escape for these three runs.


## What changed (free-coded)
`oracleBoxes` (`tools/generate/src/l1/probes.ts`) is the single source of `measuredTextHeights`. For an un-rejoined text run it now takes the height from the fold's own `selfSurfaceLines` when that function yields one, and falls back to `(inlineBox ?? box).height` otherwise. `selfSurfaceLines` is exported from `fold.ts` and is the same function the fold uses both to place the run (REQ-370 issue 4) and to size it in `textHeights`. So for a self-surface run (a button label: `surface.self`, with glyphs centred in a taller border box), the probes' box is now line-block top plus line-block height, and the run no longer "escapes" its own button. Only the height changes: the oracle's x/y (the fidelity pairing position) are unchanged. A chip (`isSelfPaintingRun`) is still measured by its box, just as the fold treats it.

The first alternative in "Proposed change" (use `renderedTextBox.height`) was not taken. It is the glyph height (13), not the line block the fold sizes the run by (13.5 × lines + top padding). Reusing `selfSurfaceLines` keeps the two sides on one procedure by construction.
