## Symptom

Operator review of the Shop tab (`apps/control-app/src/builder/shop.js`, styles in `apps/control-app/src/builder/builder.css`) after REQ-639 landed. REQ-639 asked for consistent type ("no one-off font sizes"); it fixed the item title and section headings, but the inventory list's item names and prices and the item detail's category names are still rendered oversized. Layout and controls also need further tidying.

## Root cause (type sizes)

`.builder-shop` sets no base `font-size`. REQ-639 put the builder tokens (`--builder-control-font-size` 13px, `--builder-heading-font-size` 16px) on a few named elements only; every element without an explicit size — `.builder-shop__row-name`, `.builder-shop__row-price`, `.builder-shop__row-availability`, `.builder-shop__check-text` (category names) and others — inherits the page default instead. A per-element fix will miss the next unstyled element; the fix is at the panel root plus an audit.

## Fix

### 1. Type-size audit (the main defect)
- The Shop panel's base size is the builder's control size, so anything without an explicit size gets the standard size.
- **Every piece of text in the Shop tab** (inventory list, filter bar, item detail, import screens) renders at one of the builder's type tokens: the control size, or the heading size for the one view title. No other computed font sizes anywhere in the panel. Item names, prices and category names come out at the control size.
- This is enforced by a test, not by inspection: it walks every visible text-bearing element in the rendered Shop tab (list and detail, both open) and fails on any computed `font-size` that is not a builder token value.

### 2. Inventory list: filter bar
- The collapse chevron (`«`, closes the item list) moves from the left of the controls to the **right end of the first line** of the filter bar (the search + count line). It appears once, on that line only.
- The **Show more** button is replaced by a **text link directly after the count**: `50 of 364 More…`. Clicking it loads the next page exactly as Show more did. It is hidden when every matching item is loaded.

### 3. Inventory list: rows
- Item names and prices use the standard control size (via 1).
- The **Live** and **Sold** pills are **right-justified** in the row, so they line up in a column down the list regardless of name length.

### 4. Item detail: name
- The separate **Name field is removed**. The name shown as the detail's title is the only place it appears.
- **Double-clicking the title** turns it into a text field holding the name. Enter or leaving the field accepts the change into the item's unsaved edits; Escape restores the previous name. Like every other field, the change is private until **Save** and is discarded by Revert.
- An empty name is refused the same way the Name field refused it, with the message shown.
- The title has a hover hint ("Double-click to rename") and the editable state is reachable by keyboard (Enter on the focused title) with an accessible name.

### 5. Item detail: resizable text boxes
- Today the corner drag on a multi-line text box can be dragged past the panel's edge: the handle and scrollbar disappear (clipped by the panel) while the box does not grow. Fix: a text box can never be resized beyond the width of its container, and its height is capped so its scrollbar and resize handle always stay visible inside the panel. Vertical resizing is enough; horizontal resizing beyond the column is not allowed.

### 6. Item detail: attribute values sized to content
- An attribute value is currently always a single-line box, so a long formatted value (e.g. a multi-paragraph care-guide attribute) is squashed into one line.
- Attribute values size to their content: a short single-line value stays one line; a value with line breaks or longer than the box's width becomes a multi-line box that **grows with its content up to 5 lines**, then scrolls. Line breaks in the value are shown and preserved on Save. Typing more lines grows the box (up to the cap) live.
- The attribute rows keep REQ-639's two-column `Label: value` alignment.

## What landed (implementation record)

- **Type (1):** `.builder-shop` sets `font-size: var(--builder-control-font-size)`, and the moved `«` is set to the control size as well. The audit UAT walks every visible element in the panel that has its own text, plus every input/textarea/select/button except checkboxes, radios and options. It covers list + detail open, and then the import's source and mapping screens. Every one is 13px except a view title (`.builder-shop__title`, or the title's rename field), which is 16px.
- **Filter bar (2):** the list-detail's own `«` (`.list-detail-list-collapse`) is *moved* into the search line as its last child (`margin-left: auto`), so it keeps the component's wiring and appears once. `More…` is a link-styled button (`.builder-shop__more`, the same class as before) placed straight after the count. The count's text stays `N of M`. The link is hidden once everything is loaded.
- **Rows (3):** the Sold/Live pills sit in a `.builder-shop__badges` wrapper with `margin-left: auto`, so they end at the row's right edge.
- **Name (4):** the Name field is removed. The title is an `h2` with `tabindex=0` and the hover text "Double-click to rename". A double-click, or Enter on the title, swaps it for an input (`data-field="name"`, accessible name "Item name"). Enter or blur accepts the name into the draft; Escape restores the name the edit started with. An empty name is accepted into the draft the way the old field accepted it. Save then shows the Worker's own refusal ("An item needs a name."). While the name is empty the input stays open, because there is no title to double-click. The title shows the draft's name, and the list row changes only after Save.
- **Text boxes (5):** detail textareas use `resize: vertical`, `max-width: 100%` and `max-height: 50vh`. The cause of the original symptom was horizontal resizing past the 72ch column, where the panel clipped the box.
- **Attributes (6):** each attribute value is a `textarea` (rows=1, line-height 1.4, `resize: none`). `fitToContent` in shop.js sets its height to its content, capped at 5 lines, and lets it scroll beyond that. A `ResizeObserver` measures it again once it is laid out and whenever its width changes; typing measures it on each input. The attribute name is top-aligned in the grid row.
