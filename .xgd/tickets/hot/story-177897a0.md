## Story

**As an** operator of the deployed builder, **I want** a captured reference
bundle to be kept in whatever storage the runtime that captured it has, **so
that** a page photographed in the cloud is the same artifact my laptop writes,
and either one can read back what the other produced.

## Description

Capturing a reference site produces a **bundle**: one named collection of
members — the capture record, the full-page screenshot, the per-width screenshot
ladder, the post-script and pre-script DOM, the mirrored subresources, the
multi-viewport oracle, the folded L1 document, the recovered form model and the
advisory structural hints. Until now a bundle *was* a directory on the
operator's machine and every verb that touched one reached the host filesystem
directly. The deployed runtime has no filesystem, so the cloud browser had
somewhere to look but nowhere to put what it saw.

This story gives a bundle a **storage contract** rather than a location. A
bundle is addressed by name; its members are addressed by member key and move as
bytes. The contract is honoured by more than one backing — the operator's own
reference tree, the deployment's object storage, and an in-memory one — and the
caller chooses which. Nothing above that choice can tell which it was handed.

**In scope**

- One contract covering a bundle's members, the bundles one account holds, and
  the act of binding an account before either exists. Every verb is asynchronous
  on every backing, so a caller cannot learn the shape of the fast one.
- The same bundle, member for member, whichever backing holds it: what is
  written reads back as the artifact that went in, member keys are named and
  ordered the same way everywhere, and a member absent from a bundle is an
  answer rather than a fault.
- Capture running to completion **inside the deployed runtime**, landing every
  member in the deployment's object storage, and a bundle so captured being
  equivalent to one the operator's machine captured for the same URL.
- Re-deriving the folded L1 document and the form model from a bundle already
  stored, without going back to the live site, on any backing.
- Account scoping for the deployment's backing: a captured competitor site
  belongs to the account that captured it, refused at the moment the store is
  bound and structurally unaddressable from another account's handle. The
  operator's own machine serves one operator and has no account to check.
- Bundle identity derived from the captured URL and re-capture replacing in
  place, so every `--ref` verb an operator already types keeps addressing
  exactly the tree it always did.

**Out of scope**

- Re-pointing the *reproduction* verbs (reproduce, adopt-gaps) at anything but
  the operator's own machine. They read through the contract because their
  dependency moved; the only backing they are handed is the local one. Re-folding
  is the deliberate exception.
- Serving a bundle's members to a public browser from the deployment. Offline
  re-extraction navigates mirrored bytes through a real browser against a local
  server, which the deployed runtime cannot host; a route that streamed members
  instead is a different design.
- Deleting or expiring a bundle. Re-capturing a URL replaces its members in
  place; retention is a lifecycle policy above this layer.
- A timestamped naming scheme with a `latest` alias. It remains available and
  additive; the capture time lives in the capture record, not in the name.

## Technical Context

- **Same seam, second subject.** CAP-101 (Site Storage Port) already cut exactly
  this shape for *site definitions*. This is the same cut for *reference
  bundles*, deliberately separated so the storage contract is reviewed on its
  own rather than buried inside a feature change. The two contracts do not share
  a surface: a site definition and a capture bundle have different members,
  different identity and different lifecycles.
- **Follows the cloud browser.** STORY-124 gave the deployment a browser and
  explicitly claimed only the browser-driving half — it returns a picture and
  says nothing about where a picture is kept. This story is the other half.
- **A port, not a redesign.** The artifact is required not to move: the member
  names, the bundle's schemas and the operator's on-disk layout are what they
  already were, and the correctness claim is that nothing changed. The local
  backing therefore carries its previous behaviour forward unimproved — a bundle
  write is still a sequence of member writes and is still not atomic — because
  improving it here would have made "nothing changed" uncheckable.
- **The cost, priced in the intent.** Because the contract is asynchronous
  totally, every verb that reads a bundle member became asynchronous with it:
  reproduce, re-fold, the L1 gate, reference coverage and the responsive diff.
  The intent names this cascade as the largest single cost of the work, and it
  is why roughly forty existing suites moved in the same change without any of
  their criteria changing.
- **Where the account barrier lives.** The deployment's backing reads the tenant
  registry for one purpose only — to refuse an unknown or inactive account at the
  moment a store is bound, with the same refusal shape and the same
  unknown-versus-inactive distinction site storage uses. Isolation after that is
  structural rather than checked: a bound handle composes every key from its own
  account's prefix.
- **Captured material is client-private.** A captured competitor site lands in
  the deployment's private blob storage, never in the bucket a public Worker
  serves by path.
- **What this story does not claim about the fidelity gate.** The gate and the
  aligned-crops diff still resolve a local directory and feed a path to the image
  layer. They read bundle members through the contract, but they are not
  claimed to run in the deployed runtime, and no criterion here says they do.
- **Command-line resolution stays above the contract.** `--ref` is polymorphic —
  a bundle directory or a loose screenshot — and telling those apart is a
  question about a command-line argument, not a question a store can answer. The
  contract hands back bytes, never locations; the one place a location is
  legitimate is the local backing, which is the only thing that has one.

## Reconciliation Decisions

- **An absent member is an answer, not a fault** (decided at reconciliation,
  2026-09-19): the intent lists what a bundle contains and is silent on reading a
  member a bundle does not hold. The landed contract answers nothing for an
  absent member, answers *empty* for the form model and the mirrored-asset list,
  and refuses only a missing capture record — naming the bundle rather than
  failing on a parse. Formalised because every one of those members was added by
  a later change than the bundle itself, so a bundle predating a member is the
  ordinary case and not an error state; treating it as one would make every
  older bundle unreadable.

- **A rewritten member replaces rather than accumulates** (decided at
  reconciliation, 2026-09-19): the intent requires re-folding to rewrite two
  members of a bundle it did not create, but never states what a second write to
  the same member does. Formalised because a backing that appended would leave
  the re-derived L1 document ambiguous, which is the one thing re-folding exists
  to make unambiguous.

- **Taking a handle on a bundle does not create it** (decided at reconciliation,
  2026-09-19): the intent is silent on listing semantics. The landed contract
  makes the handle total and cheap — a capture's first act is to write into a
  bundle that does not exist — and lists only bundles that hold something.
  Formalised because the alternative would require a create verb whose only
  caller is the thing that would rather just write, and because a listing that
  counted unwritten handles would report bundles an operator cannot open.

- **Re-folding refuses a bundle with no retained oracle, by name** (decided at
  reconciliation, 2026-09-19): the intent names re-folding as a criterion but
  says nothing about a bundle captured before the multi-viewport oracle existed.
  The landed code refuses such a bundle naming it and naming the remedy
  (re-capture) rather than failing on a parse. Formalised because the failure is
  common — every pre-oracle bundle has it — and an unnamed parse failure would
  send the operator looking for a corrupt file instead of an old one.

- **The local backing enumerates only what is shaped like a bundle** (decided at
  reconciliation, 2026-09-19): the intent states the on-disk layout but not what
  listing does with anything else in the reference tree. The landed adapter
  counts a bundle as exactly two segments deep, so a loose file at the root and a
  bare host directory are not bundles. Formalised because an operator's reference
  tree accumulates notes and scratch files beside the captures, and a listing
  that offered them as bundles would hand every downstream verb a name that
  cannot be opened.

- **Non-determinism is stated rather than discovered** (treated as intent, not as
  a gap): the intent's own criterion already says equivalence means same member
  set, same schemas and geometry within the existing gate's tolerance, and
  already enumerates the sources — capture time, what the live site served, font
  and layout settle timing, per-engine ladder differences, and the two browsers'
  PNG encoders differing outright. The criterion here is written on that
  authority, and screenshots are compared as images at each ladder width rather
  than byte-wise.

No contradiction between the intent and the landed code was found for this plan
item. Two of the intent's criteria are stated structurally — "no `node:` import
remains in the codec", "no filesystem call remains reachable from the capture
pipeline" — and are recorded here as criteria about **behaviour**: the pipeline
carries no storage of its own and therefore runs unchanged in a runtime that has
no filesystem, which is the observable thing that structural claim exists to buy.
