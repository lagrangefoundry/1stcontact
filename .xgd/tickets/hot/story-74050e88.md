## Story
**As a** site-reproduction operator (or the AI reproducing a captured site),
**I want** the fidelity comparison output organised object-by-object — each
reference object shown as a card of its full parameter table (typography,
colour, and box position) reference-vs-repro with mismatches flagged, worst
object first, and unpaired objects called out loudly in both directions —
**so that** I can read and diff a reproduction one object at a time and see the
obvious differences (including where each object sits) without hunting through a
flat, globally severity-sorted delta stream.

## Description
The fidelity comparison previously emitted a single flat list of deltas sorted
by global severity across every object — an object that was wrong on four axes
had those four deltas scattered across a long interleaved stream, and an object
present in the reference but missing from (or extra in) the reproduction
vanished into an "unmatched" count. This story establishes an **object-centric**
presentation over the same underlying comparison:

- **In scope:** one card per reference object (text run, image, control,
  divider) carrying a fixed, kind-appropriate parameter table shown
  reference-vs-repro with each parameter flagged matched/mismatched; the
  object's box `{x, y, width, height}` present on every card as a first-class
  column; cards ordered worst-object-first; objects that reproduce clean
  collapsed to a count; loud reporting of unpaired objects in both directions
  (reference objects with no repro match, and repro objects that matched
  nothing); the expected column printed in the spec's own field names and units
  so a flagged row is a paste-able edit; deltas with no reference object to hang
  under (section treatments, viewport/document checks, render-only checks,
  systemic aggregates) preserved in a dedicated tail; the same view available as
  human-readable text and as a machine-readable report.
- **Out of scope:** the comparison logic and tolerances themselves (what counts
  as a mismatch is unchanged and owned elsewhere); geometry extraction
  correctness; unifying the exact styled-run spec vocabulary end-to-end (a
  sibling concern — this story surfaces field names/units, not a full spec
  round-trip).

## Technical Context
The object-grouped view is a **presentation projection** built over the existing
box-to-box pairing in the comparison engine; it does not re-run or alter the
comparison. Each object's card is built from that object's own slice of the
already-computed deltas, filtered through the same ignore/suppression mask the
flat list uses, so a card's verdicts stay consistent with the flat list. Fixed
per-kind tables: text = typography + box; image = name/objectFit/aspect/box;
control = name/nameSource/box; divider = box. Any delta not represented by a
fixed parameter (gradient, border, shape, arrangement, casing, …) is appended to
the card so nothing the flat list held is lost. Position (`box`) closes every
table because it is the residual that iteration converges — intrinsic axes
(text, colour, family, size, weight) are captured verbatim and expected to match
early, while emergent geometry is what the operator iterates on.

Divergence note (for regression): intent item 4 ("same vocabulary as the spec")
names a *sibling* ticket that unifies the full styled-run spec shape; the code in
this bundle surfaces the spec's field names and units in the expected column
(e.g. `fontSizePx` as a raw px number) but does not yet emit a complete
paste-able styled-run object. The AC below asserts the delivered behaviour
(spec-named, spec-unit values in the expected column), not the fuller sibling
goal.
