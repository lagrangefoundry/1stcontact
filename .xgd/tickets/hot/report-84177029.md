## Deviation from the report's suggested field names — deliberate

The report suggested `fields.merged_into = capability-b4ac88fc` + `status = deprecated`,
citing CAP-64/66/72. That pattern is **pre-migration legacy**. The canonical schema
(`xgd_source/core/ticketing/ticket_types.yaml`, `capability.fields`) declares exactly
one retirement field:

```yaml
superseded_by_uid:
  type: uid
  required_when: status == superseded
```

`merged_into` is not a declared capability field at all; `bin/migrate-capability-lifecycle-to-status.py`
records the transition. The *current* precedent — set during this same consolidation,
hours before the anchor report — is CAP-81 (15:41) and CAP-84 (16:03), both retired as
`superseded` + `superseded_by_uid`. The report's substance (retire CAP-88 into CAP-89,
do not author a story) is honoured exactly; only the field vocabulary follows the schema
rather than the legacy example.
