## What happened
Two markdown documents uploaded as reference material (a letterhead and an invoice template) each begin with an HTML `<img>` tag for a logo. In `list_library`, their `title` is that literal tag, e.g. `<img src="images/logo.png" alt="…" width="180">`. The client sees the same thing on their Library tab. The descriptions were generated correctly.

## Expected
The title should be derived from the document's meaningful content, such as the first heading, the description's first sentence, or the filename. It should never be raw markup. At minimum, strip the tags (an `alt` value would be a reasonable fallback).

## Reproduce
Upload a `.md` file whose first line is an `<img …>` tag, then call `list_library`.

## Root cause
`titleFromText` (`apps/control-app/src/describe.ts`) titles a text/markdown material with its first line of three or more characters, after removing heading markers. It skips front matter and horizontal rules (BUG-41) but not HTML, so an `<img …>` line counts as substantial and is returned as it is.

## Fix
Inline HTML is removed from each candidate line before the substance test, inside `titleFromText`:
- HTML comments (`<!-- … -->`) and tags (`<…>`) are stripped from the line. A line that is only markup (a logo `<img>`, `<p align="center">`, `<br>`, `</div>`) is now empty, so it is skipped like a rule, and the title comes from the next substantial line (normally the first heading).
- Markup mixed with text keeps only the text: `<h1>Invoice <small>template</small></h1>` is titled `Invoice template`.
- **An `alt` value as the fallback.** If no line has text, the first non-empty `alt="…"` from a skipped tag becomes the title. The filename is used only when there is no alt either.
- Title precedence is otherwise unchanged: a declared front-matter title, then the first substantial line, then the filename.

The PDF `/Title` path and the image/font branches are untouched. Materials already stored keep their current titles. This change affects new uploads and anything re-described.

## Test plan
`tests/test_UAT_FC_BUG-184_markup_title.test.ts`, through the real `describe` entry point with no describer:
- a markdown file opening with an `<img>` logo line is titled by its first heading, and the title contains no `<`
- a document whose only text-bearing line wraps text in tags is titled by the text without the tags
- a document with an `<img alt>` and no other text is titled by the alt value
- a document of markup only, without an alt, falls back to the filename

Regression scope: the BUG-41 markdown-material UAT file.
