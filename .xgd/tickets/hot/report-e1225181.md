**STORY-170** (`story_kind` changed from feature to upgrade, points from 2 to 3):
- **Body:** the body covers what the simulator now does: it proxies to the builder, swaps the service-token pair for an assertion, refuses bad pairs, passes cookies through, sends uncredentialed requests to `/login`, and serves logout.
- **Out of scope:** the Worker's handling of `SERVICE_TOKEN_IDENTITIES` (plan item 1) and its `POST /sign-out` (plan item 5) are listed there, since those items own them.
- **Reconciliation Decisions:** I added six, dated 2026-11-07, for points where the intent was silent or had been superseded:
  - BUG-59 part two replaces part one's email-carrying token with a `common_name`-only one.
  - A wrong complete pair gets 403, not a redirect.
  - A correct pair with no address to act as gets 403 with guidance.
  - The simulator's own paths ignore credentials and are never forwarded.
  - The proxy passes requests and responses through faithfully, and answers 502 when the builder is down.
  - `--print-token` prints `export` lines, which still fits the intent's `NAME=value` form.

**Modified ACs:**
- **AC-2317:** `--print-env` now prints three lines; the third is the `SERVICE_TOKEN_IDENTITIES` mapping. The AC also says where the name and address come from.
- **AC-2318:** both token kinds pass the Worker's real verifier. A person token from `/mint` carries `email`. A swapped service token carries `common_name` and no `email`, the same shape Cloudflare issues. The existing `/mint` behaviour is unchanged.

**New ACs** (all `active`, under STORY-170):
- **AC-2361:** the matching pair is swapped for an assertion and the pair never reaches the builder. The builder admits the request as the mapped person, so `bin/publish --origin <sim>` can fill the local store. It also covers `--print-token`, the 403 when no address is configured, and the 502.
- **AC-2362:**
  - A wrong pair gets 403 and the builder sees nothing.
  - Half a pair is treated as no pair.
  - A `CF_Authorization` cookie is forwarded byte-for-byte.
  - A request with no credential gets a 302 to `/login`.
- **AC-2363:** `/cdn-cgi/access/logout` clears the cookie and redirects to `returnTo` only if it is on the builder's origin; otherwise it goes to the builder.
