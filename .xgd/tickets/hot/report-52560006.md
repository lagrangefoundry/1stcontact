All three failing tests in this batch now pass: AC2198, AC2199 and AC2200. The rest of the pytest scope still passes too (45 passed, 0 failed), and the control app typechecks with no errors. I only edited `apps/control-app/src/router.ts`, the one file the authorised exception allows.

**The fix:**
1. **Refused grants now return 400, not 500.** `InvalidGrantError` is now handled in the central error mapper, next to the `InvalidPersonRecordError` → 400 mapping, and the response carries the scrubbed message. A grant with no business, a grant with no plan, and a revoke of an unknown id now return 400 with the sentences the tests expect ("A grant must name the business it is for.", "A grant must name a plan.", "No such grant.").
2. **The three write routes now require ownership.** `POST /api/grants`, `POST /api/grants/revoke` and `POST /api/people/status` now check `ownsBusiness(deps.admission, requireScope().businessId)`, the same check the record and invite routes use. A non-owner gets a 403 with a sentence, and a refusal event is logged (`grant_refused`, `grant_revoke_refused`, `person_status_refused`). This happens before the body is read or D1 is touched, so nothing is written. Owners still succeed, and the rest of each handler is unchanged.
   - The refusal-logging block was the same in all three routes, so I put it in one local helper, `refuseNonOwner`.

**Other suites:** The only test that calls these routes over HTTP is `tests/test_reconciliation_contacts_tab_editing.workers.test.ts`, and it passes. No REQ-170, REQ-189 or contacts-tab test needed a fixture change.

One thing to know for the review: `InvalidGrantError` is also thrown for "The grant was not readable back after writing." (`people.ts:693`). That is an internal failure, and it now returns 400 along with the operator errors. I left it alone because changing it would mean editing `people.ts`, which the exception doesn't allow.
