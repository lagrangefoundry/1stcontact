## Summary

`1c shot` captures a full-page screenshot without triggering **lazy-loaded, below-the-fold images** (`loading="lazy"`). Such images render **blank** in the screenshot, so the perceptual gate (`1c diff`) sees them as missing/empty even though they load correctly in a real browser (HTTP 200).

## Evidence (joyfulculinary / REQ-36)

The new services-grid card top-media images (Offerings cards) served at HTTP 200 over `1c serve` but captured as flat grey squares in `1c shot` — the below-fold lazy images never loaded during capture. Confirmed by dropping `loading="lazy"` (eager) → the same images then captured correctly. I had to eager-load the card media purely to make it gate-visible, which is a perf regression the framework shouldn't be forced into by a screenshot-tool limitation.

## Expected

Before capturing, `1c shot` should force lazy content to load — e.g. scroll the full page to the bottom (and back), and/or await `document.images` / network-idle, and/or set the capture context to eagerly load images — so every image that a real browser would load appears in the screenshot.

## Impact

A perceptual-gate blind spot: any faithfully-reproduced below-fold image (card media, gallery, footer imagery) reads as a missing-content delta in `1c diff`, and correct repros look broken. Kin to the other gate blind spots catalogued in [[DOC-19]] (single-viewport, drift, finish).
