# Capability-Intent Alignment: Framework Absolute-or-Overlay Value System
# Level: story

**Result**: FAIL
**Violations**: 1
**Warnings**: 1
**Needs review**: 0

The capability's single story (STORY-80) is correctly aligned to cumulative
intent — it re-homes the absolute-literal base to the L1 substrate and (correctly)
scopes the named-overlay affordance out of L1. The drift is in the **capability
container body (CAP-67)**, which still describes delivery via the pre-pivot module
dials that REQ-84 **deleted**, and still presents the "named overlay" as a
delivered feature when REQ-79 **parked** it (L2 design library, "possibly never
needed").

**Current cumulative intent**: the **absolute-literal base** — hex colour, finite
px length/geometry/radius, envelope-bounded — is carried directly on **L1 leaf
axes** (box / text / image). The **named-overlay** side (palette role / named step
/ named shape) is the **parked L2 design library** (REQ-79 #1/#4): not currently
delivered anywhere, and by decision may never be. The ~20 semantic-module dials
that originally delivered absolute-or-overlay were **deleted** by REQ-84.

## Notes for the Editor

- **Root pattern**: STORY-80 was correctly reconciled through the pivot, but the
  **capability container body was not** — it still reads as the pre-pivot
  module-dial world. A reader of CAP-67 alone would believe services-grid /
  footer / contact-form dials and a shipped palette-overlay exist. The story tree
  underneath is correct; only the umbrella description is stale.
- **Ambiguity that was resolved (not escalated)**: the "named overlay" half looked
  at first like a possible coverage gap or a `needs_review`. It is neither —
  REQ-79 principle #1 ("aesthetics … not enums/palettes/presets") and principle #4
  ("L2 design library = PARKED. Possibly never needed") make the overlay a
  deliberately-deferred/parked affordance, not unexpressed active intent. There is
  a surface tension inside REQ-79 itself — the reconciliation note says the
  "absolute value OR role" concept "carries into L1 leaf axes", while principle #2
  says no role indirection *in* L1 — but STORY-80 and the shipped schema resolve it
  the same way: the literal carries into L1; the role/overlay stays above (parked).
- **Scope note**: this is a story-level finding about the capability container's
  description; the fix is a capability-body edit, plus an optional STORY-80 title
  tweak (finding #2). No AC/UAT/code changes are implied — the code is correct.
