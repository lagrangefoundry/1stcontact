**Severity**: silent correctness bug — a regression run reports overlap
resolution complete while resolving nothing.

**Observed**: regression run `r1c5acc23` (branch `regression-dccfa99b`),
container `matrix_refactor`, scope `xgd/matrix_refactor/report-98fc5946`.
`overlap_resolution_loop` broke to `capability_loop` on its first iteration
having resolved **0 of 8** documented overlap clusters. Evidence written to
REPORT-1073 (`report-4cfbbd04`).

**Two defects, one visible symptom.**

1. **Ticket-store corruption.** Anchor `report-98fc5946` was created this run
   in `f0d0ae3a5` (`.xgd/tickets/hot/report-98fc5946.md`) and is present in the
   HEAD tree, but is unresolvable by the ticketing API
   (`RESOURCE_NOT_FOUND`, searched hot/cold/canonical) and is not archived.
   `report-58c1c6a8` from the same phase is likewise gone, while
   `report-9e9f839a` and `report-8bc8d791` survive. The store is
   sparse-checked-out (`core.sparseCheckout=true`, `.xgd/tickets/**`
   skip-worktree), so `git status` stays clean while the file is absent from
   disk. Root cause of the disappearance is not yet established.

2. **The iterator degrades a system error into a normal loop exit.**
   `get_next_overlap_cluster`
   (`xgd_source/quality/structural_validation.py:515-518`) fetches the anchor
   first and returns the `done_result` sentinel
   (`cluster_index="done"`, `_is_last_iteration_item=True`) on `ErrorResponse`
   — indistinguishable from a genuine "all clusters resolved". Per the failure
   taxonomy in CLAUDE.md this is an **error** (broken state, no defined path),
   not a workflow outcome, and must terminate rather than be reported as
   completion. The same `ErrorResponse -> done_result` pattern appears at
   lines 537-544 (survey lookup) and is worth auditing across the sibling
   iterators (e.g. `get_next_capability_for_validation`).

   Note `matrix_refactor.yaml:73-76` already declares
   `dependencies: ticket_exists: uid=${anchor_report_uid}` — the precondition
   exists but is evidently only evaluated at container activation, not
   re-checked when the anchor is dereferenced mid-run.

**Consequence**: the capability matrix for this run was never de-overlapped.
The 8 clusters in survey REPORT-1072 (`report-8bc8d791`) — spanning 11
capabilities and 12 stories, incl. the CAP-67/CAP-70 boundary — remain
outstanding, and downstream `capability_loop` / `final_recheck` ran against an
un-deduplicated matrix.

**Suggested fix**: make anchor-fetch failure raise (terminating the run) rather
than return the done sentinel; separately diagnose why hot-store tickets
committed early in a regression run become unreadable.
