Blocks all downstream L1 work: while this is broken we cannot trust any fidelity
or idempotency measurement. **Do first.** Scope under [[request-7ff1bacd]] (REQ-88);
see [[DOC-27]] (vocabulary — the idempotence identity).

## Behavior (bug)
`sampleFidelityProbe` (tools/generate/src/l1/probes.ts:394) pairs a reproduced
leaf to an oracle box by **normalized text string**, via a `Map<normText, box>`.
When a page has repeated text (duplicate labels/CTAs), the map key collides and
`byText.set` keeps only the last leaf's box, so other oracle samples with the same
text pair against the **wrong** box → large phantom deltas (this is the 1616px
FAIL). Dropped/absent nodes further inflate `unmatched`. Since `evalGeometry`
reproduces keyframes exactly at sampled widths, deltas at sampled widths are
pairing artefacts, not geometry error.

## Fix direction
- Pair oracle↔reproduced leaves by a **stable identity** (index path / node id
  carried through the fold), not by raw text. Text may remain a tiebreaker.
- Handle duplicate text deterministically (positional match within a width).
- Distinguish genuine coverage gaps (dropped nodes → see B2 ticket) from
  mispairing in the report.

## Tests (required)
- **Idempotency suite**: `value-render(value-render(X)) == value-render(X)` — i.e.
  the analytic value-render of the absolute-base fold reproduces the oracle boxes
  at every sampled width within tolerance, for a fold with repeated text.
- Regression fixture with duplicated runs that currently mispairs.
- Named `test_UAT_FC_<this-ticket>_*`.

## Acceptance
Repeated-text fixture gates clean; idempotency tests pass; no phantom deltas at
sampled widths.



## Implementation (free-coded, 2026-07-22)

Fixed in `sampleFidelityProbe` (tools/generate/src/l1/probes.ts). The stable
identity used is the **occurrence index within a text key** — the very index the
fold`s responsive table (`buildResponsiveTable`) already assigns when it builds
one L1 leaf per row (FIFO document order per key). No new `id` field was added to
L1 nodes: the k-th reproduced text leaf of a key deterministically corresponds to
the k-th oracle element of that key at each width, so the probe now consumes
per-key FIFO queues (leaves in doc order ↔ oracle elements in doc order) instead
of a `Map<normText, box>` that collided on duplicate text.

Consequences:
- Repeated labels/CTAs pair to their own box → no phantom deltas at sampled widths.
- More oracle occurrences than reproduced leaves → surfaced as `unmatched`
  (genuine coverage gap), not masked by a stale map hit.
- A residual on a *specific* duplicate occurrence is still reported (occurrence
  pairing does not use nearest-box, so real drift on one duplicate is not hidden).

Tests: `tests/bug5-fidelity-pairing.test.ts` — `test_UAT_FC_BUG-5_*`
(repeated-text gate clean; value-render idempotency with repeated text; extra
duplicate → unmatched; per-occurrence residual not hidden). Regression scope
(3-probe gate, e2e-repro, l1-repro-pipeline, capture-to-l1-fold) + `tsc` clean.
