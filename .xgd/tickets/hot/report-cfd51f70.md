# Builder blocked by `code_frozen`

**Evidence**: Ran `npx vitest run tests/test_reconciliation_passwordless_sign_in.workers.test.ts`: 8/13 fail with `D1_ERROR: table sessions has no column named issued_at` and redeem returning 503. The installed component /Users/martin/lagrangefoundry/node_modules/@lagrangefoundry/auth-passwordless/src/schema.js has a sessions table with issued_at, origin_id, superseded_by, retired_at plus idx_sessions_origin_id and idx_sessions_retired_at (REQ-151), and passwordless.js:389/527 inserts issued_at and origin_id. db/migrations/0001_baseline.sql:811-824 has only the old 5-column table. The existing free-coded wiring test test_UAT_FC_REQ-202_every_statement_in_SCHEMA_STATEMENTS_is_in_the_migration and the conformance test test_UAT_FC_REQ-202_the_passwordless_contract_holds_against_this_deployments_d1 fail on the same mismatch, so the defect is in the deployment's schema, not in the new tests. (The original 'Cannot find module ./generated/ticketing' was missing build output, since regenerated by `1c assets`.)

**Proposed change**: In db/migrations/0001_baseline.sql, replace the `CREATE TABLE IF NOT EXISTS sessions` statement with the component's current SCHEMA_STATEMENTS text (add `issued_at TEXT, origin_id TEXT, superseded_by TEXT, retired_at TEXT`) and add `CREATE INDEX IF NOT EXISTS idx_sessions_origin_id ON sessions (origin_id)` and `CREATE INDEX IF NOT EXISTS idx_sessions_retired_at ON sessions (retired_at)`, matching the whitespace the wiring test compares against. If any deployed D1 already has the old table, also add a migration applying the component's SESSION_MIGRATIONS ALTERs plus `UPDATE sessions SET issued_at = created_at, origin_id = id WHERE issued_at IS NULL`. The other route is for the operator to reinstall the pre-REQ-151 auth-passwordless into the shared store to match the baseline. No test, AC or story change is needed.
