I filed the iteration 17 fix plan as **REPORT-11781 (report-24f44208)**. It doesn't fix AC-688: the loop has failed on that AC 17 times for the same reason, and it will keep doing so until you install two browsers yourself.

**Why AC-688 still fails:** its only test, `test_UAT_AC688_no_layout_divergence_across_three_engines`, runs only when Chromium, WebKit and Firefox can all launch. It skips otherwise, which the AC allows.
- I checked the browser cache this iteration. `~/Library/Caches/ms-playwright` still has `firefox-1538` and `webkit-2336`, but the pinned Playwright 1.61.1 needs `firefox-1532` and `webkit-2311`. WebKit and Firefox therefore can't launch, so the test skips.
- XGD's coverage check counts that allowed skip as "no passing test". The earlier iterations already reported this defect in XGD's tooling as BUG-1696 (and before that BUG-1695). The test, the AC and the product code are all correct.

**What the plan does:**
- AC-688 is left out of the batches under the tooling-defect rule (BUG-1067), and BUG-1696 is recorded in the batch's ladder fields.
- The one batch makes no edits. It only re-runs the Chromium-only AC-683 test at the gate, which shares the capture path with AC-688, so that evidence stays checked.
- The ladder decided at rung 3: the tests stand. No bundled ticket touches Playwright, and the reference ref pins `"playwright": "^1.61.1"` at `tools/generate/package.json:21`.
- I rejected bumping Playwright, redirecting the browser cache, retiring the AC and adding a test that passes without browsers. The first two need frozen changes; the last two would hide the problem or give false evidence.

**To clear AC-688,** run this once from the repo root in your own terminal. The builder tried it in iteration 2 and the sandbox blocked the write to the browser cache.

```
pnpm --filter @1stcontact/generate exec playwright install webkit firefox
```

When I filed the report, the sandbox also blocked an outbound connection to `github.com:22`, probably a git sync. The report was still created locally.
