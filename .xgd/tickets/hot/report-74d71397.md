I updated both target stories for plan item 8. No runtime code changed and no new stories were created.

**STORY-149 and AC-2364 (where the per-turn reminder goes).** I amended AC-2364 so the site-change reminder is carried at the end of the last user message, after the user's own text, and not in the system field. That holds whether the message content is a plain string or content blocks. The system field now carries only the priming, so no cache marker falls on a block that will change next turn. The code supports this: BUG-83 traced the move to an upstream change in `@lagrangefoundry/ai`, and the shared test double (`tests/support/scripted-model-client.ts`) now reads the system field and the turn tail separately. I added a dated decision to STORY-149 recording this.

**STORY-174 and the new AC-2594 (hover in Mark Points mode).** The new criterion says:
- with Mark Points on, the segment under the pointer keeps a dimmed outline;
- clicking it places a point and opens no editor;
- turning the mode off restores the normal hover;
- the stylesheet the overlay injects carries no copy of the renderer's region-stamp attribute.

The decision is recorded in the story.

**Decision for you:** the plan said the hover rule uses "no !important", but I did not follow that. BUG-83 says the rule "takes `!important` to keep winning over the renderer's own hot treatment", and `apps/control-app/src/builder/points.js:59` does exactly that. Intent outranks the plan, so AC-2594 doesn't mention `!important`. The point it pins is that the overlay must not restate the renderer's attribute. I recorded this in STORY-174.
