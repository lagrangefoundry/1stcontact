I fixed `test_UAT_AC1453_the_automation_identity_is_provisioned_by_a_command_that_persists_no_secret`. The test's setup was wrong. The script it tests (`bin/access-token`) is correct, and I didn't touch it.

**Cause:** The script uses `CLOUDFLARE_ACCOUNT_ID` from the environment before it looks up accounts (`bin/access-token:121`). The test helper `shellEnv`, which `script` and `scriptAsync` use to start the script, removed the credential variables but passed an inherited `CLOUDFLARE_ACCOUNT_ID` straight through. The stub API accepts any account in the URL path, so in the "several accounts" case the script never had to choose and exited 0. The test expected exit 1, so it failed. The script refuses correctly once that variable is absent.

**Fix:** In `tests/reconciliation-builder-private-access-automation.test.ts`, `shellEnv` now also deletes `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_BASE`. Each scenario that needs one of these already sets it explicitly. No assertion changed. The test still fails if the script guesses an account, if a refusal doesn't name the accounts it saw, or if the script creates anything after refusing.

**Results:**
- All 4 tests in the file pass under vitest.
- I couldn't run ESLint because the permission mode denied the command. The edit is two `delete env.X` lines and a comment, in the same style as the lines around them.
- No change to the AC or story was needed: the code does what AC-1453 describes.
