## Source

The consultant's reports from production, each a client request it could not express: PLATFORM_ISSUE-3 and PLATFORM_ISSUE-6 (parts 1–2).

## Gaps

1. **`sms:` links (PLATFORM_ISSUE-3).** A trade business whose main enquiry route is "text us a photo of the job" wanted a "Text a photo" button that opens the phone's messaging app with the number filled in. The link schema accepts http, https, mailto, tel, relative and `#` only, so the builder's write was refused and the button fell back to the contact page, which adds a step on a phone.
   - **Expected:** `sms:` is an accepted link scheme on buttons and links, with an optional `?body=` part, validated the way `tel:` is (a phone number, then only a URL-encoded body). It goes through the same safe-href allowlist and renderer re-check as every other scheme (Security Policy §2). `javascript:` and similar stay refused.
2. **Height that changes by width (PLATFORM_ISSUE-6).** A full-bleed hero fixed at 720px tall on Desktop is also 720px on a 375px phone, cutting off about three quarters of each photo. `sizing` takes `mode`/`px`/`minPx`/`maxPx` with no per-width form. The only per-width height is `geometry.keyframes[].height`, which takes the element out of the page flow.
   - **Expected:** `sizing.height` accepts per-width keyframes on the page's width ladder (like the other `responsive.*` tracks), or a per-width aspect for media and slideshows. It keeps the element in flow, renders through the same interpolation as other tracks, and holds its first value below the first keyframe (see BUG-401).
3. **One framing point for every slide (PLATFORM_ISSUE-6).** A slideshow's slides accept only `image`, `alt` and `video`. `objectPosition` is set once for all slides, so photos with their subjects in different places can't each be framed.
   - **Expected:** each slide accepts an optional `objectPosition` that overrides the slideshow's own, applied to the slide's still and its clip alike.

## Test plan

UATs `test_UAT_FC_BUG-406_*` in `tests/test_UAT_FC_BUG-406_page_vocabulary_gaps.test.ts` (real validator, real renderer, real Chromium):
- a button linking to `sms:+15551234567?body=Photo%20of%20the%20job` validates and renders as that link; `sms:` with a script-like or malformed body is refused; the renderer drops an unsafe `sms:` value that bypassed validation;
- a container with `sizing.height` keyframes 720@1280 → 420@375 renders 720px at 1280, 420px at 375 and 420px at 320, and stays in the page flow (the next section starts below it);
- in a slideshow with two slides with different `objectPosition`, each slide's still and clip render with its own position, and a slide without one uses the slideshow's.

## What changed

1. **`sms:` links.** `isSafeHref` (site-schema `validate.ts`, the one allowlist the validator, both renderers and the capture fold share) accepts `sms:` when it is a phone number — digits, an optional leading `+`, and `( ) - .` — optionally followed by `?body=` and only unreserved or percent-encoded characters (RFC 5724). Anything else after the number (another parameter, raw spaces, quotes, angle brackets, a broken `%` escape) is refused; `javascript:` and the rest stay refused. The refusal message now reads "(http/https, mailto, tel, sms, relative, or #anchor only)" (REQ-359's UAT updated to the new wording). The capture extract keeps an `sms:` href that passes the same rule, so a rendered sms button survives a re-capture.
2. **Per-width height.** `sizing.height` (new `l1HeightSizingSchema`) takes `responsivePx`, a scalar track on the page's width ladder (the same track type as REQ-88's padding tracks). It goes with `mode: "fixed"` and no `px` (validator rule `heightTrackIsFixed`); keyframes must sit on the document widths and lie within 0–100,000 px; `minPx`/`maxPx` still apply. The renderer emits it through the existing per-width track path (`pushTrack('height', …)`), so it interpolates between keyframes, holds its first value below the first keyframe (BUG-401's `ownTracksWin` makes it beat the kind's own `height` declarations), and the node stays in the page flow. Width is unchanged (no per-width width form). The per-width aspect alternative was not taken: one mechanism.
3. **Per-slide framing.** A slide accepts an optional `objectPosition` (`{ xPct, yPct }`), emitted as an `nth-child` rule on that slide's `<img>` and `<video>` after the slideshow's shared framing rule, so it wins for that slide only; a slide without one keeps the slideshow's `axes.objectPosition`.

The builder's vocabulary is derived from the Zod schemas, so the new fields reach the builder and REF-l1 without separate edits.
