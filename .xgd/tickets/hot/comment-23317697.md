AC975 now passes: the real browser launches in the sandbox and takes all its measurements. The whole batch scope passes (41 tests, 0 failures). The only file I changed is the test file; I didn't touch production code, tickets or `ledger-core.ts`.

**Root cause.** AC975 had never actually taken its measurement in this environment. At the last green commit it printed a warning and passed when no browser launched; the previous batch rightly made that a hard failure. Two problems in the test sat behind that warning, both fixed in `tests/reconciliation-builder-workspace-origin.test.ts`:

1. **The browser couldn't start under the OS sandbox (macOS Seatbelt).** Bundled Chromium died at startup and system Chrome failed its profile lock. I added a last fallback launch with `--single-process --no-zygote --disable-gpu`. It is still the real Chromium build, so the layout measurement is genuine. If every launch fails, the test still fails loudly and names each attempt's reason.
2. **The page never reached network-idle.** The workspace makes requests that have nothing to do with layout: `/b/local/api/material` returned 500 and its body never finished, and the `esm.sh` imports can't be reached from the sandbox. Waiting for network idle therefore timed out before any measurement was taken. The test now waits for the page load event and for `.builder-panel__frame` to be present, then measures.

The assertions themselves are unchanged: frame taller than 700px in a 900px window, shrinks and grows with resizes, page overflow equal to 0. With `-t AC975` and verbose output I confirmed the browser launched and the measurements ran, rather than the test returning early.

**Not addressed:** the material listing answering 500 with a body that never completes is behaviour of the local front door, which this mode freezes; I didn't investigate it. ESLint couldn't run because npm is blocked from the registry here. `tsc --noEmit` showed no errors in the edited file. Nothing is committed.
