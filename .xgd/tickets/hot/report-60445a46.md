direction, not a `needs_review`. Finding 1 is a straightforward missing Verification
clause.

**The remediation is small: one extract-and-assert, one AC edit with a two-line code
deletion.** Neither requires new test *design* of the kind Group A demanded last
cycle. If the fix loop can only do one, do finding 1 — it defends a live branch that
would silently serve the wrong document, whereas finding 2 tidies a branch that
currently fires on nothing.

**The pattern the last two cycles named has finally not recurred.** `report-68170dfc`
observed that each level had authored elements without discharging the obligation they
create one level down (stories without ACs, then ACs without UATs). Attempt 7 did
discharge it: all sixteen gap ACs are covered, and it went further than the findings
required by fixing the vacuous `itB` wrapper (I2) and by giving each browser-gated AC
a headless assertion rather than accepting the gating (I3). The two findings here are
of a different shape — clause-level precision within well-covered ACs, not missing
evidence.

**Where the next instance would be, if there is one.** Both findings are single

not uncovered ACs, but a clause inside a multi-clause criterion. The trigger to look
