## Symptom

After a successful resync on 2026-07-18, `xgd-working` was left with 238 staged
changes that staged a mass reversion: 199 ticket deletions, 9 ticket reversions,
and 10 framework file reversions, all rolling the tree back to the `e6312205`
snapshot from 22:15 that night. HEAD was correctly at the rebased tip `69ef938d`.
Only the index was wrong.

Simultaneously, the dispatcher logged 1706 `resync_spawn_blocked_broken_worktree`
events and permanently refused to spawn new resyncs.

No data was lost. The staged changeset was never committed (the ticketing API
commits individual files, not `git add -A`).

## Root cause (confirmed)

The Jul 18 22:29 resync (version 0.14.1386) used the NEW CAS isolated-worktree
approach (introduced in version 0.14.1332). Prior analysis attributed the dirty
state to "AI-driven manual git surgery in the operator checkout" — those log lines
(`reset --hard 7bf2f638 + cherry-pick 70d66f66`) are from **OLD approach runs
pre-2026-07-09** found earlier in the same resync.log. The Jul 18 run did NOT do
manual git surgery.

**Mechanism 1 — dirty checkout (BUG-828 in xgendev-main, unfixed)**

After a successful CAS publish (`git update-ref refs/heads/xgd-working 69ef938d
...`), resync runs:

```python
_git(["reset", "--hard", "HEAD"], cwd=root)   # resync.py:1170
```

`_git` uses `check=False` and never raises. If this reset failed silently (git
lock from a concurrent subprocess), the index remained pointing at old pre-rebase
content while HEAD had advanced to the rebased tip — producing the staged
reversion.

**Mechanism 2 — permanent resync blockage (BUG-310 in xgendev-main, already fixed)**

The teardown ran OLD code that deleted the branch `resync-510318c4` first, then
tried to remove the worktree directory. Directory removal failed ("Directory not
empty"). Branch gone, directory still on disk = broken worktree. The dispatcher
detects this on every poll and refuses to spawn new resyncs.

`_remove_resync_worktree` has been fixed in xgendev-main: directory is now removed
first, a `RuntimeError` is raised if it remains, and the branch is deleted only
after the directory is confirmed gone.

## Reconcile is exonerated

`request-8d885016` (REQ-63) reconcile logs show it started at 21:53 Pacific (same
time as the resync) but failed within 1 second: "SHA 3d0f8846 not reachable from
current HEAD." This is because the resync rebase had already re-authored that
commit. Reconcile never touched xgd-working. The SHA was separately repaired
(updated to rebased SHA `8c0c6363e4da654ab348e6e6446f53bcde584a97`).

## Recovery

1. `rm -rf ~/.xgd/worktrees/https___github.com_martinwesthead_1stcontact/resync-510318c4`
2. `git worktree prune` in the 1stcontact checkout
3. `git reset --hard HEAD` in the 1stcontact checkout

All three steps safe: everything in the staged changeset exists in HEAD (verified
0 missing), untracked carousel WIP (`packages/framework/src/modules/carousel/`) is
preserved by `reset --hard`.
