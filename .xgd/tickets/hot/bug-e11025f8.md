## What happened

This iteration's headline, from `$ITER/ai/prompt.md` and `$ITER/ai/evidence-digest.md`:

> **unmeasured 1** — 0 axes, 1 band, 0 populations, 0 probes.

The run declined **two** measurements, not one. The second is in
`$ITER/diff/values-diff.json`, on the hero band's pairing row:

```json
{ "label": "§1", "box": {"x":0,"y":0,"width":1280,"height":800},
  "actualLabel": "§0", "overlap": 1,
  "anchorComparable": false,
  "anchorReason": "§0 sits inside this band, so the reference measured its anchor over a
   DOM-descendant population that EXCLUDES those runs while the reproduction's geometric
   band includes them — the two anchors are not the same measurement and are not compared" }
```

That refusal is REQ-270's landed fix working exactly as designed
(`tools/generate/src/cli/capture/values-diff.ts:2938-2950`): rather than compare
`0.53` against `0.39` over two different populations, it declines. The defect is that
**nothing downstream can see that it declined.**

## Why nothing sees it

**1. `gate.json` does not carry it.** `reconcileGates` builds the `values` block at
`tools/generate/src/cli/gate-core.ts:800-810` from `deltas`, `matched`, `unmatched`,
`unpairedActual`, `worstTier`, `unpairedSections`, `unpairedActualSections`,
`unmeasuredAxes` and the optional `sectionsNotComparable`. `sectionPairing` is never
read — the only mention of it in the whole file is a comment (line 677). Confirm:

```
grep -n "sectionPairing\|anchorComparable" $REPO/tools/generate/src/cli/gate-core.ts \
  $REPO/tools/generate/src/cli/gate.ts $REPO/tools/repro-console/src/*.ts
```

returns exactly one line, and it is that comment.

**2. The console's tally has no part for it.** `unmeasuredOf`
(`tools/repro-console/src/unmeasured.ts:115-158`) is four counts:

| part | source | this run |
|---|---|---|
| axes | `values.unmeasuredAxes` | 0 |
| bands | `values.unpairedSections` + `values.unpairedActualSections` | 1 |
| populations | `values.unmatched` + `values.unpairedActual` | 0 |
| probes | `values.sectionsNotComparable` (one global string) | 0 |

The `probes` row is documented at `unmeasured.ts:108` as *"a measurement the run declared
it could not make at all"* — which is precisely what `anchorComparable: false` is. But
`probes` is computed at line 131 as `typeof values.sectionsNotComparable === 'string' ? 1 : 0`,
and that global string is set in one place only (`values-diff.ts:2851-2857`): the
flat-L1 degenerate case, where the reproduction segments into a single body-spanning
band. A **per-section** refusal on an otherwise healthy pairing sets nothing.

So a declined measurement falls between all four parts, and
`headlineOf`/`breakdownOf` print `unmeasured 1 — 0 axes, 1 band, 0 populations, 0 probes`
with no `≥` and no `silent` entry, because every part the report carries was counted.
The module's own doc comment says *"A report that does not carry one of the four parts has
a total that can only be higher than it reads"* (`unmeasured.ts:162-168`) — that is exactly
this situation, and the guard does not fire, because the report does not carry the fact at
all rather than carrying it as `null`.

**Wrong (what it prints now):**

```
gate says unmeasured parts: [] 1 0 0 0 None
declined anchors in values-diff: ['§1']
```

— one band counted, one declination not, headline `unmeasured 1`.

**Right:** `unmeasured 2` on this run, broken down as `0 axes, 1 band, 0 populations,
1 probe (§1 contentAnchor — <reason>)`. Concretely:

1. `gate-core.ts` carries the per-section declinations into the `values` block — the
   cheapest shape is `notComparableAxes: [{ scope: '§1', axis: 'contentAnchor', reason }]`,
   which matches the `{scope, axis}` shape `unmeasured.ts:88-92` already knows how to
   name; and
2. `unmeasured.ts` counts them under `probes` beside the global string, so the round's
   headline moves when the comparator stops declining.

## Why it matters beyond the arithmetic

The round is instructed that `unmeasured` "is the number to drive down". A refusal that
costs nothing in that number is a refusal no round will ever be paid to fix — and this
particular one hides the hero/header content anchor, the one section value on this page an
eye would actually check (§0 is unpaired, §1 is declined: **2 of the reference's 8 bands
have a `contentAnchorRatio` compared nowhere**, out of a headline that says 1).

Cross-reference: [[BUG-111]] closed the sibling hole (an unpaired reference section was
reported nowhere the gate reads) and its fix is visible here — `unpairedSections: 1` is in
`gate.json` and is counted. This is the same hole one row over, for a section that DID
pair.


## What landed

Both halves of the fix the section above specifies, plus the three consequences that
follow from carrying a new quantity honestly.

**1. `1c` lifts the declination out of `sectionPairing`.** `ValuesDiffReport` gains
`notComparableAxes: NotComparableAxis[]` — `{scope, axis, reason}`, where `scope` is
the `§n` band label — derived in the same pass that decides the refusal, so the list
cannot disagree with the rows it summarises. This is [[BUG-111]]'s lift one row over,
and for its stated reason: a consumer that only ever COUNTS declinations should not
have to know `sectionPairing`'s shape to find them. `notComparableAxisLabel` sits
beside the type as the sibling of `unmeasuredAxisLabel`, so the terminal row and the
JSON row cannot describe the same fact differently.

The field is **always present**, `[]` when the run declined nothing — unlike
`sectionsNotComparable`, which is absent when the sections WERE comparable. That
asymmetry is load-bearing: an empty array is the measurement "asked, and nothing was
declined", which makes an absent field unambiguously "a report written before this
existed".

**2. The gate carries it and a passing run names it.** `values.notComparableAxes` is
on `gate.json`, and `notComparableAxes` is **required** on `reconcileGates`' input —
the same choice BUG-111's counts made, for the same reason: this is a per-run
measurement of one pair of pages, not a property of the projection table every report
carries automatically, so the type is what asks. A caller that cannot state it has not
asked. `1c gate`'s `outstanding` list gains a sixth rung naming which band lost which
axis and why, and `formatGateReport` gains the matching terminal row — silent on a run
that declined nothing, like the two rows above it. `fidelity-surface.json` documents
the field for the round, next to the `sectionsNotComparable` sentence it parallels.

**3. The console counts it under `probes`, and says so when it cannot.** `probes` is
now `sectionsNotComparable` + `notComparableAxes` — the same kind of fact at two
grains, one all-bands-at-once and one per-band. The breakdown names each declination
WITH its reason (`§1.contentAnchor — §0 sits inside this band, …`), because unlike an
unmeasured axis (whose reason is a property of the instrument and identical on every
run) a declination's reason is about this page's own bands and is the whole of what a
round can act on.

A report that does **not** carry `notComparableAxes` makes `probes` silent rather than
zero — so the headline reads `unmeasured ≥ N` and the part is named beside it. This is
the module's own discipline applied to the new quantity, and it is not optional here:
every `gate.json` already on disk predates the field, and summing a missing part as
zero would make the field's ARRIVAL read as the unmeasured count going UP — a quantity
showing up reported as a movement in the thing it measures, which is precisely the
false-progress inversion `compareSets` already refuses for the other three parts. The
cost is that pre-fix iterations in an existing chain read `≥`, which is true of them.

### Verified

`tests/test_UAT_FC_BUG-139_declined_measurement_is_unmeasured.test.ts` — five UATs on
the gigabytealchemy shape (a 192px header painted over an 800px hero, plus a band both
sides agree on), driven through the real functions at every seam: `diffManifests` →
`reconcileGates` → `gate.json` on disk → `readGateReport` → `unmeasuredOf` →
`headlineOf`/`breakdownOf` → `buildPrompt`, which is the surface the round reads.

1. the declination is lifted out of `sectionPairing`, named by band and axis, and the
   field is present-and-empty (never absent) on a page that declined nothing;
2. `gate.json` carries it and a **passing** run names it in `nextStep` and in the
   terminal report — the case the silence actually mattered in;
3. the ticket's own arithmetic: `unmeasured 2` = `0 axes, 1 band, 0 populations,
   1 probe (§1.contentAnchor — …)`, nothing silent, and the round's prompt carries it;
4. a report without the field reads `unmeasured ≥ 1` with `probes` named as unsayable,
   and the global refusal counts BESIDE the per-band rows rather than instead of them;
5. the number MOVES: the same reproduction against a non-overlapping reference reads
   `unmeasured 0` with nothing silent — and what "0" means there is stated precisely,
   because 0.53 against 0.39 is then a measurement that came back 0.01 inside the
   anchor tolerance, not a measurement nobody made. A gap the tolerance does not
   absorb still lands as the delta it is.
