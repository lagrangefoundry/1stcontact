The story sits under CAP-70 (Framework Substrate) and is based on the REQ-211 ticket and its chat comment. I spot-checked the code against them and found no contradictions.

**Acceptance criteria (AC-2443 – AC-2457):**
- **Schema and envelope:**
  - Plain-string text is unchanged.
  - A list of runs validates, and each run renders with its own styling.
  - Nested runs, links and styling outside the allowed set are refused.
  - One-element (and empty) run lists are refused.
  - Run size is bounded to 0.1–8 and baseline shift to ±10em; superscript values are accepted.
- **Rendering:** a run with no styling of its own renders as bare text with no span.
- **Capture and fold:**
  - Capture records which runs belong to one sentence; a `<br>` or blockified child ends it.
  - A sentence whose runs differ is rejoined into one node in the sentence's own box.
  - A sentence whose runs don't differ is left as separate nodes.
  - The rejoined node takes its paragraph-level styling from the longest run.
  - The fidelity check and round-trip count the same things as the fold, so there are no phantom unmatched runs.
- **Editor:**
  - A multi-run node shows `Text 1 … Text N` as plain-string fields.
  - Editing one run changes only that run's words.
  - A field name that matches no run is refused, names the field, and nothing is written.
- **Height estimation:** splitting copy into runs doesn't change the estimated height, and a smaller run takes up less of the line.

**Decisions I made where the intent was silent** (recorded under Reconciliation Decisions in the story):
- A sentence whose runs differ only in baseline shift is not rejoined.
- The intent required bounds but gave no numbers, so the exact limits come from the code.
