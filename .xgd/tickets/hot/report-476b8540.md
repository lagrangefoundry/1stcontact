**Decisions recorded in STORY-178's Technical Context**
- **No rights re-check when edits re-promote.** The 2026-09-12 answer on EPIC-1 says this check is correctly absent: a picture that is already on a site cannot later lose its permission to be published.
- **No renderer available:** the edit is still stored, it is reported as not rendered, and nothing on the site changes.
- **A render that fails during promotion fails the promotion.** It does not quietly put the unedited original on the site instead.
- **Open assumption: when the assistant edits a picture with `edit_image`, its tool result does not report per-site outcomes.** `xgd intent resolve` returned `unsettled` on this. In the code, only the client's Library editor route returns that report. Through `edit_image`, a name that has gone missing from the site is still never re-added, but the assistant is not told. If the operator wants the assistant told, that is a new requirement.
