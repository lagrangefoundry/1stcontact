All five failing tests in this batch now pass. One related node test file is still red, from a known upstream break that none of these edits touch.

**Results**
- **Looking-surface node suite:** 13/13 pass, including AC2028, AC2031, AC2033 and AC2034.
- **Worker suites:** 24/24 pass across the looking-surface Worker test (AC2025), REQ-146's deployed and audit tests (AC1404–AC1411), the deployed-knowledge test and REQ-154's cloud-eyes test.
- **Also passing:** `test_UAT_FC_REQ-157_fidelity_surface` and the conversation-artifact test.
- **Checks:** `tsc` is clean on both `apps/control-app` and `tools/generate`. ESLint is not installed here and the sandbox blocked fetching it, so lint was not run.

**Part A: production edits, limited to the files the exception names**
- **`fidelity-core.ts`:** added `contentBlocksFrom` next to `isContentBlocks`, as on the tip. It turns the Toolbox's text back into blocks only when that text holds an array of blocks containing an image; anything else returns null.
- **`host-core.ts`:** the tool handler now returns `contentBlocksFrom(payload) ?? payload`. I did not port the tip's BUG-256 repeated-refusal tracking. That also meant leaving out the tip's `toolRefused` check, which lives in `toolbox-core.ts` and is not in the allowed file list. Refusals still come back as plain text, because `contentBlocksFrom` returns null for them. I left `withoutImageData` untouched, and AC2034 passes with it as is.
- **`ai.ts`:** `workerHost` takes a trailing `fidelity: HostDeps['fidelity'] = null` and passes it into the host deps.
- **`router.ts`:** a new `sessionFidelity` builds the surface per site from `shot.ts`'s `fidelityDeps(...)`. It returns null when there is no browser or no `BLOBS` bucket. Three supporting changes:
  - `chatHost` now takes the request origin.
  - `RouterDeps` gains an optional `launch` seam, mirroring the one `shot.ts` already has.
  - References come from `r2ReferenceStore(...).forTenant(tenantId)`.

**Part B: tests only**
- I rewrote AC2028 and AC2033 to match the rewritten ACs.
- Both now assert the real refusal text: the kind and missing field, the browser unused, the unknown reference named with "List the references", both byte counts with the 3 MiB ceiling, the narrower-viewport-or-compare advice, and no image bytes.
- I removed the error-code tokens and the `revision: 99` case.

**I did edit the AC2025 test, against the planner's instruction**
- The planner said to leave it alone. With the wiring in place, the six operations were offered, but `screenshot` failed with `Unexpected token 'b', "browser re"... is not valid JSON`. The test's stand-in `BROWSER` binding returns plain text, and the real puppeteer launcher can't drive it.
- The test now injects a fake browser through the router's new `launch` seam, the same way the REQ-154 cloud tests inject theirs. All original assertions are kept. I added checks that the picture's size is reported and that the page loaded was `/preview/<slug>/draft/`, answered as HTML by the Worker's own preview renderer.
- To confirm it proves the fix, I set `fidelity` to null in `ai.ts` temporarily: the test then failed (`capture_site` not offered), and I restored the file afterwards.
- I updated AC-2025's verification text to describe the injected browser; the criterion itself is unchanged.
