# l1-gate: the structural-failure verdict on www.hearingzone510.com is built from findings the reference itself exhibits and from an off-by-one pairing

Round: `repro-console:repro-www-hearingzone510-com#1` · bundle
`storage/references/www.hearingzone510.com/index` · site `repro-www-hearingzone510-com`. Evidence from
this one bundle. Companion gap ticket: REQ-370.

`gate.json`: `verdict: structural-failure`, `l1Pass: false`, `layout.findings` = 42 `overlap`, 14
`buried`, 74 `escape`. `1c l1-gate … --json` (ran it, no browser flag needed): `sampleFidelity` fails
with 42 residuals, `onSample`/`offSample`/`contentRobustness` fail. Two of those four failures say
nothing about the reproduction.

## Item 1 — the on-sample overlap and buried probes report pairs the reference paints identically · `instrument-blind`

*Defended:* the probe measured the wrong thing — it asserts "a run painted over its neighbour is a
reproduction defect", but has no reference side, so a geometry copied faithfully from the reference
is reported as a defect.

I took every distinct `overlap`/`buried` finding (path pair × width) from `gate.json`, found the same
two elements by text (or src) in the reference's `multistate.json` projection at that width, and
intersected their boxes:

- **overlap: 21 of 21 distinct pairs intersect in the reference by exactly the same amount** —
  e.g. 320px "Hours" (136,7084.3,48×24) vs "Alameda, CA 94501" (83.9,7060.3,152.2×48), ours ∩
  (48.0,24.0), reference ∩ (48.0,24.0), both `zIndex 3`; "9 am to 5 pm" vs "Friday 10 am to 4 pm"
  ∩ (128.7,14.4) on both; "Our brains thrive…" vs "SCHEDULE AN APPOINTMENT" ∩ (162.7,14.0) on both.
  All 42 findings are these 21 pairs.
- **buried: 7 of 10 distinct pairs match the reference exactly** (e.g. 1024px "We specialize…"
  ∩ image (11.3,162.0) on both sides, text `z 1`, image `z 2` — the reference also paints the
  photograph over the right edge of the paragraph's line box). The other 3 are the "For over 20
  years…" paragraph, which my text match missed because the reference records it as the bare text
  node `"F"` with the `<p>`'s box (43.05,1362,673.9×162, `z 1`) — the same box ours has, so the same
  intersection.

REQ-331 fixed this class for collages by having the fold mark *media* `stacked` where the reference's
boxes overlap (`fold.ts:3551-3577`, "ONLY THE PICTURE IS MARKED … Every colliding pair on a montage
contains a picture"). That premise fails here: 18 of the 21 pairs are **text–text** (Zyro grid text
boxes whose line boxes overlap; e.g. a 2-line box whose second line is empty). The buried probe also
fires for pairs with an image that `stacked` should already cover.

**Proposed change:** the on-sample overlap/buried probes should subtract pairs whose two oracle
counterparts intersect by the same amount (±tolerance) at that width — the property REQ-331 states
("an overlap the fold INVENTED … is still a finding") applied at the probe, for every pair kind,
rather than relying on the fold to mark one side.

**See:** `bin/1c l1-gate repro-www-hearingzone510-com --ref storage/references/www.hearingzone510.com/index --sandbox --json`
→ `onSample.byWidth[0].findings` (320×768) — **now** 4 overlaps
(`Our brains…/SCHEDULE`, `Hours/Alameda`, `Hours/Albany`, `9 am to 5 pm/Friday…`).
**Fixed:** 0 at that width, with no reproduction change.

## Item 2 — `sampleFidelity` pairs textless boxes by L1 document order, which the fold has reordered · `instrument-asymmetric`

*Defended:* the two sides are ordered by different procedures — the oracle in DOM order, the
reproduction in the order `nameCapturedBackdrops`/`nestBackingSurfaces` emit backdrops — so the k-th
"(generic)" on one side is not the k-th on the other.

`1c l1-gate … --json` → `sampleFidelity`: `residuals: 42`, `maxDelta: 5139`, **all 42** labelled
`(generic)`, 7 per width × 6 widths, every one `dx: 0, dw: 0` and `dy` equal to a band height. At
1280: `dy` 1157, 889, 1621, 2077, 3667, 1320, 757. Reference bands at 1280 start at 40, 1197, 2086,
… so 1157 = 1197−40, 889 = 2086−1197, 1621 = 3707−2086: **each oracle box is compared with the next
band's box.** Cause, from `1c page get repro-www-hearingzone510-com home --sandbox --json`: root
children begin `backdrop-1, backdrop-2, backdrop-4, backdrop-6, …, section-band-0` and the hero's
`backdrop-0` is nested **inside** `section-band-0`, so in L1 document order the hero scrim comes after
four later bands. `l1/probes.ts:2011-2040`: the non-text queue excludes only
`isSynthesizedSurfaceId(l.id)` and pairs the rest FIFO by kind; captured `backdrop-N` boxes stay in the
queue in emitted order. It means the probe never actually compares the hero scrim with its oracle.

Same queue-head failure as BUG-151 item 2 (landed for values-diff), in a different comparator.

**Proposed change:** pair `box` leaves to oracle boxes geometrically (best IoU at that width), or by
the capture identity the fold already has when it names a backdrop; keep FIFO only as a tiebreak.
**See:** the command above, `sampleFidelity.residuals` — **now** 42 × `(generic)` with `dy` = band
height. **Fixed:** 0, or residuals that are real geometry differences.

## Item 3 (minor) — the band coalescing that makes `unmeasured 2`
`values-diff.json` `unpairedActualSections`: `§4 {x:0,y:2960,w:1280,h:747}`; `unpairedActual`: the
`section-band-2` container ("Better Communication…"). The reference's two Zyro blocks at 2086 (h874)
and 2959 (h749) — both `#224e7a`, both present as `(generic) z 13` in expected-manifest (elements 39
and 44) — are coalesced into one reference section (2087, h1621), while the reproduction's raw bands
keep them as two. That is the whole of `unmeasured 2` (1 band, 1 population). `instrument-asymmetric`:
the two section lists are built by different procedures (the console's brief already warns about it).
**See:** `values-diff.json` → `unpairedActualSections`. **Fixed:** 0, with §3/§4 paired to the two halves.
