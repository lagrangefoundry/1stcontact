**Warnings (should fix — not blocking this merge)**:

1. **Stray `index.html` at the repo root will land on main.** A 17-line builder shell referencing `/webui/...` and `/builder/main.js`. Nothing serves it: the builder generates its own chrome inline at `builder.ts:162` (`chromeHtml()`), `sendFile` serves only the webui/builder roots, and there is no root vite/astro config that would treat it as an entry. It is dead.
   **Not attributable to REQ-118** — `git log main..HEAD -- index.html` shows it entered via `c99b072e0 xgd(resync): terminal state complete`, a workflow commit that swept a dirty worktree, not via the free-coded commit `58cd03439`. Flagged for operator disposal rather than failing this review, since a fix loop scoped to REQ-118 is the wrong instrument for it. Recommend `git rm index.html` before or after the merge.

2. **The picker can offer one file under two spellings.** `imageHandles` normalises every listed asset to `/assets/<name>`, while `imageChoices` (`edit.ts:198`) adds the node's current `src` **verbatim** — which it must, since a `<select>` whose options omit its own value selects the first option instead. So a node holding the relative spelling `assets/hero.png` on a site where `draft/assets/hero.png` exists produces two options for one image: `/assets/hero.png` and `assets/hero.png`. This spelling is not hypothetical — `reconciliation-copy-edit-write-path.test.ts:86` seeds exactly `src: 'assets/hero.jpg'` (that fixture writes no file to disk, so it does not trip there).
   Derived from reading the code; I did not execute a repro (`1c new` cannot run outside the repo root — Astro path resolution fails — and creating a site in-repo would have dirtied this read-only review).
   Consequence is cosmetic, not a correctness or security defect: both options are safe, both write a valid handle, and the load-bearing guarantee (current handle always present) is unaffected. Note the *relative* spelling is the worse of the two — on a nested page `assets/hero.png` resolves to `/<page>/assets/hero.png` — so the duplicate is a user-visible chance to pick the inferior form. Worth closing when the upstream labelled/thumbnail option list arrives (the ticket's recorded known limitation), by having the picker offer the normalised handle and the descriptor carry the current value separately.

**Observation (no action)**: the `src: ''` edge case is benign — `isSafeUrl` rejects the empty string, so a blank-src image cannot be saved regardless of what the picker does with it.
