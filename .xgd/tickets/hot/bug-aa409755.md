## Symptom

Dev, 2026-10-26, with builder tabs open for several businesses at once (Dina's Diner 4, Ariel's Arc
Welding 2, Bob's, Charlie's and others):

- **Ariel 2 and Bob showed broken-image icons with alt text** in the site panel (every mode) and in
  the Library, while Charlie's and other Dina tabs looked fine. The images later came back by
  themselves. The data was intact throughout: stored files valid, a local render loads every image,
  and every image request that reached the server returned 200.
- **Dina 4's preview wouldn't navigate.** Changing the page selector, or clicking a link in the
  preview from Home to Menu, did nothing.
- Earlier, a "1 question needs you" link opened an empty questions panel; the question appeared
  seconds later (see REQ-467).

## Cause

The dev server (`http://127.0.0.1:8789`, `bin/dev`) is HTTP/1.1. Chrome allows **6 connections per
host, shared across every tab**. Each builder tab holds long-lived connections permanently: three
EventSources (`/api/sites/changes`, `/api/material/changes`, `/api/people/changes`, opened in
`apps/control-app/src/builder/api.js`), plus the open conversation's turn stream. Two tabs fill the
pool. With several tabs, every new request in every tab (images, page navigations, plan re-reads)
waits in the browser's queue and never reaches the server until a long-lived connection closes.

The dev log shows it from the server side:
- Ariel 2's page at 02:02 asked for 3 of its 8 images. All 3 returned 200; the other 5 never arrived.
- Dina 4's last page navigation reached the server at 02:02:24. The operator's later selector
  changes and link clicks produced no request at all.
- Change streams were open from at least six businesses in that window.

Cloudflare serves production over HTTP/2, which multiplexes every request over one connection, so
customers are mostly unaffected. The operator's dev setup, and any client stuck on HTTP/1.1 (some
proxies), is not.

## Fix (scope agreed with the operator 2026-10-26; as built)

The builder must **keep running and keep updating in every tab, including ones in the background**.
The operator switches tabs while builds run. So the fix is to use fewer connections, not to close
streams in hidden tabs.

1. **Dev serves HTTP/2, like production — on 8789.** `bin/dev up` starts a front on
   `https://127.0.0.1:8789` (`1c dev front`; Node's built-in `http2`, TLS, HTTP/1.1 still accepted)
   that proxies every request — event streams included, frame by frame — to the control app's
   `wrangler dev`, which moves to an internal plain-HTTP port, **8786** (8790 is the filing service;
   8791 is a sibling project's in the measured port sweep). Any number of tabs and streams then share
   one connection, as on Cloudflare. No backward compatibility for plain `http://127.0.0.1:8789`:
   the operator browses the HTTPS address.
   - The certificate is **self-signed, minted once** with the system `openssl` into the dev scratch
     tree (`storage/tmp/dev/tls/`), covering `127.0.0.1` and `localhost`, and reused across starts so
     the browser's one-time exception keeps holding. Chrome warns once; acceptable for dev only.
     Production is unaffected (Cloudflare's own certificate).
   - The Worker sees its own address as `https://127.0.0.1:8789` (wrangler
     `--local-upstream 127.0.0.1:8789 --upstream-protocol https`), so origin checks, magic links and
     sign-out return URLs name the address the operator browses, whichever door a request came in by.
   - A front whose worker is not answering returns a 502 naming the worker port and how to start it,
     rather than hanging.
   - `bin/access-sim` (8799, plain HTTP, used by tooling) forwards to the worker port (8786) and sends
     browsers (login redirect, logout return, the sign-in page's link) to the HTTPS address. Its
     startup banner prints both (`builder` and `browse`). `--browse` overrides the browser address;
     when `--builder` is given explicitly and `--browse` is not, browsers go to that builder.
   - `1c ps` / `bin/dev` know both services: `dev` (the HTTPS front on 8789, `1c dev front`) and
     `dev-worker` (wrangler on 8786, `1c dev serve control-app`), started worker first, front after,
     access-sim last. `1c dev serve control-app`'s banner names the address to browse. `1c reset`'s
     store guard checks the worker port.
2. **One update stream per tab.** A single `GET /api/changes` event stream carries site (draft),
   library (material) and people (contacts) changes for the tab's business. A kind is included when
   its parameter is present (`site=<key>` with optional `site_since`, `material=<cursor>`,
   `people=<cursor>`; an empty cursor means "from now"). Each frame is tagged with `event: <kind>`
   and is that kind's own feed frame, unchanged; the stream is composed from the three existing
   per-kind feeds (which remain, with their cursors, scoping and resume semantics). Its `id:` is a
   JSON object holding every kind's latest cursor, so a browser reconnect presenting it as
   `Last-Event-ID` resumes each kind where it stopped. A kind the origin refuses (e.g. a site the
   business does not hold → 404) refuses the whole stream with that answer; one feed ending ends the
   stream, so the browser's reconnect reopens all kinds at their cursors.
   In the builder, `subscribeDraft` / `subscribeMaterial` / `subscribeContacts` keep their
   signatures but join one `EventSource` per tab; a join or leave reopens it (coalesced per tick)
   with the remaining kinds, resuming each at its last cursor. A tab therefore holds at most two
   long-lived connections (updates + the conversation turn), even over HTTP/1.1.
3. ~~Tabs share their update connection~~ — **dropped** by the operator: with HTTP/2 in dev and
   production, a cross-tab SharedWorker is code to maintain for a rare HTTP/1.1-proxy client, and
   fix 2 already bounds that case.

## Test plan

UATs named `test_UAT_FC_BUG-295_*`:
- `tests/test_UAT_FC_BUG-295_one_change_stream.workers.test.ts` — the origin serves one
  `/api/changes` stream carrying site, material and people frames, each tagged with its kind, whose
  id holds every cursor; a reconnect presenting the last id resumes every kind (writes made while
  disconnected arrive); a site the business does not hold refuses the stream (404).
- `tests/test_UAT_FC_BUG-295_one_stream_per_tab.test.ts` — preview, library and people subscriptions
  in one tab open exactly one `/api/changes` `EventSource` under the tab's business, each subscriber
  receives only its own kind's frames, and leaving reopens with the remaining kinds at their cursors.
- `tests/test_UAT_FC_BUG-295_dev_serves_http2.test.ts` — the front negotiates HTTP/2 over TLS with a
  certificate valid for 127.0.0.1, forwards the browsed Host, reuses the minted certificate; with 12
  standing event streams on one connection a new image and page request complete in under 2s; a
  worker that is not answering is a named 502; `bin/dev`'s service table puts the front (`dev`,
  8789, `1c dev front`) after the worker (`dev-worker`, 8786), wrangler's argv carries the port and
  the HTTPS upstream flags, the banner names the browse address; access-sim's login redirect and
  logout return go to `https://127.0.0.1:8789`.
- Existing pins updated for the new topology: BUG-150, REQ-319, REQ-322 dev-tooling UATs, and the
  REQ-161/AC977 origin probe list (now probes `/api/changes`).
