## Symptom (Dina's Diner, 2026-10-24 UTC)

- The first-draft build (01:18:43) and the second pass (01:23:35) **both wrote
  the site**. Each `Delegate` result has `wrote: true`, and the change account
  lists places changed: header and footer created, 9 home-page elements, 13
  site-settings fields, a new Catering page and nav entries.
- Even so, the second result carried **"THE LAST 2 BUILDS CHANGED NOTHING. Do not
  start another build for this; a further one is refused in this request."**
- From then on **every `Delegate` was refused `idle_builds`**: three at 01:25:44,
  then three more at 01:26:46 ("THE LAST 7 BUILDS CHANGED NOTHING"). Nothing more
  could be built in that request, including the host-held review continuations.
- The consultant told the client: "Dina, I couldn't make the next round of fixes
  this time. Your first draft is exactly as it was."
- REQ-436's "announce each finished piece" line never fired either.

## Cause

REQ-436's `afterBuild` (`tools/generate/src/cli/ai/host-core.ts` ~1692) counts a
build as idle when `writtenPages(output)` is empty. `writtenPages` (~1591) reads
**only `account.changed.differences[].page`**. The builder's change account now
reports what changed under **`account.changed.places`**, and `differences` comes
back `[]` even for a build that rewrote pages. This is probably since the change
account was slimmed (BUG-252); confirm. So every build reads as having changed
nothing. After `IDLE_BUILDS` (2) builds, `buildRefusal` refuses every `Delegate`
for the rest of the request, and `announceBuild` is never reached.

## Fix

- **One source of truth for "did this build change the site"**, read from the same
  account field the builder actually fills: `places` (pages and site settings,
  including `created`), or `wrote` together with the places. It must not depend on
  a field that a slimming or reshaping of the account can empty. A build that
  changed only site settings (`site.json`, nav, text styles, palette) counts as a
  change. Announcing uses the pages it touched, and the home page for a shared
  part or site-wide change, as `shownPages` already intends.
- **Lock it to the real result shape:** a test builds a `Delegate` result the way
  the builder produces it today (not a hand-written fixture with `differences`
  filled), so a future reshaping of the account fails the test rather than
  silently disabling building.
- **A false idle stop must never outlive its request:** the idle count belongs to
  the message, as REQ-436 intends. Confirm a new client message starts at 0. Here
  the refusals ran on through two host continuations of the same request.

## Test plan

`tests/test_UAT_FC_BUG-266_a_build_that_wrote_is_not_idle.*`, using the
scripted-model host harness with the real builder result shape:

- Two builds that write pages: neither counts as idle, a third `Delegate` is
  accepted, and each produces REQ-436's announcement.
- A build that changes only site settings (nav, palette, text styles): not idle.
- Two builds that write nothing (`wrote: false`, no places): the third is refused,
  as REQ-436 requires.
- After a false-idle refusal, a new client message's first `Delegate` is accepted.
- Re-run the REQ-436, BUG-256 and BUG-252 UATs.
