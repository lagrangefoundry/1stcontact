This story documents `capture_site`, `list_references` and `describe_reference`, plus the guard that limits what a capture may fetch. It sits under CAP-92 alongside STORY-157 and STORY-158.

**Four things the code does that contradict the REQ-157 intent.** I wrote the acceptance criteria to match the intent, so AC-2049 and AC-2050 will fail against the code as it stands. The details are under "Code issues" in the story so the fix step can act on them:
1. **The redirect limit counts the wrong thing.** It counts every distinct domain a page loads anything from, not redirect hops. A normal page that pulls fonts, a CDN and analytics from more than 5 domains gets cut off partway, even though the code's own comment says this shouldn't happen.
2. **The 32 MiB size limit only works in the Worker.** On Node there is no size limit at all.
3. **The 60 s time limit is never applied.** The value is defined but nothing uses it.
4. **A capture that hits a limit still counts as a success.** `capture_site` returns a named reference with the problem only listed in `refusals`, instead of failing with `REFUSED` as intended.

**Gaps I filled where the intent says nothing.** These are recorded under "Reconciliation Decisions" in the story:
- One blocked image or file on an otherwise public page is answered 403 and reported, and the capture still completes.
- A bad address is rejected before any paid browser session is started.
- Addresses containing a username or password are refused, not stripped.
- The limit values are 5 hops, 32 MiB and 60 s.
- The list and describe results return the fields the code returns today.

DNS rebinding is recorded as an explicit non-goal.
