Issue 1 **confirmed landed**: all five header links now paint at 1280 at the reference's boxes (`regions.json` #2 `nodes.ref`/`nodes.actual`, e.g. "Meet the Chef" (642.2,70,142.19×46) on both). They now paint as black plates, which is a new fold defect filed as **REQ-372**, not this ticket.

Issue 2 **landed for `::before` glyphs and not for borders.** All 16 icon glyphs are now captured and drawn. Two shapes are still missing; together they are regions #6/#9/#10 = 1083.84 of 36140.73 = **3.00%** of the ranked score, with 0 deltas:

1. **The hero divider (region #6, `bbox {224,496,304,16}`, score 556.36).** The reference has a 2px white rule at y 505–506, x 20–527, and ours has none: rows 505/506 read mean (255,255,255) in the reference vs (48,41,21) in ours. capture.json has no record near it. **Cause:** Elementor's markup is `<span class="elementor-divider-separator">\n\t\t\t\t\t\t</span>`. The whitespace text node means it does not match `:empty`, so `extract.ts:2862` `root.querySelectorAll(':empty')` never offers it to `borderRuleOf`. Chromium does not implement Selectors 4's whitespace-insensitive `:empty`. The rule is `--divider-border-width:2.5px` on `border-block-start`, width 41% (post-4401.css). **Fix:** test "no element children and only whitespace text" instead of `:empty`.
2. **The three social-icon rings (regions #9/#10, scores 269.10/258.38).** `.elementor-social-icon{background-color:#FBFBFB00;border-style:solid;border-color:#FFFFFF}` (post-4597.css). The reference's white ink spans about 26×27 around each glyph (e.g. x 568–593, y 4588–4614), and ours is only the glyph (574–588). capture.json's only record there is the 16×16 glyph (`borderWidthPx 0`). The `<a>` is not empty (it holds a screen-reader `<span>Instagram</span>` and the `<i>`), and it is not a rule (its thin axis is far more than 2×border+1), so `borderRuleOf` rejects it by design. **What is lost:** a transparent-fill **bordered box** around content, which nothing in the capture records as a surface. **Fix:** record a border-only element (non-transparent border, transparent fill) as a box with its `border` when it is not already a captured surface.

Both are capture-side and need a **re-capture** after they land.
