# values-diff / gate coverage: a band's paint is compared against a box that something opaque is painted over, and the box that does paint it is counted nowhere

Filed by `repro-console:repro-joyfulculinarycreations-com#3`, iteration 3 of the reproduction of
https://joyfulculinarycreations.com, alongside the round's gap ticket. Three instrument defects, one
theme: **the largest paint disagreements on this page are reported as clean, and the records that
would have caught them are excluded from both the delta count and the unmeasured set.**

- reference bundle: `/Users/martin/lagrangefoundry/1stcontact/storage/references/joyfulculinarycreations.com/index`
  (`capturedAt` `2026-09-27T00:47:21.132Z`, `captureSchema` 7)
- artifacts: `/Users/martin/lagrangefoundry/1stcontact/storage/tmp/repro-console/repro-joyfulculinarycreations-com/iteration-3/diff/`

`defect_class`: **`instrument-blind`**.

---

## 1. The actual side's band `surfaceFill` is read off a box that is painted over

### What the instrument says

`values-diff.json` produces **no** `surfaceFill` delta for §6 (the testimonials band), because both
manifests agree:

```
expected-manifest.json  sections[6]  {"index":6,"overlay":null,"contentAnchorRatio":0.38,"textAlign":"left","surfaceFill":"#ffffff","box":{"x":0,"y":2949.515625,"width":1280,"height":525.015625}}
actual-manifest.json    sections[6]  {"index":6,"overlay":null,"contentAnchorRatio":0.38,"textAlign":"left","surfaceFill":"#ffffff","box":{"x":0,"y":2949.515625,"width":1280,"height":525.015625}, "paddingTopPx":0,"paddingBottomPx":0}
```

### What the page does

`actual.png` versus `screenshot.full.png`, row y=3104, inside that exact box:

| x | reference | reproduction |
|---|---|---|
| 0, 80, 160, 240 | `(255, 255, 255)` | `(40, 84, 45)` |
| 1040, 1120, 1200 | `(255, 255, 255)` | `(40, 84, 45)` |

`(40, 84, 45)` is `#28542d`. The band the comparator just called `#ffffff == #ffffff` is painting
dark green across 510 of its 1280 columns, over its full 525px height.

That area is **32.28% of the whole page's pixel disagreement** (computed as mean absolute RGB
difference over the 1280×4743 overlap of the two screenshots; the left gutter is 16.08% at mean
197.07/255 and the right gutter 16.20% at mean 198.54/255). It is `regions.json` region 1,
`score 362246.62` — **52.57% of the ranked region score** — and it yields **zero value deltas**.

### Why

The reproduction stacks two absolutely-positioned boxes over that rectangle (`iteration-3/site/home.html`):

```html
<div class="l1-10" id="backdrop-7"></div>   …   <div class="l1-…" id="section-band-1"> …
```
```css
.l1-10 { background-color: #ffffff }     /* earlier sibling — painted under */
                                          /* section-band-1 paints #28542d over it */
```

The actual-side band slicer attributes the band's `surfaceFill` to `backdrop-7` — the box underneath —
and never to the opaque box on top. A band-fill comparison that reads a box the page has covered is
not measuring the band's paint.

### Suggested fix

The actual-side band fill must be the **topmost opaque paint over the band's box**, not the first
band-sized box the slicer meets. Failing that, when two band-sized boxes coincide and the upper one
is opaque, the upper one's fill is the band's.

### How to see it, and how to know it is fixed

```
python3 -c "
import json
e=json.load(open('/Users/martin/lagrangefoundry/1stcontact/storage/tmp/repro-console/repro-joyfulculinarycreations-com/iteration-3/diff/expected-manifest.json'))
a=json.load(open('/Users/martin/lagrangefoundry/1stcontact/storage/tmp/repro-console/repro-joyfulculinarycreations-com/iteration-3/diff/actual-manifest.json'))
print('ref  §6', e['sections'][6]['surfaceFill'])
print('ours §6', a['sections'][6]['surfaceFill'])"
python3 -c "
from PIL import Image
print('ours pixel (0,3104):', Image.open('/Users/martin/lagrangefoundry/1stcontact/storage/tmp/repro-console/repro-joyfulculinarycreations-com/iteration-3/diff/actual.png').convert('RGB').getpixel((0,3104)))"
```

- **wrong now**: `ref §6 #ffffff` / `ours §6 #ffffff`, and the pixel reads `(40, 84, 45)`.
- **right when fixed**: `ours §6` reads `#28542d` and `values-diff.json` carries a `surfaceFill`
  delta `expected #ffffff, actual #28542d` on §6.

(The reproduction-side cause of the wrong colour is the gap ticket's issue 3. **Both need doing**:
fixing only the fold leaves the comparator one stacked box away from going blind again on the next
site, and fixing only the comparator leaves this page's largest region unexplained.)

## 2. `bandPaintActual` is excluded from `unpairedActual` *and* counted in none of the four unmeasured parts

### What the instrument says

`gate.json` `values.bandPaintActual` is `3`, and `values-diff.json` names them:

```json
[ {"label":"Dreaming of healthier meals…","role":"generic","kind":"box","box":{"x":0,"y":0,"width":1280,"height":800},"index":12},
  {"label":"\"It's not just about eating your veggies…\"","role":"generic","kind":"box","box":{"x":0,"y":2667.515625,"width":1280,"height":267},"index":55},
  {"label":"What people are saying","role":"generic","kind":"box","box":{"x":0,"y":2950,"width":1280,"height":525},"index":64} ]
```

`gate-core.ts:862-867` lifts them out of `unpairedActual` deliberately:

> `${bandPaintActual} reproduction element(s) are a band's own PAINT (a full-bleed box coinciding with
> a band) and are NOT counted as unpaired objects: the reference represents the same fact on its
> section record, so there is nothing on that side to pair them with`

and `tools/repro-console/src/unmeasured.ts` maps the unmeasured set onto four fields —
`unmeasuredAxes`, `unpairedSections + unpairedActualSections`, `unmatched + unpairedActual`,
`sectionsNotComparable + notComparableAxes`. **`bandPaintActual` appears in none of them.** This
round's headline reads `unmeasured 4`; three further reproduction-side paint boxes were measured by
nothing and counted by nothing.

### Why the stated justification fails here

"the reference represents the same fact on its section record" is exactly the claim defect 1
falsifies. For entry `index 64` the reference's section record says `surfaceFill: "#ffffff"` and the
reproduction's box paints `#28542d` — there *was* something on that side to pair it with, and the
pairing would have produced a colour delta. For `index 12` (the hero image box, `{0,0,1280,800}`) the
reference's section record carries `surfaceFill #000000` + a background image but no way to express
the `opacity: 0.49` and `filter: brightness(0.67)…` that the page's overlay child actually applies —
so that one is genuinely uncomparable, and it should therefore be **counted as unmeasured**, which it
also is not.

Either way the exclusion is wrong in both directions at once: comparable records are dropped, and
genuinely-incomparable records vanish rather than being counted.

### Suggested fix

Two independent changes:

1. `unmeasured.ts` — add `values.bandPaintActual` to the `populations` part (or as a fifth part). It
   is a reproduction-side record that entered the comparison and left it uncompared, which is the
   definition the module already uses for `unpairedActual`. Counting it would have made this round's
   headline `unmeasured 7`, not 4, which is the honest number.
2. `values-diff.ts` — before lifting a box into `bandPaintActual`, check whether the reference's
   section record for the same box actually carries the axis in question. If it does, pair them and
   compare.

### How to see it, and how to know it is fixed

```
python3 -c "
import json
g=json.load(open('/Users/martin/lagrangefoundry/1stcontact/storage/tmp/repro-console/repro-joyfulculinarycreations-com/iteration-3/diff/gate.json'))
v=g['values']
print('deltas',v['deltas'],'unpairedActual',v['unpairedActual'],'bandPaintActual',v['bandPaintActual'])
print('unmeasured parts: axes',len(v['unmeasuredAxes']),'bands',v['unpairedSections']+v['unpairedActualSections'],
      'populations',v['unmatched']+v['unpairedActual'],'probes',len(v['notComparableAxes']))"
```

- **wrong now**: `unpairedActual 2`, `bandPaintActual 3`, and the four parts sum to 4 — three
  reproduction-side paint boxes are in neither number.
- **right when fixed**: the round's unmeasured headline accounts for all five uncompared
  reproduction-side records (2 + 3), or those of them that are comparable produce deltas instead.

## 3. `coverage` calls an image "referenced" when it paints zero pixels

### What the instrument says

`gate.json` `coverage`:

```json
{ "mirroredImages": 7, "referencedImages": 7, "unreferencedImages": [], "sections": 11,
  "pageHeightPx": 4843, "pxPerSection": 440, "findings": [] }
```

A clean bill on content completeness.

### What the page does

One of those seven, `assets/10.jpg`, paints nothing at all. `regions.json` region 3,
`bbox {x:672, y:1648, w:176, h:176}`, `score 3380.65`, `readout.meanRgb` `ref [117.62, 103.77, 97.44]`
vs `actual [122, 122, 122]` — three identical channels across 30976 px, i.e. the page background
showing through. Both `nodes` sides name the same element at the same box
(`ref` index 47 / `actual` index 49, `src …/10.jpg`, `box {674.72, 1658.47, 162.06, 162.06}`).
Sampled directly:

| (x, y) | reference | reproduction |
|---|---|---|
| (680, 1690) | `(115, 82, 66)` | `(122, 122, 122)` |
| (720, 1750) | `(70, 46, 36)` | `(122, 122, 122)` |
| (800, 1780) | `(135, 115, 108)` | `(122, 122, 122)` |

The asset is mirrored and 845 KB (`iteration-3/site/assets/10.jpg`) and the L1 references it — the
fold clipped it to nothing (the gap ticket's issue 8). The coverage proxy counts **references in L1**,
so a mirrored, referenced, entirely invisible image reads as covered.

### Suggested fix

`coverage` already has both screenshots and both manifests. For each mirrored image, check that the
reproduction paints *something* inside the image element's own box — a variance test over the crop is
enough: `actual` variance ≈ 0 while `ref` variance is not is a dropped image, and it belongs in
`coverage.findings` where a content-completeness failure can be seen before anybody looks at colours.

### How to see it, and how to know it is fixed

```
python3 -c "
from PIL import Image
import numpy as np
a=np.asarray(Image.open('/Users/martin/lagrangefoundry/1stcontact/storage/tmp/repro-console/repro-joyfulculinarycreations-com/iteration-3/diff/actual.png').convert('RGB'))[1658:1820,674:836]
r=np.asarray(Image.open('/Users/martin/lagrangefoundry/1stcontact/storage/references/joyfulculinarycreations.com/index/screenshot.full.png').convert('RGB'))[1658:1820,674:836]
print('ours variance', round(float(a.var()),3), ' ref variance', round(float(r.var()),3))"
```

- **wrong now**: `ours variance 0.0  ref variance 1035.535`, and `gate.json` `coverage.findings` is `[]`
  with `unreferencedImages: []`.
- **right when fixed**: `coverage.findings` names `assets/10.jpg` as referenced-but-unpainted, so the
  content-completeness gate reports it without a human having to open a crop.
