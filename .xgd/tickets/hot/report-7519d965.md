# Mode override granted: code_frozen

The reference state declares the backend's capabilities when registering it, so image content passes the vision gate. The working tree omits them, so every uploaded image is stored with the describer-failed outcome. AC2097 and AC2378 correctly demand that an image is sent and described. The code is wrong, not the tests.

Planner instructions for the batch:

Iteration 1 already fixed nine of these tests: the storeFor helpers in the three reconciliation-material-description*.workers.test.ts files now pass { businessId: tenant } to ticketStoreFor. Keep those edits and do not touch the tests again. The two remaining failures (REQ-207 AC2097: images.seen is empty; AC2378: image status 'failed') come from a production defect. In apps/control-app/src/ai.ts, describerSession() registers its backend with lib.registerBackend(name, () => backend) and declares no capabilities, so the session manager refuses image content with 'declares no vision capability'. Register the backend with the adapter class's declared capabilities, lib.ClaudeAPIBackend.capabilities, as the third argument, the way the library registers its own backends, and add a short comment explaining why the capabilities are not optional. Apply it in describerSession() so both describers get it. Do not special-case the image path, and keep the distinct per-describer names. No test or AC changes. Done means AC2097 (both files), AC2378, every FC_REQ-207 and FC_REQ-173 UAT, and the other ai.ts consumer suites in dependency_tests all pass.
