# Fix Plan — Iteration 9

## Hypothesis
AC-2479 fails only because `tools/generate/src/cli/capture/interact.ts` lets `fill` reach a field by its `name` attribute or `id` (fillNames) and picks a menu option by words OR value in one pass (the SELECT branch), both of which REQ-216 forbids. The AC-2026 failure in this iteration's input is out of date: that test was already fixed and passes.

## Analysis

**Resubmission.** This replaces the first iteration-9 plan (REPORT-11598). The validator refused that plan for a single reason (`fix_plan_filter_rejected`, frozen_path_problems): *"batch 0: the instructions name production files that `code_frozen` freezes in reconcile mode (tools/generate/src/cli/ai/fidelity-surface.json) and the batch grants no `code_frozen` override naming them."* Batch 0 named that file only to describe which shape the test must keep, and edits nothing there. Its instructions now describe the shape without naming the production path. Batch 1's instructions also no longer name production files outside its grant. The validator raised no ruling problems and no rejected scope terms, so the diagnosis and the ruling are unchanged.

**Inputs are partly out of date.** The failure list comes from quality report REPORT-11589 (report-efc6404e). The iteration-8 plan (REPORT-11592) ran after it:
- **Batch 0 (AC-2026, test-only) is fixed.** REPORT-11593 (report-b5cfdad9) rewrote the AC-2026 test in `tests/reconciliation-assistant-looking-surface.test.ts` to the nine-key, six-kind picture, with the draft-only `after` array. Batch_quality_check REPORT-11595 shows AC2026, 2027 and 2028 passing 3/3. The orphan entry for AC-2026 is the same failure.

  - (a) `fill "email_input" with ...` reaches a field by its id and returns a picture instead of refusing;
  - (b) `fill "Region" with "United Kingdom"` selects an earlier option whose *value* is "United Kingdom" instead of the option whose *words* are "United Kingdom" (value GB).

**Hypothesis history.** The interact.ts hypothesis was proposed in iterations 6, 7 and 8, and the builder confirmed it each time. Only a mode rule stops it. Rule (b) applies: rule on the blocked_by by the ladder. The ruling is **Grant**.

**Why the grant is admissible despite report-07babd4a.** That review (override_misjudged) denied `code_frozen` for **batch 0** of this story. The reason was the trust-boundary audit item: marking on the screenshot path, under a grant over host-core.ts, fidelity-core.ts, ai.ts, router.ts and shot.ts.

This block comes from **batch 1**, the batch that has carried AC-2479 since iteration 6. The grant names one different file, interact.ts. Its concern is control-name matching inside a page-step script, with no marking, escaping, sanitising or provenance. Batch 0 keeps AC-2026, so the blocked tests keep their batch number.

**Ladder for AC-2479 (rung 1 decides).** REQ-216 (in scope) says "There is no way to name a selector, an id or an attribute". It also says a menu matches the option's words first and its value only as a fallback.

The reference (`reconcile-src-BUNDLE-42:tools/generate/src/cli/capture/interact.ts`) states the same intent in its own comments:
- lines 12-17: "THE UNIT IS A SHORT PHRASE, NOT A SELECTOR";
- lines 278-279: "A menu is chosen by the words a person reads on it, and only falls back to the value".

Its code contradicts those comments: fillNames pushes `getAttribute('name')` and `el.id` (within 197-206), and the option loop matches text OR value in one pass (within 278-286). So the reference does not settle the question the other way. The other rulings do not fit:
- `aligned_to_tip` is invalid, because REQ-216 explicitly requires the behaviour;
- `declined` cannot work, because the fix is production-only;
- `superseded` does not apply, because neither AC-2479 nor its test changed.

**Conflicts.** None. The REQ-216 menu FC test uses a single option, so a words-first, value-fallback match still passes it. No REQ-216 FC test fills a field by id or name attribute.

**Other consumers of interact.ts** are reached through the draft-picture path. Their tests (the REQ-216 FC tests and AC2025, 2027 and 2028) are in batch 1's `dependency_tests`.
