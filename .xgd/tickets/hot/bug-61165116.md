## Symptom

Working session on **2026-09-02** built a demo site ("Gigabyte Alchemy") through the
builder AI. On returning to the local dev server, the **chat transcript is intact but
the site is a blank starter page**.

Not expected. The site was not deleted — its content was **overwritten with the
`1c new` starter scaffold** while every other artifact of the session survived.

## What the local store actually holds

The site is `tenant=1stcontact, slug=alpha` in the local miniflare D1
(`apps/control-app/.wrangler/state/v3/d1/…`).

| Artifact | State |
|---|---|
| `chat-cdd0f518` + `comment-3e10c30f` (transcript, 38,896 bytes) | **intact** |
| `site_changes` — 16 journal records, palette/config/l1/component ops | **intact** |
| `site_assets` + R2 `draft/1stcontact/alpha/assets/AlchemistLabWithTech.png` (2.4 MB) | **intact** |
| R2 `audit/1stcontact/site-alpha/` — 65 AI tool-call records | **intact** |
| `sites.site_json` | **replaced by `starterSiteJson('alpha')`** — no palette, tagline `alpha — built with 1st Contact` |
| `site_pages(home.json)`, 536 bytes | **replaced by `starterHomePage('alpha')`** — one centred placeholder reading `alpha` |

`sites.version = 26` and `sites.counter = 16` were **not** reset. A delete-and-recreate
would have zeroed both (`createDraft` inserts at `version 0, counter 0`). So this was an
overwrite of an existing row, not a fresh site.

`sites.updated_at = 2026-09-03T03:12:17.291Z` — about 7h40m after the last AI edit
(`2026-09-02T19:29:45Z`), and **no audit record exists at that time**. The write did not
come through the AI surface.

The same shape produced a second scaffolded `alpha`, under `acct_uatwestheadme`, on
2026-09-03T21:49:49Z.

## Mechanism

`SiteStore.write()` (`tools/generate/src/store/d1r2-store.ts:461`) replaces `site_json`
outright and upserts pages by name. It has **no guard on existing content** — no version
precondition, no "refuse if this slug already holds authored work", no snapshot first.

`createDraft()` (`:391`) is `INSERT OR IGNORE`, so it is safe on its own. But every
"create a starter site" sequence in the codebase is `createDraft` **then** `write(starter)`:

- `apps/control-app/src/identity.ts:597-601` — provisioning a business
- `apps/control-app/src/router.ts:884-886` — `POST /api/import`, i.e. `bin/publish`

Against a slug that already exists, the first call is a no-op and the second is a total
content wipe. The safety `createDraft` appears to provide is illusory.

**Which path fired here (inferred, with evidence):** the scaffold now on disk has its
placeholder heading set to the *slug* (`"alpha"`). `identity.createStarterSite` always
passes `STARTER_HEADING = 'Your 1stcontact site'` (`identity.ts:441`), and has done since
`61a0becc61` (2026-08-31) — so provisioning is ruled out. The heading-defaults-to-slug
shape is `starterHomePage(slug)`, which is what `1c new` writes (`commands.ts:68`). That
reaches D1 only through `/api/import`. `bin/publish` defaults its origin to
`http://localhost:8788` — the operator's running dev server — so a `1c new alpha` +
`bin/publish` in any checkout (including a free-coding worktree, which has its own
`storage/` but posts to the same shared dev Worker) lands on top of whatever the operator
has at that slug.

## Two distinct defects

1. **A scaffold write can destroy authored content.** Neither `/api/import` nor
   provisioning distinguishes "seed an empty site" from "replace a site someone built".
   `bin/publish`'s own docstring calls re-running it "the ordinary way to use it".

2. **There is no undo.** The change journal records only labels and summaries — the `l1.set`
   records carry before/after *text*, not documents — so it cannot reconstruct a page.
   No revision had been published for `alpha` (`published_sites` holds only `xgd`), so
   there is no snapshot tier either. DOC-12's forward-only model protects *published*
   revisions; a draft that was never published has no protection at all.

## Recovery for this instance

Recoverable, by hand, from the R2 audit trail. The audit records carry the **full `set_l1`
node payloads** — e.g. `audit/1stcontact/site-alpha/1788374147.604-0015.json` (5,970 bytes)
contains the whole hero / about / pillars document, background image reference, overlay and
palette hexes. Replaying the write-effect records in key order reconstructs the final page;
the last mutating op was `write_image` at `1788376498.045`.

## Scope — to be agreed before coding

Candidate fixes, not yet chosen:

- Make the starter-site write refuse a slug that already holds content (the guard belongs in
  the `createDraft`+`write` pair, or in a single `createStarterSite`-style store operation
  that is genuinely idempotent).
- Make `/api/import` refuse to overwrite an authored site without an explicit `--force`.
- Snapshot before any destructive write, so a draft has a floor even when never published.
