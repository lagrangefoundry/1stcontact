## Symptom

Open the builder, select a site, look at the Site tab's chat panel.

- The composer shows the **STOP** button, with no turn having been invoked.
- Typing a message and pressing Enter renders the user's bubble and then
  nothing happens — no reply, no tool activity, no error.

Nothing recovers it except waiting ~10 minutes or reloading into the same
state again.

## Root cause

`storedTranscript` in `tools/generate/src/cli/ai/host-core.ts` computes the
`live` flag — "a turn is open at this cursor, so the panel should reattach" —
as:

    deps.lib.closedPrefix(records).length !== records.length

`closedPrefix` returns a **number** (the count of leading records that leave no
turn open), not an array. `.length` on a number is `undefined`, and
`undefined !== records.length` is true for every non-empty record stream. So
**`live` is true for every session, always**, whether or not a turn is running.

The library is loaded untyped (`AiLibrary`), so the type system had nothing to
say about it. The flag was introduced by BUG-46 and its UATs only ever exercise
the case where a turn genuinely *is* open — where the wrong answer happens to be
the right one — so the defect shipped green.

What the operator then sees follows mechanically from that one value:

- `chat.js`'s `setSession` reads `live === true` and calls `chat.resume(...)`,
  which puts the composer into its streaming state — hence the STOP button on a
  panel nobody has spoken to.
- `mountChat`'s submit handler is `streaming ? queue(md) : send(md)`, so the
  typed message is **queued behind the phantom turn** rather than sent. The
  bubble is the queue rendering, not a request.
- `/api/ai/reattach` tails a quiet junction, which yields nothing and returns
  only when `watch`'s own `timeoutMs` (10 minutes) elapses. The composer is
  gated for that whole window.

## Fix

Delete the second read and take `live` from the value `manager.transcript()`
already returns.

Upstream computes exactly this predicate itself
(`manager.js`: `live: closedPrefix(records) < records.length`) and documents it
for precisely this failure — "a reload landing *between* turns would gate its
composer for ten minutes". `storedTranscript` was re-deriving, from a second
read of the same log, a fact the call it had just made had already answered —
and got it wrong. Consuming the library's answer removes the divergence rather
than repairing one side of it, and removes `logFor`/`closedPrefix` from this
module's surface entirely.

## Test plan

`tests/test_UAT_FC_BUG-64_quiet_session_is_not_live.workers.test.ts`, in the
workerd project, against the real session manager, junction and D1 store with
only the Anthropic client doubled — the same apparatus BUG-46's suite uses.

- A freshly opened session, and a session whose only turn has completed,
  both report `live: false` from `POST /api/ai/session`. Both are false on the
  unfixed code.
- A session read *during* a paced turn still reports `live: true`, so the fix is
  not "always false" — BUG-46's property is pinned by the same assertion that
  would catch over-correcting it.
- The panel does not enter its streaming state for a session reported
  `live: false`, and a message typed into it is sent rather than queued — the
  operator-visible half of the bug, asserted where the operator meets it.
