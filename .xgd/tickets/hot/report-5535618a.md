## Loop-design note

Re-cutting the branch is **necessary but not sufficient**. Findings 1 and 5 together: a branch
carrying all of `main`'s tests would still fail this check on AC-1354, because that UAT exists
nowhere. Closing this capability's uat level needs **both** (a) the branch to see the code and
(b) `test_UAT_AC1354_*` authored on `main`.

The deeper shape: an earlier **ac-level** pass in this same regression run authored AC-1353 and
AC-1354 (their ticket blobs are on this branch and not on `main`), creating criteria whose UATs
can only be written against code the branch does not carry. The uat-level stage that follows was
therefore guaranteed to fail from the moment those ACs were created. Per the failure/error
taxonomy this is a **terminal failure** — an expected dead end with no fix-loop path by
construction — and the repeated `@fail` → `fix_uat_validation` → `@fail` cycle is the symptom of
it being routed as a recoverable failure. It should halt gracefully to the operator, not retry.

Declaring `progress_made=false` with `needs_more_work=true` is the honest exit and stops the loop
here rather than spending a 33rd iteration on the same wall.
