## Story
**As a** client asking the consultant to reproduce or learn from an existing website, **I want** the assistant to be able to capture that site itself and then see what it recorded, **so that** it can work from a faithful reference without me running tools, and without the assistant ever being able to fetch something inside my system it should not reach.

## Description
REQ-157 gives the assistant a read-only "looking and judging" surface (STORY-157). This story is the part of that surface that **brings a reference in**:

- **`capture_site(url)`**: the assistant names a public http/https address. A real browser loads it, records it at each viewport width, reads its values and mirrors its images. The result is a named reference, which every later picture of kind `reference` takes.
- **`list_references`**: what has been captured, with each capture's address and time.
- **`describe_reference(name)`**: what one capture holds, i.e. the widths it recorded, its sections, images mirrored against images referenced, and the coverage findings that say whether it looks complete. The assistant reads this before trusting any comparison against the capture.
- **The egress guard.** `capture_site` is the first operation that fetches an address *a model chose*, which makes it a server-side request forgery surface ([[DOC-2]]). The rule refuses non-http(s) schemes, URLs carrying credentials, and private, loopback, link-local, unique-local, CGNAT and multicast address space. That includes the cloud metadata endpoint written as a bare IPv4 address or as IPv4-mapped IPv6, plus `localhost` and `.local` / `.localhost` / `.internal` / `.home.arpa` names. It also bounds a capture by redirect hops, total bytes and wall-clock time. The rule is applied to the typed address up front (so a bad address leases no metered browser) and then **to every request the page makes**, including each redirect hop and every subresource, in both the Worker (Browser Rendering) and Node (Playwright) browsers.
- **Refusals are named and journalled.** A refusal reaches the model under the surface's declared `REFUSED` error, which names the address and the reason and tells it not to retry or re-spell. The Toolbox audit record for the call carries the URL. Subresources refused mid-capture are reported in the result, never dropped silently.
- **What comes back is a stranger's content.** All three operations return `untrusted` provenance, and `capture_site` tells the model that captured words are material to report on, never instructions.

**In scope:** the three operations, the egress rule and its caps at both driver seams, pre-flight, REFUSED and audit, and untrusted-content marking.
**Out of scope:** surface composition, grant, the picture vocabulary and `screenshot` (STORY-157, plan item 4); `compare` / `check_fidelity` (plan item 5); the operator-typed `1c capture` command (STORY-124/147), which installs no guard and keeps its existing network behaviour.
**Explicit non-goal:** DNS rebinding is not defended. The guard sees host names and literal addresses, not what a name resolves to, and nothing inside workerd can resolve a name to check it.

### Code issues: intent contradicted by the landed code (for fix_uat_coverage)
1. **The redirect cap counts every origin, not redirect hops.** Intent (REQ-157 *Grant and safety* and AC6) says to cap redirects and refuse redirect loops. The guard adds the origin of *every* allowed request, subresources included, and trips once more than 5 distinct origins have been seen. Its own comment says "documents, not subresources … counting them as such would refuse ordinary sites". In practice an ordinary page that loads a web-font host, a CDN and analytics trips the cap, and every later request is refused. The AC captures the intent: subresources from many origins do not trip the redirect cap.
2. **The byte cap is not enforced on Node.** Intent AC6 says to refuse over-large responses. Only the Browser Rendering driver counts response bytes against the guard. The Playwright driver installs the per-request rule but never records bytes, so Node captures are unbounded in size.
3. **The time cap is never applied.** The *Grant and safety* section says to "cap time". A 60 s per-capture ceiling is declared ("passed to the session lease"), but nothing passes it anywhere.
4. **A tripped capture is not refused.** Intent AC6 says a capture over the size cap or caught in a redirect loop "is refused", and the guard's own contract says a capture that has blown its budget "must not limp on and return a half-loaded page as though it were the page". `capture_site` never checks whether the guard tripped. It returns a successful named reference with the trip listed in `refusals`. The AC captures the intent: refused under `REFUSED`, and no usable reference presented as the capture.

## Reconciliation Decisions
- **Refused subresources do not fail the capture** (decided at reconciliation, 2026-10-27): intent is silent on what happens when one subresource of an otherwise public page is refused. The code answers it 403, lets the page finish, and reports every refusal in the result even on success, because a capture that silently skipped imagery makes every later verdict wrong. Formalized as the "every request is checked" AC.
- **Pre-flight before leasing a browser** (decided at reconciliation, 2026-10-27): intent puts the control at the driver seam and does not mention a pre-flight. The code also checks the typed address first, so an obviously bad address costs no metered browser and no retries, and the caller is told "refused" rather than "capture failed". Formalized as the typed-address AC.
- **Credentials in a URL are refused, not stripped** (decided at reconciliation, 2026-10-27): intent does not mention credentials. The code refuses, because whoever wrote them meant them to be sent, and sending them to a host the model chose must not happen quietly. Formalized within the typed-address AC.
- **The concrete cap values** (5 hops, 32 MiB, 60 s) (decided at reconciliation, 2026-10-27): intent says "cap" without numbers. The values as declared in the code are formalized.
- **list/describe report shapes** (decided at reconciliation, 2026-10-27): intent says only "what has been captured, and what is in it". The fields the code returns are formalized, because the image counts and findings are what `check_fidelity` and the surface's own workflow note depend on.
