# capture/values-diff: the full-bleed band test measures against `scrollWidth`, so a reproduction that scrolls sideways has no bands — and the textless pairing then invents twelve deltas from the gap

Filed by `repro-console:repro-joyfulculinarycreations-com#1`, iteration 1 of the reproduction of
https://joyfulculinarycreations.com. Artifacts:
`/Users/martin/lagrangefoundry/1stcontact/storage/tmp/repro-console/repro-joyfulculinarycreations-com/iteration-1/diff/`.

These are defects in the **instrument**, not in the reproduction engine. They are filed separately
from this round's gap ticket (**REQ-332**) as §5 of the round brief requires, following BUG-148's
precedent.

`defect_class`: **`instrument-blind`**, **`instrument-asymmetric`**.

They are worth having because together they account for **32 of the round's 122 value deltas (26%)**
— including all nine of the highest-severity deltas in the run — and for the entirety of the round's
headline `unmeasured 10`. Every one of the 32 describes a difference that does not exist in the
served document.

| issue | deltas it creates | tier |
|---|---|---|
| 1 — bands dropped because `docW` is a scroll width | 9 `missing` + 6 `arrangement` | all CRITICAL |
| 2 — textless pairing takes the queue head with no geometric check | 12 | 2 CRITICAL, 2 HIGH, 2 MEDIUM, 6 LOW |
| 3 — `semanticOf` reaches an ancestor landmark role | 5 `a11yRole` | HIGH |

Three issues. **Issue 2 is dependent on issue 1** — fixing issue 1 removes the coverage gap that
issue 2 turns into false deltas — but issue 2 must be fixed anyway, because the next site with an
uneven band count will reproduce it. Issue 3 is independent.

## Issue 1 — `backdropBoxes` and `bandSlices` test "full-bleed" against `document.documentElement.scrollWidth`, so 420px of horizontal overflow drops all eleven bands

**`defect_class`: `instrument-blind`** — the section pass reported `UNMEASURED` and the element pass
reported nine bands `absent`, on a document whose served CSS paints all eleven; the score is not
wrong, it is empty.

### The test I ran, and what it returned

`tools/generate/src/cli/capture/extract.ts:410`:

```js
var DOC = document.documentElement;
var docW = DOC.scrollWidth, docH = DOC.scrollHeight;
```

`extract.ts:746-747` and `:759-786` (`backdropBoxes`), for a colour-only candidate:

```js
var BACKDROP_MIN_HEIGHT = 8;
var BACKDROP_EDGE_TOL = 1;
…
if (!url) {
  // A colour-only box qualifies as a backdrop only when it is full-bleed.
  if (!(b.x <= BACKDROP_EDGE_TOL && b.x + b.width >= docW - BACKDROP_EDGE_TOL)) continue;
```

and the identical predicate again at `extract.ts:1634`, inside `bandSlices` — the REQ-269 geometric
segmenter written specifically so that an L1 reproduction would stop degenerating to one band:

```js
function bandSlices() {
  var bgs = backdropBoxes();
  var cand = [];
  for (var i = 0; i < bgs.length; i++) {
    var b = absBox(bgs[i].el);
    if (b.height < BACKDROP_MIN_HEIGHT) continue;
    if (!(b.x <= BACKDROP_EDGE_TOL && b.x + b.width >= docW - BACKDROP_EDGE_TOL)) continue;
    cand.push({ el: bgs[i].el, box: b });
  }
  …
  if (kept.length < 2) return [];
```

**On this reproduction, `docW` is not the viewport width.** From
`iteration-1/diff/actual-manifest.json`:

```json
"viewport": {"width": 1280, "height": 4710}
"sections": [{"index": 0, … "box": {"x": 0, "y": 0, "width": 1699.75, "height": 4710} …}]
```

The document is 1699.75px wide at a 1280px viewport, because the reference's testimonial carousel
lays two slides outside the visible one and L1 cannot clip them (REQ-332 issue 2). Every band
backdrop is 1280 wide and starts at `x: 0`, so the predicate evaluates
`0 + 1280 >= 1699 → false` for all eleven, `cand` is empty, `kept.length < 2`, `bandSlices()` returns
`[]`, and `extract.ts:2306-2310` falls back to the single body-spanning band.

**The reference does not trip it**, from `capture.json`: `viewport {"width": 1280, "height": 4744}`
and `sections[1].box {"x":0,"y":0,"width":1280,"height":4743.9375}` — 1280, with the *same two
off-screen slides* at `x = -419.1875` and `x = 1026.8125`, because the real page's `.swiper` clips
them. So the two sides are segmented by procedures that differ **because of a property of our own
render**, which is the definition of an asymmetric measurement dressed as a reproduction defect.

### Hypothesis

`extract.ts` — `docW` at line 410 is used for two different jobs: bounding the visible region (line
594, `if (b.x >= docW || b.y >= docH) return false`), where a scroll width is right, and deciding
"is this box full-bleed" (lines 774 and 1634), where it is wrong. A full-bleed band is one that spans
the **layout viewport**, not one that spans whatever the widest overflowing descendant dragged the
scroll box out to.

### Proposed change

Introduce a second width — `var layoutW = DOC.clientWidth` (or `window.innerWidth`, which
`extract.ts` already uses for `viewport.width`) — and use it for the two full-bleed predicates at
`extract.ts:774` and `extract.ts:1634`, leaving `docW` for the visible-region bound at line 594 and
for the body-band fallback boxes. Both sides then answer "full-bleed" by the same rule whatever the
overflow.

**This will raise the delta count, and that is the point.** It removes 9 CRITICAL `missing` and 6
CRITICAL `arrangement` deltas that are false, and it makes eleven band records and three
section-level axes (`overlay`, `contentAnchor`, `textAlign`) comparable on a reproduction where they
are currently skipped — so real residuals in them will appear for the first time. `unmeasured` should
fall from 10 to 1 (the remaining probe).

## Issue 2 — a textless record with no accessible name takes the head of its role queue with no geometric check, so a coverage gap becomes twelve confident false deltas

**`defect_class`: `instrument-blind`** — it measured the wrong thing: two boxes 2624px and 533px apart
were compared as though they were the same object, and every axis it then read off them is a number
about nothing.

### The test I ran, and what it returned

`tools/generate/src/cli/capture/values-diff.ts:2574-2601`:

```ts
// ── text-free fields (REQ-47): pair by a11yRole + document order ─────────────
for (const exp of expected.elements) {
  if (!exp.textless) continue
  …
  const q = fieldQueues.get(exp.a11yRole ?? exp.role)
  const expName = norm(exp.accessibleName ?? '')
  let act: ValueElement | undefined
  if (q && q.length > 0) {
    const byName = expName ? q.findIndex((el) => norm(el.accessibleName ?? '') === expName) : -1
    act = q.splice(byName >= 0 ? byName : 0, 1)[0]
  }
```

A band backdrop has `a11yRole: "generic"` and no accessible name, so `expName` is `''`, `byName` is
`-1`, and it takes `q.splice(0, 1)[0]` — **the head of the queue, whatever and wherever it is.**
There is no geometric fallback and no floor below which it declines to pair.

With eleven `generic` records on the reference side and two on ours (issue 1), the queue drains in
order: reference element 71 gets our element 70, reference element 72 gets our element 75. From the
two manifests:

| | box | `surfaceFill` | `opacity` | `filter` | bg image |
|---|---|---|---|---|---|
| ref `elements[71]` | `(0,0,1280×800)` | `#000000` | 1 | null | – |
| ref `elements[72]` | `(0,0,1280×800)` | `#000000` | 0.49 | `brightness(0.67) contrast(0.88) saturate(1.06) …` | HERO |
| act `elements[70]` (= `box-1`) | `(0,0,1280×800)` | `#000000` | 0.49 | `saturate(1.06) brightness(0.67) contrast(0.88)` | HERO |
| act `elements[75]` (= `box-6`) | `(0,2624.125,1280×267)` | `#ffffff` | 1 | null | market-vegetables |

So the hero's opaque base is compared against the hero's **scrim**, and the hero's scrim against a
band 2624px further down the page and 533px shorter. `box-0`, the element `elements[71]` should have
paired with, is painted (`.l1-3 { background-color: #000000 }`) and merely absent from the manifest.

### Hypothesis

`values-diff.ts:2592-2595`. The accessible-name join was added (REQ-96) precisely because
document-order FIFO "assumes the two sides enumerate their controls in the same order, and a
reproduction has no way to guarantee that" — the comment says so. A band backdrop has no accessible
name, so it falls straight through to the assumption the comment disowns, and the fallback is the
queue head rather than nothing.

### Proposed change

Give the unnamed case the join key it actually has: **its box**. Both sides' `ValueElement` carries
`box`, so after the name lookup misses, pick the queue entry with the greatest
intersection-over-union with `exp.box`; and if the best IoU is below a floor (say 0.25), **do not
pair** — `push(exp, 'missing', 'present', 'absent')` and leave the candidate in the queue for a
later reference element.

Declining to pair is strictly better than pairing wrongly: an unpaired record lands in `unmatched`,
which is part of the number this loop is told to drive down, instead of manufacturing twelve
confident values. It will *lower* the delta count here, and that is legitimate because all twelve it
removes are false — the corresponding rise is in `unmatched`, where it belongs.

## Issue 3 — `semanticOf`'s unbounded `[role]` ancestor walk attributes a carousel slide's `role="group"` to a text run three ancestors down

**`defect_class`: `instrument-asymmetric`** — the reference side reads a role off a structural ancestor
that an L1 render, by construction, does not have, so the two sides cannot agree however good the
reproduction is. The delta points at the side that is right.

### The test I ran, and what it returned

`tools/generate/src/cli/capture/extract.ts:1377-1384`:

```js
function semanticOf(el) {
  if (!el.closest) return el;
  var anc = el.closest('[role],a[href],button,h1,h2,h3,h4,h5,h6,input,textarea,select,img,hr');
  return anc || el;
}
function a11yRoleOf(rawEl) {
  var el = semanticOf(rawEl);
  var explicit = el.getAttribute && el.getAttribute('role');
  if (explicit) return explicit.trim().toLowerCase();
```

`[role]` is unbounded: `closest` walks to the document root, so **any** ancestor carrying **any** role
attribute — a landmark, a region, a grouping — is returned as the run's own semantic element.

The reference's testimonial markup, from
`storage/references/joyfulculinarycreations.com/index/raw.html`:

```html
<div class="elementor-main-swiper swiper" role="region" aria-roledescription="carousel" aria-label="Slides">
  <div class="swiper-wrapper">
    <div class="swiper-slide" role="group" aria-roledescription="slide">
      <div class="elementor-testimonial">
        <div class="elementor-testimonial__content">
          <div class="elementor-testimonial__text">
            We've really enjoyed having Sarah plan out a healthy and delicious menu …
```

The run's owning element is `div.elementor-testimonial__text`. `closest` walks `__text` →
`__content` → `.elementor-testimonial` → `.swiper-slide[role="group"]` and returns the slide, so
`a11yRoleOf` records `group`. The reproduction emits the run directly, with no slide wrapper — there
is nothing in L1 that would produce one — so it records `generic`.

### The five deltas

```json
{"text":"“So fabulous. We are planning to do this as often as poss…","role":"body",
 "property":"a11yRole","expected":"group","actual":"generic","kind":"semantics",
 "tier":"HIGH","magnitude":0,"severity":3100,"valueType":"A"}
```

and the same on `We've really enjoyed having Sarah plan out a healthy and …`, `Dan H.`,
`Parent / CFO` and `I cannot say enough good things about our meal. Sarah Joy…` — every run inside a
`swiper-slide`, five HIGH deltas at severity 3100 each. `group` is not any of those runs' role; it is
the slide's, and the run is three levels below it.

This is REQ-302's own fix reaching too far. Its comment at `extract.ts:1365-1375` explains why the
walk exists — a presentational `<span style="background-clip:text">` inside an `<a>` made the
reproduction read `link` and the reference `generic` — and that is a real and correctly-fixed case.
But the span-inside-anchor case is bounded by the elements it names; `[role]` is not.

### Hypothesis

`extract.ts:1379`. The walk needs a bound. Either:

- **depth** — the presentational-wrapper case is one or two levels (`<a><span>text</span></a>`), so
  stopping at, say, 2 ancestors keeps it and excludes a landmark four levels up; or
- **the role's own kind** — the case the fix was for is an *interactive or heading* ancestor (`link`,
  `button`, `heading`), never a landmark or a grouping. Restricting the `[role]` branch to a
  role allowlist — `link`, `button`, `heading`, the form roles — and ignoring `region`, `group`,
  `list`, `presentation`, `none` and the landmarks is the narrower and truer fix, because it names
  *why* the ancestor stands in for the run.

The second is preferable: the depth bound is a number nobody can defend, while "a landmark is not a
run's role" is a statement about what the axis means.

### Proposed change

Bound the `[role]` branch of `semanticOf` to roles that can legitimately own a text run's semantics,
and keep the tag-name branch as it is. Then `role="group"` on a slide and `role="region"` on the
carousel are invisible to `a11yRoleOf`, both sides read `generic`, and the five deltas go away
because there was never a difference.

This *lowers* the delta count by 5, which is legitimate on the same grounds as issue 2: all five are
the ruler's own. It does not reduce what is measured — `a11yRole` is still compared on every run, and
a genuine `heading`-vs-`generic` (REQ-269's 11 headings) still fires.

fold from the oracle the bundle already holds, so it can never pick up an extractor change. Offline
re-extraction is exactly the right tool and it exists — `reextractFromBundle`,
`tools/generate/src/cli/capture/reextract.ts:156`, DOC-13 §9's "capture once, re-map forever", which
re-runs the whole pipeline against the bundle's own mirrored bytes without re-hitting the live site —
but **nothing calls it**: `grep -rn reextractFromBundle tools/generate/src apps` returns only its
definition and its re-export at `capture/index.ts:38`, and `1c` has no verb for it (`index.ts` has a
`case 'refold'` and no `reextract`). So until either a verb is added or the operator re-captures, the
five deltas persist with the fix in place. Do not read that as a failed fix — and consider that
exposing `reextractFromBundle` as `1c reextract <bundle>` is the cheaper half of this ticket, because
it is what makes every future extractor fix verifiable against the bundles already on disk.

# Implementation — what landed

Three fixes, one commit, one UAT file
(`tests/test_UAT_FC_BUG-151_the_instrument_measures_the_page_it_served.test.ts`, 14 UATs).
Eight of the fourteen fail against the pre-fix source and pass against the fixed source; the other
six are the no-regression guards and pass on both sides, which is what makes them guards.

## Issue 1 — `layoutW` splits the two jobs `docW` was doing

`extract.ts` now carries `var layoutW = DOC.clientWidth || docW` beside `docW`. `docW` keeps the job a
scroll width is right for — bounding the visible region (`onScreenBox`) and clamping a painted extent —
and `layoutW` answers "does this box span the page", at both full-bleed predicates
(`backdropBoxes`, `bandSlices`).

**`clientWidth`, not `innerWidth`.** `innerWidth` includes the scrollbar gutter and a `width:100%`
band does not, so an `innerWidth` rule would drop every band on a platform with a classic scrollbar —
the same class of defect this ticket is about, just with the sign reversed. **The `|| docW` fallback is
deliberate**: where `clientWidth` is unavailable the pre-fix answer stands, so no conventionally
laid-out document can change verdict (there the two widths are equal anyway).

Two consequences beyond the two predicates the ticket named:

- **A qualifying slice is now RECORDED at `layoutW`.** `bandSlices` boxed its emitted slices
  `width: docW`. Leaving that alone would have traded nine false `missing` deltas for eleven false
  `size` ones against a reference whose own bands are 1280 wide, and left each band record
  disagreeing with the very rule that admitted it. The `document.body` gap-fillers move with them,
  for the same reason. The BUG-15 body-band *fallback* box (the degenerate no-qualifying-children
  case) stays at `docW` as the ticket asks.
- **The degenerate-single-band trigger now reads `layoutW` too** (`bandRoots[0].box.width >= layoutW - 2`).
  "One band covers the whole page" is a viewport question by the same argument; measured against a
  scroll width, a flat render whose painted extent stops at the viewport edge would never reach
  geometric segmentation at all.

**The predicate still discriminates.** Widening the rule from the scroll box to the viewport must not
make every painted box full-bleed: bands inset to 900px of a 1280px viewport qualify as backdrops
neither before the fix nor after it, and a UAT pins that.

## Issue 2 — an unnamed textless field joins on its box, or not at all

`values-diff.ts` gains `boxIoU` (the 2D twin of the existing `verticalIoU`: a section is identified by
a vertical interval because it is full-bleed, but two cards side by side share their whole vertical
interval and are different objects) and `FIELD_PAIR_IOU_MIN = 0.25`. After the accessible-name lookup
misses, the pass takes the candidate with the greatest box IoU; below the floor it **does not pair** —
the reference record lands in `unmatched` as an honest `missing` and the candidate stays in the queue
for a later reference element that may really be it.

Two properties the fix has to preserve, each pinned by a UAT:

- **The accessible-name join keeps precedence over geometry.** A name says the two sides mean the same
  control, which is a stronger claim than overlap; a named control the reproduction placed wrongly must
  still pair, so that its `position` delta is what gets reported rather than a `missing`.
- **It is inert for a pre-`box` manifest.** With no geometry on either side there is nothing better
  than the queue head, so an old bundle keeps its old pairing instead of reading `missing` on every
  field it has.

The floor is deliberately loose. A band reproduced 60px short is the same band drawn a little
differently and the `size` axis exists to say so; a tight floor would refuse the very pairs the axes
are there to grade.

**Verified against the round's own manifests.** `values-diff` is pure, so
`iteration-1/diff/{expected,actual}-manifest.json` re-run directly. Total value deltas **120 → 114**,
and the eight false `(generic)` values are gone — `position @ (0,0) -> @ (0,2624)` (the round's
loudest claim), `size 1280×800 -> 1280×267`, `backgroundImage HERO-… -> market-vegetables-…`,
`filter present -> none`, `surfaceFill #000000 -> #ffffff`, `opacity 0.49 -> 1`, and both
`padding{Top,Bottom}Px 0 -> 45` — replaced by one honest `(generic) missing`.

**And two real residuals surfaced that the mispairing had been hiding**, which is the clearest evidence
that declining to pair measures *more*, not less:

| newly visible | what it is |
|---|---|
| `"It's not just about eating your veggies…"` `position @ (0, 2668) -> @ (0, 2624)` | a genuine 44px displacement, previously eaten as a `missing` |
| `Dreaming of healthier… → THE HOLISTIC APPROACH` `gap 94px -> 51px` | a genuine 43px gap error, previously unmeasurable |

## Issue 3 — the semantic-ancestor walk is bounded by the role's KIND

`semanticOf`'s selector splits in two. The tag-name branch is unchanged; the `[role]` branch is
replaced by an explicit allowlist of the roles a text run could legitimately **be** — `link`,
`button`, `heading`, and the form-control roles, i.e. the vocabulary `a11yRoleOf` itself emits — with
the `i` case-insensitivity flag. `region`, `group`, `list`, `presentation`, `none` and the landmarks
are invisible to the walk. An element matching both branches still resolves by tag, so an anchor
carrying `role="presentation"` is still an anchor.

**One addition the ticket did not name: an element's OWN role is still its own role.** The defect is
reaching *through* a grouping role to an ancestor, not honouring one an element carries itself, so
`semanticOf` returns `el` unchanged whenever `el` has a `role` attribute — a `role="group"` box that
directly holds its text still reports `group`. Without that guard the narrowed selector would have
walked *past* such an element to some further ancestor and reported the wrong role for a different
reason.

## What was NOT done, and why

**`1c reextract` is not in this commit.** The ticket's issue-3 caveat suggests exposing
`reextractFromBundle` as a verb, and it is right that this is what would make an extractor fix
observable against bundles already on disk. It is not a one-line verb, though: to be *useful* it has
to decide what it rewrites inside the bundle (`capture.json` alone leaves `multistate.json`'s
projections carrying the stale `group`, so a re-fold has to follow), and those are product decisions
about bundle mutability rather than a wiring detail. Bundling them here would put an unverifiable new
CLI surface — it needs a browser to do anything at all — inside a defect fix. It wants its own scope.

**Consequently issues 1 and 3 are not verified end-to-end on this round.** Both are extractor-side, and
the stored `actual-manifest.json` is a pre-fix extraction, so the ticket's `1c gate` / `1c values-diff`
checks cannot move without a re-extraction or a re-capture. Chromium does not launch in this
environment (blocked at the Mach bootstrap level), so the evidence for them is the jsdom UATs driving
the real `EXTRACT_SCRIPT` over fixtures built to the measured shapes — `scrollWidth 1700` against
`clientWidth 1280` for issue 1, the reference's own `swiper` / `swiper-slide[role=group]` nesting for
issue 3 — each failing pre-fix and passing post-fix. The operator's own `1c gate` run is what confirms
the round-level numbers.
