Parent: [[EPIC-12]] §8. **Follows [[REQ-256]]**, which put the AI into the
console's loop. This ticket is what the FIRST LIVE ROUND taught us — it ran on
`gigabytealchemy.ai` on 2026-09-16 and its evidence is at
`storage/tmp/repro-console/repro-gigabytealchemy-ai/iteration-1/ai/`.

## What the first round showed

The round worked. It read the evidence, named a real defect in the engine's own
gate, proved it from the captured files rather than from the screenshot, traced
the consequence through `reconcileGates`, and handed back a complete gap ticket
with a 6,346-character body.

**The console then threw it away** and reported `the round produced no outcome
block.` Everything in this ticket follows from reading that transcript.

## Goal

Make a loop-1 round cheap enough to run many times and capable of keeping what
it finds. Three things are in the way: the console cannot read a good round's
answer, every round starts from zero knowledge, and a round can only report the
one thing that fits the one shape it is allowed to return.

## Behavior

### 1. The outcome block survives a ticket body that contains fenced code

`parseOutcome` (`tools/repro-console/src/ai.ts`) extracts the round's answer
with a lazy fenced-block regex:

```
finalText.matchAll(/```(?:json)?\s*\n([\s\S]*?)```/g)
```

A gap ticket that carries its evidence quotes `gate.json` and `capture.json` in
fenced code blocks, exactly as [[REQ-256]]'s own brief §6.3 demands. Those
fences are literal characters inside the JSON `body` string, so the lazy match
stops at the first one and the outcome block is truncated — in the observed
round, at 1,130 of 7,500 characters. It then fails to parse and the round is
reported as having produced no answer.

**The better the ticket, the more certainly this fires.** It is not an edge
case; it is the common case for any round that honours the brief.

The parse must not depend on fence discipline. A string-aware balanced-brace
scan for the last JSON object carrying a `status` recovers the observed round's
answer whole, ticket body intact, and was verified against the real transcript
before this ticket was written.

### 2. One unbounded gap ticket, plus bugs for everything else it trips over

**The gap ticket has no bound.** A round's deliverable is ONE detailed ticket
asking for changes to the reproduction engine, and neither its size nor the
scope of work it requests is capped. A round that finds five related residuals
writes one ticket describing five.

The first round did the opposite. It wrote: "Regions 1-5 and 9 ... are
candidate classes for a later round; I am filing the one that is provable
end-to-end." Those findings were discarded with the prose that described them,
and the later round they were deferred to will start from zero and never know
they were seen. **Deferring is losing.** The brief's one-ticket-per-round shape
must not read as one-finding-per-round, and today it does.

**Bugs found along the way are filed separately.** While working towards the
gap ticket a round trips over defects that are not reproduction-engine gaps —
in L1, in its own standing brief or knowledge base, or anywhere in the broader
`1c` implementation. The first round found one: the gate mis-routing its own
verdict, which is a defect in the instrument rather than a gap in the engine,
and it had no shape in which to report it except folding it into the gap
ticket.

A round must be able to hand back such bugs as their own tickets, separate from
the gap diagnosis. The console files them exactly as it files the gap ticket:
the console runs `xgd`, the round does not, and they land at `status: draft`
and never at any `ready_*` status. [[REQ-256]] behaviour 3 — the round writes no
code and runs no command — is unchanged and remains structural.

### 3. Rounds carry context forward across iterations of the same site

Every round today is a fresh `claude -p` with no `--resume` and no
`--session-id`. Each one re-derives its bearings, and a second iteration on the
same site knows nothing of what the first diagnosed.

Rounds must be able to resume a prior round's session across iterations of the
same reproduction. The design question this has to answer: resume is valuable
because the round already knows the site, and dangerous because it anchors the
round on last round's hypothesis when the evidence underneath it has changed,
and because context grows without bound across a long iteration chain. That
second risk is the brief's own one rule turned against it — a round that
reasons from what it remembers rather than from what this iteration captured is
reconstructing, which is the failure mode loop 1 exists to avoid.

State the scope the implementation chose — per site, per iteration chain, reset
on what — and why.

**Priming is [[REQ-262]], not this ticket.** What a round is told BEFORE it
starts — the brief, the session knowledge base, the L1 and engine
documentation — is that ticket's work. This behaviour is only about carrying a
PRIOR ROUND's context forward.

### 4. The transcript shows the round once

`formatStreamEvent` prints the `result` event's text, and the same text has
already been printed as the assistant's final message. Every round's diagnosis
therefore appears **twice** in `transcript.txt` and twice in the pane the
operator reads — 22KB for the observed round, half of it a duplicate. The
`system` event line also printed four times, and printed no model, because the
field it reads was not populated.

### 5. A round's answer is recoverable without re-running the round

The observed round's work was not lost — it is in `transcript.txt` — but the
only way to get a ticket out of it was to re-run the round and pay for it
again. A round that produced a final message the console could not parse must
be recoverable from the artifacts already on disk.

The failure text must also point at those artifacts. `the round produced no
outcome block.` gives the operator nothing to act on and does not mention that
the round's entire diagnosis is sitting next to the message.

### 6. Every round records its model and what it cost

Nothing in `tools/repro-console/src/` records cost, tokens or the model used —
verified by search. `REPRO_CONSOLE_AI_MODEL` is optional, so with it unset a
round runs on whatever the CLI happens to default to, and the console does not
record which that was.

This loop is meant to run many times and its per-round cost is the thing that
decides how many. The `result` stream event carries usage and cost and the
console currently discards both. Record the model and the round's cost beside
the outcome, so "is this affordable to run often" is answerable from the
artifacts rather than from impression.

### 7. Evidence is pre-digested where that is cheaper than reading it

A round has no `Bash`, deliberately, so it cannot query a 4,000-line
`multistate.json` — it reads and greps. That is the correct trade for
[[REQ-256]]'s behaviour 3 and this ticket does not reopen it.

The cheaper half of the same problem is the console's: where a round
predictably needs a derived fact, the console can compute it while it is
already writing the evidence directory, and the round reads one line instead of
a file. Any such digest is an addition to the evidence on disk, never a
replacement for it — the brief's one rule is that claims come from the captured
files, and a round must still be able to reach them.

### 8. This ticket changes no tool permissions

**The tool policy belongs to [[REQ-262]] and only to [[REQ-262]].** Nothing
here widens, narrows or restructures `AI_ALLOWED_TOOLS`,
`AI_DISALLOWED_TOOLS`, `AI_PERMISSION_MODE` or `AI_SETTING_SOURCES`.

That is a concurrency rule, not just a scoping preference: both tickets are
being worked at the same time and both touch `tools/repro-console/src/ai.ts`.
One owner for the policy constants keeps two sessions from editing the same
surface.

Everything this ticket asks for is reachable inside the round's existing
permissions. The round still hands back CONTENT and the console still runs
`xgd` — including for the separate bugs of behaviour 2, which need no new
permission because the round never files them itself.

If work here appears to require a permission change, that is a signal the
change belongs in [[REQ-262]]. Raise it there rather than making it here.

## What landed

Commits are on `fields.commits`. Everything below is the implementation record —
what was built, and the decisions taken inside the latitude the behaviours left.

### The parse (behaviour 1)

`jsonObjectsFromEnd` in `tools/repro-console/src/ai.ts` replaces the fence
regex. It scans for balanced JSON objects, string-aware (a `{`, `}` or a fence
inside a JSON string is data), trying **every** `{` as a start in reverse rather
than skipping past the first one that balances — so a stray brace in a round's
prose can neither swallow the answer nor be mistaken for it. The nested objects
inside the answer (`ticket`, each `bugs` entry) are reached first and rejected
for carrying no `status`, which is what makes the outermost object win.

**The fixture moved.** Requirement 2 names the transcript at
`storage/tmp/repro-console/…`, which is gitignored scratch — a test reading it
would pass here and fail on a fresh checkout. The file is copied byte-for-byte
to `tests/fixtures/repro-console/round-gigabytealchemy-ai-iteration-1.transcript.txt`
and the UAT reads that. It parses to `status: filed`, class
`coverage-check-misses-section-background-images`, and a 6,346-character body
with its fenced `gate.json` and `capture.json` evidence intact; the same test
also asserts that the OLD regex really does truncate it, so the fix cannot
quietly stop being a fix.

### The bugs list (behaviour 2)

`AiOutcome.bugs` is a list of the same `TicketDraft` shape the gap ticket uses,
read on **every** status — a `no-gap` round may still have found a bug, and
that is the case the list exists for. The console files each through the same
`fileTicket` call the gap goes through, so `status: draft` is still written in
exactly one place and widening what a round may REPORT has not widened what it
may TRIGGER. Each bug's body is written to its own `bug-N-body.md` beside the
round, reviewable like every other artifact.

A malformed bug draft is **dropped, not failed**, where a malformed gap draft
fails the round: the gap IS the deliverable, so an empty one would be filed in
its place, whereas losing an aside costs one aside.

Each filed bug becomes another link under the iteration, served by
`/iteration/<n>/ticket/<uid>`. That route is **checked against what this round
filed** rather than passed through to xgd — the console is not a ticket browser
and a route that read any uid a visitor typed would be one.

The unboundedness of the gap ticket is not something the console can enforce, so
it lives where it can bind: the brief now says it in §1 and §6, and the per-round
prompt repeats it with the sentence the first round needed and did not have —
**"Deferring is losing."**

### Resume (behaviour 3)

`tools/repro-console/src/session.ts`, with the scope and the reset rules stated
beside the reasoning for them, as requirement 7 asks.

- **Scope: one CLI session per reproduction chain** — per site slug, for as long
  as the chain is reproducing the same reference. That is the unit because it is
  the unit the value comes from: a resumed round is cheaper because it already
  knows *this page*.
- **Reset on a moved reference** — a different bundle, or a re-capture. The
  remembered numbers then describe a page that no longer exists, so the memory
  is not even safe as a pointer.
- **Reset on a changed brief** — a resumed round is not re-sent the brief, so
  one resumed across an edit would be running the old instructions invisibly.
  The record holds a fingerprint of the brief's text.
- **Reset after `RESUME_MAX_ROUNDS` (5) rounds** — the bound on context growth
  and on how long one hypothesis keeps its grip. Small on purpose: the value of
  resume is front-loaded and the risk is not.

The session id comes from the round's own `system` init event, never from
anything the console mints: the CLI owns session identity.

Two consequences worth recording. **A resumed round is not re-sent the brief** —
re-sending it would grow the session by the brief's own length every iteration,
which is half of what makes a long chain dangerous; it gets `resumePreamble()`
instead, which tells it in as many words that what it remembers is *a pointer,
never evidence*, and that anything it cannot re-read this round it cannot state
this round. And **a resume that will not start is not a failed round**: the CLI
prunes sessions, so an attempt that produced no init event at all is retried
once from scratch. A round that ran and then failed to produce a usable answer
is deliberately NOT retried — that would pay for the same round twice, and
behaviour 5 recovers it for free.

### The transcript (behaviour 4)

The `result` event no longer reprints its text — that text is the assistant's
final message and was already printed, which is where half of the observed
round's 22KB went. Its line now says what the event uniquely knows: what the
round cost. Only a `system` event with `subtype: "init"` is a session starting;
another subtype prints its own name (a compaction boundary matters to a resumed
round) and a subtype-less one prints nothing.

### Recovery (behaviour 5)

`POST /iteration/<n>/recover`, offered as **[read it again]** under any failed
round that left a transcript. It re-reads `transcript.txt`, runs the same
`parseOutcome`, and files through the same path a live round's answer goes
through — so "recovered" is not a second, weaker kind of filing with its own
rules to go stale. It spawns nothing and costs nothing. The round's own
measurements (cost, session) survive the re-read; the working-tree comparison
does not run, because the round that wrote the transcript finished long ago and
attributing today's tree to it would be the false report that check exists to
avoid. The outcome is marked `recovered: true` so the artifact says where it
came from.

A failed round's reason now names the transcript path and says what to press.

### Cost (behaviour 6)

`RoundCost` — model, cost, duration, turns and input/output tokens — read off
the `system` init and `result` events and written into `outcome.json` beside the
outcome, and shown as one line under the round on the page, because "can we
afford to run this often" is a question the operator asks while looking at it. A
round that reported nothing says nothing rather than printing a row of dashes.

### The digest (behaviour 7)

`tools/repro-console/src/digest.ts` writes `ai/evidence-digest.md` before the
prompt that names it. It is **counted, not interpreted** — no ranking of what
matters, no hypothesis:

- every value delta, severity-ordered, with its real expected/actual values;
- every ranked pixel region with its box, score and crop filenames;
- **asset attribution**: for each mirrored image, every path in `capture.json`,
  `multistate.json` and the reproduction's own L1 whose string value names it —
  or `**nowhere**`, which is the other half of the same answer;
- a **key census** of the reference manifest and the capture: every field name
  and how often it occurs, so *"does this document have such a field at all"* is
  one line rather than four tool calls. The first round spent those four calls
  establishing that `"src"` occurs zero times in the manifest and three more
  establishing that the image IS named there, as `backgroundImageUrl`.

Every list is capped and **says so when it caps** — a silent truncation would
read as "that is all of them". The prompt names the digest as arithmetic rather
than a source and still hands over every file it derives from, so the one rule
is unweakened.

### Not done here: the tool policy

Behaviour 8 was rewritten mid-build to assign the policy constants to
[[REQ-262]]. A session-tool-list falsifier had been implemented against the
earlier wording; it was removed (commit 2) rather than carried, and
`AI_ALLOWED_TOOLS`, `AI_DISALLOWED_TOOLS`, `AI_PERMISSION_MODE` and
`AI_SETTING_SOURCES` are untouched by this ticket. Requirement 5 is asserted
instead by a UAT proving that `--resume` is a flag on the same invocation: the
permission mode, the empty settings sources and both tool lists are byte-identical
on a resumed round, so [[REQ-256]] behaviours 3 and 4 hold on iteration 7 exactly
as on iteration 1.

If the check is still wanted, it belongs in [[REQ-262]].

### Acceptance: the gap the first round found

Filed as **BUG-100** (`bug-14025216`), at `status: draft`, carrying the round's
own 6,346-character body verbatim: `referenceCoverage()` builds its referenced
set from `manifest.elements[].src` alone, so section background imagery is
always reported unreferenced — and because `reconcileGates` consults coverage
before value deltas, that false finding hijacks any perceptually-breached run to
`capture-incomplete`, which is the verdict that tells a round to stop and file
nothing.

### Evidence

`tests/test_UAT_FC_REQ-261_loop1_rounds.test.ts` — 13 UATs. Real console, real

commands the console asks the machine about are substituted through the seams

### Requirement 6, re-checked after the behaviour-8 rewrite

Verified as a fact rather than as an intention: the whole `── the tool policy ──`
section of `tools/repro-console/src/ai.ts` — `AI_ALLOWED_TOOLS`,
`AI_DISALLOWED_TOOLS`, `AI_PERMISSION_MODE`, `AI_SETTING_SOURCES` and every doc
comment attached to them — is **byte-identical** across this ticket's commits.

One consequence had to be fixed rather than merely observed. The resume UAT as
first written pinned `'manual'` and named `Bash` directly, which would have made
this ticket's test file **a second place [[REQ-262]] has to edit** in order to
change a constant it owns — the cross-session coupling behaviour 8 exists to
prevent, reintroduced by the test instead of by the code. It now asserts:

- the resumed argv **is** the fresh argv plus `--resume <id>` and nothing else;
- both argvs carry whatever the four constants say, read from the constants
  themselves rather than from literals.

So requirements 5 and 6 are one assertion, and neither of them owns a value.
Checked by changing `AI_PERMISSION_MODE` on a scratch edit: [[REQ-256]]'s UAT
fails, because that ticket owns the value, and all of this ticket's UATs pass.
