## What this is

The D1 store addresses a site by its **key**. `sites.slug` and
`UNIQUE (tenant_id, slug)` are dropped, and nothing in the multi-tenant schema
carries a name that a human chose and a lookup has to undo.

This is [[DOC-45]] §6, which proposed it and left it *"pending the decisions in
§11"*. Those decisions are made: §11 item 4 is settled, and §7 has been rewritten
so the public address is a host chosen at publication rather than a token derived
at provision.

## Why now, specifically

[[DOC-45]] §6 states the deadline and it is the reason this is not deferred:

> The window is open now and closes on the first customer. […] both hold one
> tenant, no users and no sites, so it is still a wipe-and-reapply that costs
> nothing. After a real customer exists the same change is a
> create-copy-drop-rename on every child table.

And [[DOC-45]]'s own order of work puts it first, for a reason that lands
directly on the settings epic: *"the host work would otherwise be built on a
token scheduled to disappear."* [[EPIC-4]]'s children are that host work.

## The bug this closes on the way past

`sessionIdFor(slug)` returns `` `site-${slug}` ``
(`tools/generate/src/cli/ai/host-core.ts:427`), and since [[BUG-90]] the slug is
derived from the business name. The assistant's transcript is homed in a ticket
found by `fields.session_id`, so **the first rename of a business would move the
session id and orphan the entire conversation** — not destroy it, which would at
least be visible, but silently replace it with an empty one.

Nothing triggers this today because no rename path exists. [[EPIC-4]] builds the
rename. Keying the session on the site's own key fixes it before it is reachable,
rather than after somebody loses a conversation.

## Behaviour

- **Every D1 store operation takes a site key.** [[DOC-45]] §6 records that
  `createDraft`, `hasDraft`, `readPages`, `listAssets`, `forget`, `readSiteJson`
  and `write` all currently open with `siteIdOf(slug)` and spend a lookup undoing
  an indirection. The port takes the key; those lookups go, and so does the
  public `siteKey(slug)` whose only job was to expose the conversion.
- **The preview URL carries the site key.** `previewUrl` builds
  `/preview/<slug>/<channel>/` (`apps/control-app/src/builder/api.js:115`). It
  becomes the key. Readability buys nothing on a URL that is never shared and is
  only used during site development, and the URL is already business-scoped
  separately through `setBusinessScope`, so the name carries no information the
  scope does not already supply.
- **The AI session id is derived from the site key**, so renaming a business
  leaves the conversation exactly where it was.
- **Provisioning derives no addressing token from the business name.**
  `businessSiteName(name, businessId)` ([[BUG-90]]) has nothing left to name.
- **A slug-shaped refusal in the port no longer exists**, because there is no
  shape left to refuse.

## What this does not reach

- **Page names stay.** `site_pages.name` — `home.json`, `about.json` — is the
  path *after* the host and is a genuine public address that must stay readable
  ([[DOC-45]] §6).
- **The file-backed authoring tier keeps its directory names.**
  `storage/sites/xgd/` is git-tracked, single-user, has no tenant and nothing to
  collide with. [[DOC-45]] §6 is explicit that *"the rule is about the
  multi-tenant database"*, so `fs-store`, the `1c` CLI and `edit.ts` are out of
  scope by design rather than by omission — which is what keeps this a bounded
  change to one store rather than a rewrite of three.
- **`publicSiteUrl` is already correct** and does not change: it takes the site's
  key today (`apps/control-app/src/public-url.ts`), which is the shape everything
  else is moving to.

## Whether `sites.name` should exist at all

[[DOC-45]] §6 proposes the slug splits into two jobs and that the second becomes
`sites.name` — *"the human label the builder lists sites by"*, prose, no
uniqueness constraint.

**There is no list.** A business holds exactly one site ([[BUG-90]]), and that
site is not named separately from the business that has it. A column whose only
reader would be a selector that does not exist is a column added for a future
this epic has explicitly deferred. It is left out; it costs one migration to add
on the day a business holds two sites, which is the same day the site selector
lands.

## Falsifiers

- A slug column, or any unique index over a human-chosen name, in the
  multi-tenant schema.
- A D1 store method that resolves a name to a key before doing its work.
- A session id that changes when a business is renamed.
