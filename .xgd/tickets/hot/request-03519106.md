## What this is

The D1 store addresses a site by its **key**. `sites.slug` and
`UNIQUE (tenant_id, slug)` are dropped, and nothing in the multi-tenant schema
carries a name that a human chose and a lookup has to undo.

This is [[DOC-45]] §6, which proposed it and left it *"pending the decisions in
§11"*. Those decisions are made: §11 item 4 is settled, and §7 has been rewritten
so the public address is a host chosen at publication rather than a token derived
at provision.

## Why now, specifically

[[DOC-45]] §6 states the deadline and it is the reason this is not deferred:

> The window is open now and closes on the first customer. […] both hold one
> tenant, no users and no sites, so it is still a wipe-and-reapply that costs
> nothing. After a real customer exists the same change is a
> create-copy-drop-rename on every child table.

And [[DOC-45]]'s own order of work puts it first, for a reason that lands
directly on the settings epic: *"the host work would otherwise be built on a
token scheduled to disappear."* [[EPIC-4]]'s children are that host work.

## The bug this closes on the way past

`sessionIdFor(slug)` returns `` `site-${slug}` ``
(`tools/generate/src/cli/ai/host-core.ts:427`), and since [[BUG-90]] the slug is
derived from the business name. The assistant's transcript is homed in a ticket
found by `fields.session_id`, so **the first rename of a business would move the
session id and orphan the entire conversation** — not destroy it, which would at
least be visible, but silently replace it with an empty one.

Nothing triggers this today because no rename path exists. [[EPIC-4]] builds the
rename. Keying the session on the site's own key fixes it before it is reachable,
rather than after somebody loses a conversation.

## Behaviour

- **Every D1 store operation takes a site key.** [[DOC-45]] §6 records that
  `createDraft`, `hasDraft`, `readPages`, `listAssets`, `forget`, `readSiteJson`
  and `write` all currently open with `siteIdOf(slug)` and spend a lookup undoing
  an indirection. The port takes the key; those lookups go, and so does the
  public `siteKey(slug)` whose only job was to expose the conversion.
- **The preview URL carries the site key.** `previewUrl` builds
  `/preview/<slug>/<channel>/` (`apps/control-app/src/builder/api.js:115`). It
  becomes the key. Readability buys nothing on a URL that is never shared and is
  only used during site development, and the URL is already business-scoped
  separately through `setBusinessScope`, so the name carries no information the
  scope does not already supply.
- **The AI session id is derived from the site key**, so renaming a business
  leaves the conversation exactly where it was.
- **Provisioning derives no addressing token from the business name.**
  `businessSiteName(name, businessId)` ([[BUG-90]]) has nothing left to name.
- **A slug-shaped refusal in the port no longer exists**, because there is no
  shape left to refuse.

## What this does not reach

- **Page names stay.** `site_pages.name` — `home.json`, `about.json` — is the
  path *after* the host and is a genuine public address that must stay readable
  ([[DOC-45]] §6).
- **The file-backed authoring tier keeps its directory names.**
  `storage/sites/xgd/` is git-tracked, single-user, has no tenant and nothing to
  collide with. [[DOC-45]] §6 is explicit that *"the rule is about the
  multi-tenant database"*, so `fs-store`, the `1c` CLI and `edit.ts` are out of
  scope by design rather than by omission — which is what keeps this a bounded
  change to one store rather than a rewrite of three.
- **`publicSiteUrl` is already correct** and does not change: it takes the site's
  key today (`apps/control-app/src/public-url.ts`), which is the shape everything
  else is moving to.

## Whether `sites.name` should exist at all

[[DOC-45]] §6 proposes the slug splits into two jobs and that the second becomes
`sites.name` — *"the human label the builder lists sites by"*, prose, no
uniqueness constraint.

**There is no list.** A business holds exactly one site ([[BUG-90]]), and that
site is not named separately from the business that has it. A column whose only
reader would be a selector that does not exist is a column added for a future
this epic has explicitly deferred. It is left out; it costs one migration to add
on the day a business holds two sites, which is the same day the site selector
lands.

## What the removal drags with it

These are consequences of the change above rather than separate intentions, and
they are written down because each is a behaviour a reader could otherwise meet
only in a diff.

- **`createDraft` mints the key and hands it back.** It used to take a slug and
  answer whether it had created anything — a shape only a chosen name makes
  possible, because `INSERT OR IGNORE` needs something to collide on. With the
  key minted inside the statement there is nothing to collide with, so every
  call creates a site and the caller cannot address the one it just made unless
  the verb returns its key.
- **[[BUG-51]]'s guard moves to the caller.** *"Do not scaffold over a site that
  already exists"* was expressed as `createDraft`'s return value. It is asked of
  `siteKeys()` now, before the call — which sees every site the business holds
  rather than a collision on the one name that happened to be passed, and is the
  stronger guard for it.
- **The portal is found by `kind`, not by a reserved name.** `/account` serves a
  portal a business may author into its own store, and it was found under the
  reserved slug `portal` — a magic word a customer could have collided with, and
  one that cannot survive the column being dropped. `sites.kind` is a closed
  enum the code declares; it is not typed by anyone, addresses nothing on its
  own, and the site is still named by its key alone. `siteKeys(kind?)` narrows by
  it; omitting the argument means every site the business owns, which is what the
  [[DOC-37]] erasure path needs and what a builder site list must not use.
- **The builder's wire vocabulary says `site`.** The query parameter and JSON
  body key that named a site on `/api/copy`, `/api/palette`, `/api/assets`,
  `/api/upgrade` and `/api/ai/session` were all called `slug`, and `/api/sites`
  answered with a `slug` field. The value is a key now and the name has to say
  so, or every reader of the wire keeps a word the store no longer uses. The
  builder modules that consume it (`previewUrl`, `assetUrl`, `mountEditor`,
  `mountImagePicker`, `openPalettePopup`, `sendUpload`) take `site` for the same
  reason.
- **`POST /api/import` resolves its own target.** The payload used to address one
  by slug, and cannot: a D1 site is named by a key and `1c push` reads a
  directory under `storage/sites/` that has never seen one. The target is this
  business's own site — the one of kind `site`, created when the business holds
  none. A business holding several is refused with a message saying so rather
  than guessed at, because guessing would overwrite a site nobody was pushing to.
  `payload.slug` survives and names the SOURCE: what the site is called on the
  laptop it came from, which is what a refusal has to say back, and it addresses
  nothing on the receiving end.
- **`1c push` prints the destination key**, because it is the site's public
  address and the only handle the operator now has for what they just wrote.
- **A key is never shown to a user as a name.** The palette popup's empty state
  read `<slug> has no colors yet`; a 128-bit key in that sentence is noise, so it
  says `This site has no colors yet.` The starter page's `seoMeta` had the same
  shape — `<slug> — Home`, `Welcome to <slug>` — and takes the business's name as
  entered instead, which is what those two sentences were always reaching for.
  Anywhere a chosen name used to appear in prose and has become a key, the key is
  dropped rather than displayed.
- **`theOneSite` asks for kind `site`.** The upload path that places a correction
  on "the one site" enumerated every row, so a business that had authored a
  portal owned two and the answer became "no single site" — silently declining to
  place bytes because of a page authored at `/account`.

## Migration

`0005_retire_site_slug.sql` drops `idx_sites_tenant_slug`, drops `sites.slug`,
adds `sites.kind` defaulted to `site`, and adds `idx_sites_tenant_kind` to
replace the index the unique constraint was silently serving for every
`WHERE tenant_id = ?` read.

It is a file rather than an edit to the baseline because the baseline has been
applied to both databases and `wrangler d1 migrations apply` records what it has
run — so an edit reaches neither, and would leave both holding `slug TEXT NOT
NULL` while the store had stopped writing it. The first symptom of that is every
`createDraft` failing on a constraint invisible from the code.

**It is the first migration in this project that is not re-runnable**, and the
test fixture absorbs that. Migrations `0001`–`0003` are `IF NOT EXISTS`
throughout, so `applySchema` was free to call twice and several suites do — one
`beforeAll` per `describe`, because workerd storage persists across them inside
one file. `0005` cannot be written that way: a second pass reaches `0001`'s
`CREATE UNIQUE INDEX … (tenant_id, slug)`, which `IF NOT EXISTS` no longer skips
because `0005` dropped that index, and fails on a column that is gone. So
`applySchema` asks the DATABASE whether it is at head — `PRAGMA table_info(sites)`
for the `kind` column — rather than memoising in a module variable, which is
correct under either isolation regime.

**It is numbered `0005` and not `0004`.** It was written as `0004`; [[REQ-240]]
landed its own `0004_user_acceptances.sql` on `xgd-working` while this was on a
branch, and `wrangler d1 migrations apply` orders by filename, so two files
sharing a number is an ordering nobody declared. Renumbering is free because
neither had been applied to a database anyone shares. The fixture's migration
list carries both, in that order.

## Falsifiers

- A slug column, or any unique index over a human-chosen name, in the
  multi-tenant schema.
- A D1 store method that resolves a name to a key before doing its work.
- A session id that changes when a business is renamed.
- A store verb, a route, or a builder module that still calls a site's
  identifier a slug.
- A reserved site name of any kind — `portal`, `unnamed`, or another — used to
  find a row.
