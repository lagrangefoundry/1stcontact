I fixed 9 of the 11 failing tests in this batch. The other 2 are blocked: the production code needs a change, and code is frozen in this mode.

**Fixed (test-only).** All three reconciliation files still called `ticketStoreFor(env)` the old way, with the tenant passed as `TENANT_ID` in the env. The code now takes `ticketStoreFor(env, scope)` and reads `scope.businessId`, so every test that touched the store failed with `Cannot read properties of undefined (reading 'businessId')`. I changed the `storeFor` helper in each file to pass `{ businessId: tenant }`, the same shape other passing suites use:
- `tests/reconciliation-material-description.workers.test.ts`
- `tests/reconciliation-material-description-digest.workers.test.ts`
- `tests/reconciliation-material-description-session.workers.test.ts`

No assertions changed. After the rerun, 21 of 23 tests in those files pass, including every AC1690, AC1693, AC1694, AC1697 and AC1698 test and the digest-era AC2097 test. That should also clear the orphaned AC-1693, AC-1697 and AC-1698 entries. Nothing is committed; the workflow handles that.

**Blocked (production defect).** Two tests still fail, and the cause is in the code, not the tests:
- `test_UAT_AC2097_documents_and_images_are_each_described_in_their_own_toolless_unprimed_session` fails with `images.seen` empty: no image request reached the network.
- `test_UAT_AC2378_image_and_document_describers_never_answer_for_each_other_in_either_build_order` fails because the image description status is `'failed'`.

The underlying error, shown in full by `tests/test_UAT_FC_REQ-207_image_describer_session.test.ts`, is:

> BackendError: The 'material_image_describer' backend refused this content: image content requires a backend with the vision capability. The 'material_image_describer' backend declares no vision capability…

`apps/control-app/src/ai.ts:189` registers each describer's backend with `lib.registerBackend(name, () => backend)` and declares no capabilities. The installed `@lagrangefoundry/ai` defaults `vision` to false (`src/backend.js:166`) and checks it per backend name before sending an image (`src/backend.js:220-225`). So every image description is refused before it reaches the model. In real use, every image the client uploads would be stored with the "describer failed" outcome. The tests are correct as written, and changing them to pass would mean hiding a real fault.

The library lives outside this worktree (`/Users/martin/lagrangefoundry/node_modules/`) and my reads of it were denied, so I didn't check the exact `registerBackend` signature.
