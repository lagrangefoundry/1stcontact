Both batch failures are fixed, and every test in the batch scope passes: 73 tests across 8 files. All edits are in the five files the exception allows.

- **AC-2509 (a body is capped while it is read):**
  - **Test first:** I added a submission with no declared length whose body never ends. It must get a 413, the stream must be cancelled, and no more than `MAX_BODY_BYTES` plus one chunk may be read. Against the old code the test hung, because `request.arrayBuffer()` waits for the whole body before anything measures it.
  - **Fix:** `readFields` in `apps/public-site/src/lead.ts` now reads the body chunk by chunk and keeps a running byte count. As soon as the count passes the cap, it cancels the stream and returns the existing 413. The declared-length check and the bytes-then-decode step are unchanged, and the comment now says truthfully how the read is bounded.
- **AC-2486 (the drawing caption):**
  - **Test first:** the test now asserts that the SVG caption contains "letter widths and line breaks" and "not evidence". The old caption failed it.
  - **Fix:** `DRAWING_RASTER_NOTE` in `tools/generate/src/cli/picture.ts` gains that warning and keeps the default-face and `measure_drawing` parts. The caption text in `fidelity-surface.json` and the comment above the constant say the same.
- **Not changed:** multipart handling and bounce/complaint suppression, as the planner instructed. The AC tickets already describe this behaviour, so neither the ACs nor the story needed updating.
