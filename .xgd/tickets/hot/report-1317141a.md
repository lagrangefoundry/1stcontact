## Step 0 — Intent, as the operator stated it

**BUG-39** — "one streaming model double, shared by every suite". The declared
scope is the *test double*, not the product: four suites each carried their own
transcription of the provider's wire protocol; the shared AI backend moved to
`messages.create({stream: true})` and its accumulator now reads block events;
three Node suites kept handing back a finished `{content: [...]}` message that
is never read, so their turns completed having seen no text and no tool call —
15 assertions failing on the assistant's half of a turn simply not existing.
The fix collapses four copies into one shared double and adds a drift guard.
The ticket explicitly flags two surviving failures as **out of scope** and
"for the operator to decide".

**REQ-154** — "the headless browser in the cloud: a Browser Rendering driver
behind the existing seam". The declared scope is the **second implementation of
an interface that already exists** (`BrowserDriver` / `BrowserDriverFactory`),
plus the binding it needs. The body names the one part that is *not* mechanical:
our own preview output sits behind the access gate, so a browser the Worker
launches is challenged and photographs the challenge page. The body offers three
candidate answers and requires the choice be settled here with reasons recorded.
The implementation record (the "What was built" half of the ticket) states a
**fourth** option was found and shipped: in-process request fulfilment. Two
things are declared deliberately not done — no HTTP route answers the screenshot
capability, and reference bytes have not moved to object storage.

## Observations

- **Two items, not five, and the reason is that the seam already existed.** The
  REQ-154 commit is 2,233 insertions, which invites inflation. But the ticket is
  right about itself: `BrowserDriver` / `BrowserDriverFactory` were declared for
  this on the day the capture pipeline was written, and `1c shot`, the capture
  pipeline, the conformance harness and the fidelity gate all already take a
  factory. Nothing above the seam changed. What is genuinely new is one driver
  and one origin-fulfilment mechanism.

- **The lease was NOT split out.** Session release on success / failure / timeout
  is the ticket's own AC6 and carries 5 UATs, which tempts a third item. It is
  folded into item 1: a metered driver that strands sessions is not a separate

  verdict on a page that was not clean. That is worth an AC of its own inside
  item 1, because it is the one reuse that would be silent.
