# values-diff: the reference's page background is inferred from the tallest band, so the one thing a bundle records seven times is never compared

Filed by `repro-console:repro-joyfulculinarycreations-com#4`, iteration 4 of the reproduction of
https://joyfulculinarycreations.com.

`defect_class`: **`instrument-blind`**.

This is the ruler half of the gap ticket filed alongside it (issue 1 there — the fold takes the page
canvas from the tallest band). The engine half is that the reproduction paints the wrong canvas. This
half is that **the comparator cannot tell**, because it derives the *reference's* canvas by the same
broken method and then compares the wrong value against itself.

## What happens

`tools/generate/src/cli/capture/value-axes.ts:849-856`:

```ts
{
  axis: 'bodyBackground',
  role: 'carried',
  note: 'BUG-27 — the page\'s base fill: what shows through wherever no band paints. Read off `<body>` on the reproduction side; inferred from the widest band on the bundle side, because that is the only place a bundle records it. …',
  reference: (capture) => pageBaseOf(capture.sections),
  reproduction: (signals) => signals.bodyBackground,
}
```

and `pageBaseOf` (`value-axes.ts:821-832`) is the largest-area section carrying a background colour:

```ts
for (const s of sections) {
  const area = (s.box?.width ?? 0) * (s.box?.height ?? 0)
  if (area > bestArea && s.background.color) { bestArea = area; best = s.background.color }
}
```

**The note's premise is false.** The bundle records `bodyBackground` directly, at every projection, in
`multistate.json` — written by the extractor at `tools/generate/src/cli/capture/extract.ts:3068`
(`bodyBackground: bodyBg`). It is `capture.json` that carries no such key; `multistate.json` sits
beside it in the same bundle and the differ already reads it.

`values-diff.json` reports **zero deltas** for it. `bodyBackground` is `role: 'carried'`, so it is not

wrong" — and nothing in `values-diff` can follow it.

## The proposed change

1. `reference: (capture) => …` should read the bundle's recorded value —
   `multistate.projections[].manifest.bodyBackground`, which the differ already loads — and fall back
   to `pageBaseOf(capture.sections)` only when no projection recorded one. Correct the note while you
   are there: the claim "that is the only place a bundle records it" is what made this invisible.
2. Consider promoting the axis from `role: 'carried'` to `role: 'compared'`. It is a single colour per
   document, it is recorded on both sides, and on this page it is worth more pixels than any value the
   table does compare. As a compared axis it would have produced one delta instead of 22% of the page's
   disagreement in silence. (This will **raise** the delta count by one on this bundle, which per
   [[REQ-277]] is the instrument sharpening, not a regression.)
3. The capture should also write `bodyBackground` into `capture.json` so the primary record is not the
   one place it is missing — that half is in the gap ticket's issue 1 and is capture-side, so it needs a
   re-capture. Item 1 here needs neither a re-capture nor a refold.

# What was implemented

Items **1 and 2**. Item 3 is capture-side, needs a re-capture, and stays with the gap ticket.

## 1. The reference reads what the bundle recorded

A capture bundle is **two artifacts**, and the manifest-level axes need both. `capture.json` is the
structural record (theme, bands, runs); `multistate.json` is the projection ladder, and every cell of
it is a `ValueManifest` the extractor wrote from the reference's *own* `<body>` at capture time. The
reference side of the axis table had no way to reach the second one, which is why the canvas was
inferred at all.

- `value-axes.ts` — the reference side of a manifest axis now takes a **`CaptureManifest`**
  (`{ capture, recorded? }`) rather than a bare `Capture`, mirroring what `CaptureBand` already does
  for a section (where the bundle's `captureSchema` travels with the band). `recorded` is a
  `RecordedManifest` = `Pick<ValueManifest, 'bodyBackground'>` — deliberately narrow, so the type says
  exactly which axes a `capture.json` genuinely cannot answer; widening it when a second such axis
  appears is a one-word edit. The three existing rows (`viewport`, `subScales`, `bodyBackground`)
  destructure `{ capture }`; `bodyBackground` reads
  `recorded?.bodyBackground ?? pageBaseOf(capture.sections)`.
- `pageBaseOf` is kept, **as a fallback and only that** — a bundle captured before the projection
  ladder existed has nothing better, and inferring beats declining. Its doc comment now says so, and
  names the joyfulculinarycreations `sections[3]` case as the reason it is wrong whenever the widest
  band is not the page.
- The row's `note` is corrected. The old sentence — "inferred from the widest band on the bundle side,
  because that is the only place a bundle records it" — was the false premise that made this
  invisible, so the new note states where the value actually lives and that the widest band is a
  pre-ladder fallback.
- `values-diff.ts` — a new exported **`recordedManifestOf(capture, multistate)`** resolves the
  recorded values. It selects the projection at the **capture's own viewport width** (via the existing
  `selectProjectionAtWidth`), because the canvas is recorded per projection and a media-query /
  colour-scheme canvas can legitimately differ across the ladder; a ladder-wide scan is the fallback
  for a projection that predates the axis, not the primary reading. It returns `undefined` — never a
  fabricated default — for a bundle with no ladder, so the axis falls back to inference rather than
  asserting a colour nothing measured.
- `flattenCapture(capture, multistate?)` takes the ladder as an optional second argument and passes
  `{ capture, recorded }` to the projector. Optional so the offline / pre-ladder paths still flatten.
- Both call sites now hand it the whole bundle: `fidelity.ts`'s `runValuesDiff` (the single-width
  `1c values-diff` path — the one that was broken; the `--size` and `--multi-viewport` paths already
  read `multistate.json` directly and were never affected) and `fidelity-core.ts`'s `check_fidelity`
  tool. `readMultiState` is tolerant (`null` for a pre-ladder bundle), which is what keeps the
  inference available as the fallback it now is.

## 2. The axis is compared, not merely carried

`role: 'carried'` → `role: 'compared'`, and `diffManifests` gained the comparison to match — `role`
alone drives only `UNMEASURED_AXES`, exactly as it does for the other two compared manifest axes
(`viewport`'s precondition check and `subScales`' attribution are both hand-written too).

- A new `DeltaProperty` **`bodyBackground`**, registered `VALUE_TYPE: 'A'` (authored — the repair is
  to copy the reference's value into the document's base fill) and `PROPERTY_KIND: 'color'` (a wrong
  canvas is a colour defect, with the colour tolerance every other colour axis gets).
- One delta per document, recorded as `§canvas` / `document`, because the canvas is the fill that shows
  through wherever no band paints and the bands are exactly where it does not show — so it belongs at
  the manifest level, not on any band.
- `undefined` on either side is **unmeasured, not clean**, and is skipped: a bundle with no ladder and
  no band carrying a background has recorded no answer, and comparing against a stand-in would fire a
  delta on every such reference.
- **Known consequence, deliberately not changed:** the delta lands in the existing `color` kind, which
  is `LOW` tier, and the report ranks by tier before severity — so the page's largest single
  disagreement still sorts below every `MEDIUM`/`HIGH` row (its severity number, 1060, is high). This
  is how `color` and `surfaceFill` already behave for a completely wrong band fill. Giving the canvas
  its own higher tier would change gate pass/fail thresholds across every reference and was outside
  what this ticket asked for; it is worth a separate decision.

## Test plan

`tests/test_UAT_FC_BUG-169_the_page_canvas_is_read_and_compared.test.ts` — seven UATs through the real
`cmdValuesDiff` command, offline via the documented `--actual` manifest seam, against a bundle written
to disk whose shape reduces the filing page to five bands (a white band, a taller grey band that is the
widest painted thing, a black hero, and two `kind: 'none'` strips):

1. `reference_reads_the_recorded_canvas_not_the_tallest_band` — the ladder records `#ffffff` and the
   widest band paints `#7a7a7a`; the reference manifest reads white.
2. `a_wrong_canvas_is_one_delta_not_silence` — a reproduction painting the widest band's grey produces
   exactly one `bodyBackground` delta, `#ffffff → #7a7a7a`, `kind: 'color'`, `valueType: 'A'`.
3. `a_reproduced_canvas_that_matches_is_clean` — a reproduction painting the recorded canvas is clean
   on the axis, so the row is a measurement and not an unconditional alarm.
4. `a_bundle_with_no_ladder_falls_back_to_the_widest_band` — the pre-ladder inference still works, so
   the fix needs no re-capture of old bundles.
5. `the_canvas_is_resolved_at_the_captures_own_width` — a ladder recording `#ffffff` at 375 and
   `#0b0b0d` at 1280, with a 1280 capture, grades against the 1280 cell and not the first-listed one.
6. `the_canvas_axis_is_compared_with_readers_on_both_sides` — the declaration itself: `role:
   'compared'`, a reader on each side, absent from `UNMEASURED_AXES`, and a note that names
   `multistate` (the sentence whose absence hid the defect).
7. `a_canvas_no_side_recorded_is_unmeasured_not_clean` — no ladder and no band background leaves the
   axis absent from the reference manifest and fires no delta.
