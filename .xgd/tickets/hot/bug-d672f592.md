## Symptom

`wrangler dev` fails to build the control app:

```
✘ No matching export in "src/generated/ai-knowledge.js" for import "KnowledgeDocs"
    src/session-knowledge.ts:2
    src/system-knowledge.ts:3
```

Appeared immediately after re-running `bin/install --component all` against
`lagrange-framework`, which repopulated the shared `@lagrangefoundry/*` store
(mtime 2026-09-07 11:20) from the framework's current `xgd-working`.

## Root cause

The shared component store is **not version-pinned** — every package reports
`"version": "0.0.0"` and nothing in this repo records which framework commit it
was installed from. `bin/install` therefore always delivers the framework's
head, and the framework moved four days ahead of us while nothing here changed.

1stcontact last touched its AI host on 2026-09-02
(`f0724a537f`, `tools/generate/src/cli/ai/host-core.ts`). Since then the
framework landed the **DOC-22 three-tier priming architecture** and the
knowledge changes that ride on it:

| framework commit | date | what it changed |
|---|---|---|
| `28367ac5aa` | 09-03 | three-tier priming configuration — `Role` reshaped |
| `c77717d61f` | 09-03 | **KM priming providers replace `KnowledgeDocs`** |
| `ec4ec07300` / `b9ac6366bb` | 09-03 | `landscape_text` + `mechanism_text`, async, cache nothing |
| `d1356ac3c7` | 09-04 | the knowledge document tier |
| `4d3a68b45e` | 09-05 | explicit priming cache-boundary marker |
| `c62eeeb132` | 09-06 | retire recycle-and-carry; bound the window in turn pairs |

The build error is only the **loudest** consequence, and it is the least
important one.

### The silent half

`Role`'s constructor in the installed `@lagrangefoundry/ai` is now:

```js
constructor({ name, priming = [], reminders = [], tools, permissions,
              sandbox, cacheBoundary } = {}) { ...; Object.freeze(this) }
```

`system`, `source` and `reminder` are **gone**. Priming is assembled by
`assembleMarked(product, role, ctx, {providers})` from a product tier plus a
role tier of named entries, each rendered by a registered `PrimingProviders`
entry.

This repo is on the pre-DOC-22 API at every call site and has migrated nothing —
grep for `PrimingProviders`, `productFromMapping`, `registerDefaults`,
`registerKmProviders`, `cacheBoundary` returns zero hits outside `node_modules`.
Both `Role` constructions still pass the retired keys:

- `tools/generate/src/cli/ai/host-core.ts:591` — `system: CONSULTANT_SYSTEM`,
  `source: deps.priming ? … : …`, `reminder: consultantReminder(slug)`
- `apps/control-app/src/ai.ts:161` — `system: DOCUMENT_DIGEST_SYSTEM`,
  `source: { documents: () => [] }`

Because the object is frozen over a fixed key set, those keys are **silently
dropped**. So deleting or stubbing the `KnowledgeDocs` import — the apparently
obvious two-line fix — produces a Worker that builds, boots, and serves an
assistant with **no system prompt, no role purpose, no KM landscape and no
reminder**. That is strictly worse than the current failure, which at least
stops.

### The replacement shape

`@lagrangefoundry/ai-knowledge` now exports `landscapeProvider`,
`mechanismProvider` and `registerKmProviders(providers, runtime, {mechanismFor, kb})`.
The map and the mechanism become two *named priming sections* in a product
mapping rather than one assembled `ContextSource`; `mechanismFor(backend)`
returning `null` drops both, which is how a backend with no knowledge surface is
expressed. `@lagrangefoundry/ai` supplies `PrimingProviders`,
`productFromMapping`, `registerDefaults` / `defaultProviders` / `defaultProduct`,
and `SessionManager` gained `{product, providers, cacheBoundary, windowTurns, …}`
options to carry them.

## Decision

Operator direction (2026-09-07): **migrate**. This is a dev environment with no
production data. Any local state that the migration invalidates — chat
transcripts, live junctions, the miniflare D1/R2 stores — is to be cleared
rather than migrated. **The one artefact that must survive is the draft `xgd`
site** (`storage/sites/xgd`). Everything else is expendable.

## Behaviour

### The session is primed again, through configuration rather than two fields

A session's priming is assembled from an ordered list of named entries across a
product tier and a role tier, each entry either static text or a named provider
(DOC-22 §2, §3). This project's assembly reproduces, entry for entry, the
document it used to build by hand:

- **`consultant-system`** — static text, `CONSULTANT_SYSTEM`. First, because it
  was the role preamble and the preamble came first.
- **`km-landscape`** — the `km.landscape` provider: the map of what territories
  exist, one per visible knowledge base.
- **`purpose`** — static text, `CONSULTANT_PURPOSE`.
- **`km-mechanism`** — the `km.mechanism` provider: how *this* session reaches
  the corpus.

Landscape, then purpose, then mechanism is KM's own order and is load-bearing:
the last thing the agent reads is the first thing it does. The manual travels
in as the mechanism, so the corpus is reached through THIS session's actual
grant rather than through a sentence written by hand about what it might have.

**A host with no knowledge base still primes coherently.** Where the KB has not
been built, the two KM entries are absent and the manual is delivered on its
own, after the system text. An operator who has never run `1c kb build` gets an
assistant that knows its tools and not the design documents — which is the
assistant this host had before — rather than one that fails to start.

**The describer role primes with its digest instruction and nothing else.** It
is handed one document and there is nothing else it should know.

### The per-turn reminder becomes a provider

`Role` is frozen. The reminder is therefore rendered by a registered reminder
provider that reads the host's per-turn state at assembly time, and the host
never assigns to a role object. What the reminder carries is unchanged: the
site's slug, the two habits that decay, the change signal when the client has
moved the site, and the corpus delta when one arrived.

The change signal and the corpus delta remain absent when there is nothing to
report. A reminder that says "nothing happened" every turn is one that gets
skimmed on the turn something did.

### A session started under a legacy role name still reopens

Unchanged by this migration and asserted alongside it, because the role registry
is rebuilt here: `caretaker` remains a second key onto the same role object.

### The generated shim carries the new names

`1c assets` writes the bridge shim from an explicit export list. It names the
KM priming providers and no longer names `KnowledgeDocs`, which upstream
deleted. Listed rather than wildcarded, so the next upstream rename surfaces as
a typecheck failure here instead of `undefined is not a function` inside a turn.

## Fix

Adopt DOC-22 in this repo:

1. `tools/generate/src/cli/ai/host-core.ts` — build a `PrimingProviders`
   registry and a `ProductConfig` per manager; construct `Role` with `priming` /
   `reminders` entries; register the reminder provider; drop the
   `role.reminder = …` mutation in `streamPrompt`.
2. `tools/generate/src/cli/ai/host.ts` — reshape the `HostDeps.priming` seam
   from "build a `ContextSource` from the box" to "register KM's providers and
   contribute its entries"; wire `registerKmProviders`.
3. `apps/control-app/src/system-knowledge.ts`, `session-knowledge.ts` — same
   seam on the Worker side, replacing both `KnowledgeDocs.open` call sites.
4. `apps/control-app/src/ai.ts` — the describer `Role`.
5. `tools/generate/src/cli/assets.ts` — `AI_KNOWLEDGE_EXPORTS`.
6. The three test files naming `KnowledgeDocs`.

## Test plan

UATs named `test_UAT_FC_BUG-63_*`. The regression that matters is **not** "the
Worker builds" — it is that a constructed session's assembled priming actually
contains what it is supposed to. The old shape had no test asserting that, which
is why the dropped `Role` keys would have shipped silently.

- the assembled priming carries the system text, the landscape, the purpose and
  the mechanism, in that order
- a host with no knowledge base primes with the system text and the manual, and
  names no KM section
- the reminder is rendered per turn by a provider, and the host mutates no role
- the change signal and the corpus delta appear only when there is something to
  report
- a session recorded under `caretaker` reopens against the consultant role
- the generated bridge shim names the KM providers and not `KnowledgeDocs`
