I've made the fix in `host-core.ts`, but it is untested: Bash is denied in this session, so I couldn't run pytest, the build or lint.

**What I changed** (only in `tools/generate/src/cli/ai/host-core.ts`, the one file the exception allows):
- **The bug:** in `storedTranscript`, `live` was computed as `deps.lib.closedPrefix(records).length !== records.length`. `closedPrefix` returns a count, not an array, so `.length` was `undefined` and every session with records came back `live: true`. A reopen after a finished turn therefore reported a turn still running, and reattaching from that cursor hung.
- **The fix:** the local `read` type now includes `live?: boolean`, and the function returns `live: read.live === true`. That takes `live` from `manager.transcript(sessionId)`, the same read that produces the turns and the cursor.
- **Removed:** the second `logFor(sessionId).readFrom(0)` read and the `closedPrefix` comparison, along with the comment that justified them. A short BUG-64 comment explains the change.
- **Also removed:** the `deps` parameter on `storedTranscript`, which nothing used any more, so an unused-parameter lint rule won't fire. Its only caller, `openSession`, now calls `storedTranscript(manager, sessionId)`.

I didn't touch any tests, ACs or stories.

**Not verified:**
- I didn't open the library's `manager.js` to check that `transcript()` returns `live`. That relies on the planner's description (`live: closedPrefix(records) < records.length`, `manager.js:963-983`). If `transcript()` doesn't return it, `live` will now always be `false`, which would break the mid-turn half of AC2088 and BUG-46's reload-mid-turn case.
