## The fix

Rather than special-case `#`, the audit collapsed the symptom and one further case into a single rule — after dropping the slash, **is the first path segment non-empty and colon-free?** If not, prefix `./`:

```ts
const rest = v.slice(1)
const firstSegment = rest.split(/[/?#]/, 1)[0]
return firstSegment === '' || firstSegment.includes(':') ? `./${rest}` : rest
```

Both cases are the same defect the ticket identified — dropping the slash changed what the remainder *means*, not its shape. `/#how` and `/?q=1` (which had it too) lose their path entirely and resolve against the current document; `./` forces a path segment so they resolve against the snapshot directory, still document-relative.

## Security finding from the audit

The "check the rest of the sink" pass turned up a live XSS. `isSafeUrl` admits `/javascript:…` *because* the leading slash makes it relative — then `relativizeUrl` stripped that slash behind its back and handed back the URL the validator had just refused:

```
/javascript:alert`1`  →  isSafeUrl: true  →  href="javascript:alert`1`"
```

Parens and quotes are blocked by `URL_FORBIDDEN_CHARS`, so the usual payloads never reached the code — a backtick payload did, at the node-link `href` sink. Same rule closes it.

Your three audit questions: query strings are fine (`?v=` cache-busting unaffected); the flat-snapshot assertion still fires and is now pinned by a UAT; the non-`index.html` page condition is now genuinely exercised — every behavioural UAT renders a two-page snapshot and asserts on browser-resolved URLs, not emitted spelling. ## One design point worth your eye

**A trailing slash is deliberately not eligible**, and that's load-bearing rather than tidiness. Pages reference assets document-relatively (REQ-109), so the request URL's *directory* is what `theme.css` resolves against:

- `…/<sha>/whitepapers` → directory `…/<sha>/` → references land ✓
- `…/<sha>/whitepapers/` → directory `…/whitepapers/` → everything resolves a level too low, page loads unstyled ✗

That's the same failure the existing `redirect` route prevents at the snapshot root. Serving the page at both URLs would have looked like a convenience and quietly shipped an unstyled variant.
