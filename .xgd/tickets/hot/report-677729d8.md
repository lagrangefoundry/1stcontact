I wrote one UAT for STORY-119's AC-1342, and it passes.

The BUNDLE-39 plan changes one AC in this story: AC-1342, the committed-credential scan's new exemption for the identity mapping (BUG-59). The existing UAT for AC-1342 in `tests/reconciliation-platform-build-deploy-smoke.test.ts` only checks two of the new rules: the committed tree scans clean, and a provider key put under the exempted name is still caught. It doesn't check the edge cases the reworded AC now lists, so the new test covers them. It runs the real scan code (`tests/support/credential-scan.ts`) over the real committed `wrangler.toml` files, and over copies of the control app's file with the one mapping line changed. It checks that:

- **Real config passes:** every Worker's deployment configuration scans clean. The production mapping `1stcontact-publish=…` is read as an exempted entry and is a valid `name=address` pair. The same line under a name that isn't exempted would be flagged, which shows the clean result really comes from the exemption.
- **Valid values pass:** an empty value has no entries and passes, and several well-formed pairs pass.
- **Bad entries fail:** five bad entries fail in the same run, with the file and the offending entry in the failure message. They are a bare token, no `@`, no dotted domain, a space in the name, and an empty name.
- **Value checks still apply:** a provider-prefixed key or a private-key block is still caught under the exempted name.
- **The exemption is a named list:** `DEPLOY_TOKEN_IDENTITIES` and `API_SECRET_IDENTITIES` are not treated as exempt, and the scan still reports their credential-named values.

I didn't change any runtime code, existing test or ticket. Lint wasn't run: `npx eslint` tried to download eslint, and the sandbox blocks the npm registry. The test run also printed wrangler errors because the sandbox blocks writing wrangler's debug log; they didn't affect the result.
