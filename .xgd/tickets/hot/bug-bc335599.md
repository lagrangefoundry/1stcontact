## Symptom

Clips made with AnimateImage are stored as Library materials of kind `video` (`VIDEO_KIND`, `apps/control-app/src/videogen.ts`), each with a poster still. In the builder's Library the client can't watch them:
- **Opening a video shows no video.** The detail pane's `preview()` (`apps/control-app/src/builder/library.js`) draws an `<img>` only for `image` and capture rows, and otherwise mounts the document reader by content type. `readerKind('video/mp4')` returns null, so nothing is shown.
- **There's no way to filter to videos.** The kind filter offers `KINDS = ['image', 'document', 'font', 'capture']`, without `video`.

So the clips the consultant made (several, in one jewellery site's case) are invisible as video exactly where a client expects to review them.

## Fix

1. **The detail pane plays the video.** For a `video` row (or any `video/*` content type), the pane shows a `<video>` with controls, `muted`, `playsinline` and `loop` for a loop/pingpong clip, using the material's file and its poster still as the poster. The poster shows until play. Download stays as for other files. A missing file shows the existing "That file is no longer in storage." message.
2. **Tiles show the poster,** so a video is recognisable in the grid, with a small play marker and the clip's duration where known.
3. **The kind filter includes `video`.**
4. **Keyboard and screen reader:** the video has the material's title as its label, and its controls are reachable from the keyboard, like the image preview's open action.

## What landed

- **The clip records how long it runs and how it plays.** When the consultant makes a clip, the clip's material ticket gets `duration_s` (seconds, as made) and `clip_mode` (`loop`, `pingpong` or `reveal`) as fields. The plugin only puts these on its result and in the human-readable body (`videogen.ts`, `SiteClipToolbox.animate_image`).
- **The Library row carries the poster, length and mode.** `MaterialRow` (`material.ts`, `rowOf`) gains `poster` (the poster still's material id), `duration_s` and `clip_mode`. All three are `null` on anything that is not a clip, and on clips made before these fields existed.
- **The row (the Library's "tile") leads with the poster.** A clip row with a poster shows the still, with a ▶ marker over it and the length beside it (`5.5 s`). For a screen reader the cell is still the row's typed image, labelled `video, 5.5 s`. A clip with no poster recorded keeps a typed 🎞 glyph labelled `video`, and a poster that fails to load falls back to that glyph.
- **The detail pane plays the clip** as described in Fix 1. The poster comes from the poster material's file. `loop` is on only for `loop`/`pingpong`; a reveal, or a clip whose mode is unknown, plays once.
- **The kind filter lists `video`**, and choosing it lists only clips.
- CSS sits beside the existing Library rules: `.builder-library__row-thumb`, `-row-poster`, `-row-play`, `-row-duration` and `.builder-library__video`. The video rule is separate from `.builder-library__image` because AC-1811's test reads that rule by its exact selector.

## Design decisions

- Duration and mode are recorded as ticket fields at creation, rather than parsed from the clip body or the attachment metadata. The Library list reads fields only, and the body is written for a person.
- Clips made before this change have neither field, so they show no length and play once. Their poster is shown, because `poster` was already recorded.

## Test plan

- `tests/test_UAT_FC_BUG-351_library_plays_a_clip.test.ts` (jsdom, installed components, faked transport):
  - A clip row shows the poster material's image with a play marker, the length, and the `video, 5.5 s` label. A clip with no poster keeps the labelled glyph.
  - Opening a pingpong clip shows a `<video>` with `controls`, muted, `playsinline`, looping, the clip's file as `src`, the poster material as `poster`, the title as its label, and the download link.
  - A reveal plays once, with no poster when none is recorded.
  - The kind filter offers `video`, and choosing it lists only the two clips.
  - A `<video>` error replaces the player with "That file is no longer in storage."
- `tests/test_UAT_FC_BUG-351_clip_row_carries_poster_and_length.workers.test.ts` (real clip plugin, D1 store and `listMaterial`; only fal is faked): a pingpong clip's row has `poster` = the poster material (an `image`), `duration_s` = the clip's duration, and `clip_mode = 'pingpong'`; a non-clip row has all three null.
- Regression: every jsdom suite that mounts the Library or reads `builder.css`, plus the clip and Library-surface workers suites. The failures are unchanged from the same suites without this change (40 jsdom tests, and AC1722/AC1724 in `reconciliation-library-surface.workers`, all pre-existing).
