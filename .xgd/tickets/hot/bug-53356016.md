# gate: an oracle that disagrees with itself in 15 places is graded as a reproduction failure, not `capture-incomplete`

Round: `repro-console:repro-www-hearingzone510-com#2` · bundle `storage/references/www.hearingzone510.com/index`
(captureSchema 15). Companion to REQ-377 issue 1, which is the capture half.

**defect_class `instrument-blind`.** *Test run:* I read `gate-core.ts:1129-1138`. `capture-incomplete` fires
only on `perceptualBreach && referenceFindings.length`, and the reference findings are coverage findings
(an impoverished manifest). This bundle's `coverage.findings` is `[]` (21/21 images referenced), so the gate
had no way to say the oracle is invalid. It returned `structural-failure` and handed the round 48 deltas
and 690 layout findings to work. Most of them are measured against a header position the page only has
mid-scroll. The gate did not report a wrong score; it graded against an oracle it never checked.

## The evidence the gate had in hand and did not read
- One element, "Learn to train your brain to hear better.", has `box.y` **1336.60** in `capture.json`.
  In `multistate.json` it is 209.1 / 401.7 / 226.7 / 245.6 / **118.6** / 206.6 at the 800-ish heights and
  141.1 / 155.7 / 113.7 / 54.6 / **12.6** / 49.6 at the taller ones. At equal width, the two heights
  disagree by up to 246px on a node the fold then gives a `viewportResponse` to (card-0 1280:
  `yFactor −0.53` = (12.6−118.6)/200).
- `screenshot.full.png` rows 0–40 are (255,255,255) at x 10/200/1270, while the manifest's band §0
  (0,0 1280×40) "paints NOTHING" (`values.nonSurfaceSections`). The bar's gradient is painted at
  y 285–325 and the `#224e7a` header at rows 325–425, inside the hero.
- `hints.json` records `position:"sticky"` on that subtree, at box y 1289.

## Proposed change
1. Have the capture record `scrollY` on every manifest it writes (REQ-377 issue 1 step 3). Have the gate
   return `capture-incomplete` when any projection, `capture.json` or a ladder screenshot was read at a
   non-zero scroll.
2. Independently of that field, add a cheap self-consistency probe for a bundle: a text run whose `box.y`
   differs between the two heights of one width by more than its own height, with no `vh` dependency
   (its x/width/height identical), is evidence of an unstable read. Report it under `coverage.findings`
   so the existing `capture-incomplete` rung fires.

## Implementation scope (free-coded, this session)

**What changes for the user.** `1c gate` (and `referenceCoverage`) gains a reference-side coverage finding,
`unstable-read`: the bundle's own `multistate.json` disagrees with itself about where a text run is. When it
fires, the gate verdict is `capture-incomplete`, ahead of every other rung (it joins BUG-189's `empty-section`
as an *oracle-invalidating* finding — breach or no breach, structural failure or pass). The finding detail
names each run (truncated text), the width, the two viewport heights and the two `y` values, and the total count.
The diagnosis says the reference was read mid-scroll / unstably, so every other gate on the run was measured
against an oracle that disagrees with itself; the next step is a capture fix and re-capture.

**The probe (proposed change step 2), as built.** Per width, take the shortest and tallest `rest` projections on
the primary engine. Pair text runs by (text, occurrence index). A pair counts only if `x`, `width` and `height`
agree within 1px AND the run's `y` in the TALLER viewport is SMALLER than in the shorter one by more than the
run's own height.

**Design decision — the direction rule.** The ticket's literal rule ("`box.y` differs by more than its own height,
x/width/height identical") is not sound: content below a `100vh` hero keeps x/width/height and moves DOWN by the
height delta (or a multiple of it) legitimately. Measured over the five committed reference bundles, the
symmetric rule fires on gigabytealchemy (328), joyfulculinarycreations (254) and faelan (18) — all healthy vh
layouts. A taller viewport never legitimately moves in-flow content UP, so the rule is one-directional: it fires
on hearingzone510 (34 runs, including "Learn to train your brain to hear better" 118.6 → 12.6 at 1280) and on
none of the other four.

**Deferred — proposed change step 1 (`scrollY` on every manifest).** Recording `scrollY` is the writer half and
belongs to REQ-377 issue 1 step 3, which also has the pipeline refuse a non-zero read — at which point a gate
check on the field would be redundant. Not built here; the step-2 probe works on bundles already on disk
(including this one) without re-capture.

## Test plan
`tests/test_UAT_FC_BUG-194_unstable_read_coverage.test.ts`, offline bundles through the real `referenceCoverage`
and `cmdGate` entry points (BUG-189's fixture shape):
- a run that moves UP in the taller viewport by more than its height → `unstable-read` finding naming run, width,
  heights and y values;
- a run that moves DOWN (vh hero) → no finding; a run whose width/height also changes → no finding;
- the finding outranks a structural failure → `capture-incomplete`, report text names `unstable-read`;
- without it, the same structural failure stays `structural-failure`.
Regression scope: BUG-189 and other gate UATs.
