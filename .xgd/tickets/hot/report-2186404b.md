REQ-205, which is in scope in BUNDLE-40, superseded both. AC-2279 and AC-2281 were already rewritten to say so (updated 2026-11-08T04:11), but their tests were not rewritten with them. The code and the ACs agree; only the tests are stale.

## Analysis
- **Failures (report-71a7d46b):**
  - `tests/test_reconciliation_outgoing_messages.test.ts:206` (AC-2279) expects `{vars: 'no-reply@1stcontact.io', 'env.production.vars': 'no-reply@1stcontact.io'}`. `apps/control-app/wrangler.toml` now carries `MAIL_FROM = "1st Contact <no-reply@1stcontact.io>"` in both sections (lines 233 and 371). The cause is the test constant `FROM_ADDRESS` at line 30.
  - `tests/test_reconciliation_outgoing_messages.workers.test.ts:255` (AC-2281) asserts `payload.text` is undefined. The adapter now sends a derived `text` part beside `html`.
- **History is from another run.** The prior fix_plan and assessment reports (report-18b12df9, report-1da9821d, report-df962c87, report-c66149a6; 2026-11-04) belong to the BUNDLE-37 reconcile, where REQ-205 was out of scope. That run correctly made mail.ts send `html` and explicitly kept `text` out. In BUNDLE-40, REQ-205 is in scope, so that run's "do not add a text part" instruction no longer applies. This is a new hypothesis, not a repeat: it changes the layer from code to stale test, and the hypothesis count is 0 for it.
- **Intent (REQ-205, request-33c49c03.md):**
  - §1: "Every message carries a plain-text alternative, derived from the HTML."
  - §3: "`MAIL_FROM` becomes `1st Contact <no-reply@1stcontact.io>`."
  - "Existing evidence this supersedes": "[[REQ-196]]'s payload assertion gains the `text` part alongside `html`, and its configuration UAT gains the display name."
  - REQ-205 is later than REQ-196 and REQ-197, which are the intents behind the stale assertions.
- **The ACs already match REQ-205:**
  - AC-2279 says the fallback is "exactly `1st Contact <no-reply@1stcontact.io>`" in both sections.
  - AC-2281 says HTML plus a non-empty derived plain-text field containing no HTML tags.
- **No blocked_by report and no mode rule is in the way.** The fix touches tests only. Production code stays as it is.
- **No isolation or contamination pattern.** Both tests fail on deterministic value mismatches.
