## Symptom

`bin/build` fails at the `Typecheck and package builds` step:

```
apps/control-app build$ tsc --noEmit
../../tools/generate/src/render/render.ts(226,60): error TS2345:
  Argument of type '{ fatal: true; }' is not assignable to parameter of type
  'TextDecoderConstructorOptions'.
  Property 'ignoreBOM' is missing in type '{ fatal: true; }' but required in
  type 'TextDecoderConstructorOptions'.
```

Nothing after `apps/control-app` in the recursive build runs, so the whole
build is red on one line.

## Root cause

`pageDrawings()` in `tools/generate/src/render/render.ts` (added by
`5ea0b90de5`, the timed-motion primitive) constructs
`new TextDecoder('utf-8', { fatal: true })`.

That compiles inside `tools/generate`'s own program, whose `lib` includes
`DOM` — `lib.dom`'s `TextDecoderOptions` has both fields optional. It does
NOT compile inside `apps/control-app`'s program, which sets
`types: ["@cloudflare/workers-types"]` and no `DOM` lib, so the only
`TextDecoder` in scope is the Workers one, whose
`TextDecoderConstructorOptions` declares **both** `fatal` and `ignoreBOM`
as required, not optional.

`apps/control-app`'s `include` is only `src/**/*.ts`, but its source imports
the render engine, so `tools/generate/src/render/render.ts` is pulled into
that program and checked under the stricter Workers types. A module in
`tools/generate` that is reachable from the Worker therefore has to satisfy
the Workers `TextDecoder` signature regardless of what its own tsconfig
permits.

## Fix

Spell both fields out at every `TextDecoder` construction that passes an
options object, matching the existing house pattern in
`apps/control-app/src/mime.ts` (`{ fatal: false, ignoreBOM: false }`).

`{ fatal: true }` and `{ fatal: true, ignoreBOM: false }` are the same
decoder — `ignoreBOM: false` is the WHATWG default, meaning a leading BOM is
consumed rather than surfaced as U+FEFF. This is a typecheck fix with no
runtime behaviour change: one unreadable drawing is still left out of the map
and the node still renders as the `<img>` it always was.

## Test plan

A source-level guard, because the failure class is a compile-time shape, not
a runtime behaviour: every `new TextDecoder(label, { … })` in first-party
source that passes an options object must name both `fatal` and `ignoreBOM`.
This catches the next instance anywhere in the repo, not just the one line
that broke this build — a bare `{ fatal: true }` written in `tools/generate`
will be red the moment the Worker's program reaches it, and the guard says so
before `bin/build` does.

Regression scope: `bin/build` reaching green through the typecheck step.
