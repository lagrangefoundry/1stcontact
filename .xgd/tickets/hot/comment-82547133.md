**What changed**
- **The describer now says what a picture is.** In the same vision call it answers `Kind: photo` or `Kind: graphic` (maps, menus, flyers, signs, logos — anything whose text matters). A photo also gets a focal point. The material stores this as a new `image_kind` field. Neither line is left in the description.
- **Backfill.** Image materials with no classification (older uploads, and copied ones like Dina's 11) get classified in two places: by `POST /api/library/backfill` (its answer now lists `classified`), and when `place_on_site` places one. Only `image_kind`, and for a photo the focal point, are written. Title and body are never touched.
- **Graphics are never cropped.** The image node has a new typed `graphic: true` flag. Design defaults give a graphic no aspect, and the renderer never crops it: no `aspect-ratio`, and `cover`/`none` is drawn as `contain`. An aspect typed on a graphic is counted as off-system.
- **The consultant is told how to place it.** `place_on_site` returns `graphic: true` for a graphic, or the photo's focal point to set as `objectPosition`.
- **A REQ-448 bug fixed on the way.** `place_on_site` was dropping the focal point before it reached the model, so the "set it as `objectPosition`" instruction never had a value to work with.
