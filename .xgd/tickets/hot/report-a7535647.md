# Sprint Review — Sprint 1

**Status**: FAIL
**Intent**: bug-5cabb340 (BUG-32 — Rebranding gap: WEBUI_SCOPE still resolves the superseded scope)
**Story**: story-e674c60a (STORY-99, upgrade, CAP-85)

## Summary

The sprint's declared delta — move component consumption to `@lagrangefoundry`, collapse the scope
to one definition site, and replace the silent-green failure mode with unconditional evidence — is
**delivered in full**, and I verified it by execution rather than by reading the quality report.
All three delta acceptance criteria (AC-960, AC-961, AC-963) carry positive, unconditional UATs
that run and pass: `vitest run tests/bug32-webui-scope-rebrand.test.ts
tests/reconciliation-builder-workspace-origin.test.ts
tests/reconciliation-builder-workspace-chrome.test.ts` → **23 passed / 0 skipped**. No `skipIf`
appears in the new suite; `WEBUI_INSTALLED` is asserted as an outcome
(`reconciliation-builder-workspace-origin.test.ts:475`), never used as a gate. The scope is written
once (`tools/generate/src/cli/webui.ts:104`), `builder.ts:72,74` compose from it, the browser
sources are renamed in place, `index.html` is deleted, and a tree-wide `git grep` confirms the
superseded literal survives in no tracked file outside the declared `.xgd/**` exclusion. Evidence
is honest: real resolver, real out-of-repo store, real generator output — nothing mocked, faked or
vendored, and the Vitest `resolve.alias` entries are derived from `webuiPackageDir`/`WEBUI_SCOPE`
rather than standing in for them.

The sprint fails on one specific, narrow point. Closing the intent required a **net-new change to
the single resolution point** — `webui.ts` replaced `createRequire(import.meta.url)` with
`createRequire(path.join(mainCheckout(walkOrigin()), 'package.json'))`, adding ~50 lines of
multi-branch `.git`-walking logic (`webui.ts:51-101`). That change is load-bearing (it is what gives
nine of this story's criteria any evidence at all inside a linked worktree), it is production code,
and **no acceptance criterion and no UAT asserts it**. Its only coverage is incidental to where the
suite happens to run. That is the same silent-green shape this sprint exists to eliminate, one level
down, so it is worth one cheap corrective story rather than being waved through.

## Gaps Identified

### Gap 1: the component-resolution anchor is net-new production code with no covering acceptance criterion

- **Intent requirement**: STORY-99's Technical Context declares the route correction explicitly —
  *"resolution is anchored at the main checkout … Nine of this story's criteria therefore lost their
  evidence in every working tree while reporting green."* The story's whole premise is that
  consumption evidence must be unconditional and environment-independent.
- **Current state**: `tools/generate/src/cli/webui.ts:70-101` introduces `mainCheckout()` and
  `walkOrigin()` — new in this sprint (`git diff main...HEAD` shows
  `-const require = createRequire(import.meta.url)` replaced by the anchored form). The function has
  four distinct outcomes: `.git` is a **directory** (main checkout → return it); `.git` is a **file**
  (linked-worktree pointer → resolve `gitdir`/`commondir`, return its parent); `commondir` **absent**
  (return the pointer's own directory); **no `.git` at all** (return the walk origin). `walkOrigin()`
  adds a fifth path for a bundler-inlined `import.meta.url`. The sprint's delta ACs are AC-960,
  AC-961 and AC-963 — none of them mentions resolution anchoring, and no test in `tests/` references
  `mainCheckout`, `commondir`, or worktree resolution as a subject.
- **Impact**: only the linked-worktree branch is exercised, and only because this worktree happens to
  be one — `AC-961` at `reconciliation-builder-workspace-origin.test.ts:421` passes here solely
  because `mainCheckout` correctly resolves `.git` →
  `/Users/martin/lagrangefoundry/1stcontact/.git/worktrees/branch-BUG-32` → commondir →
  `/Users/martin/lagrangefoundry/1stcontact`. Run the identical suite from the main checkout and
  ordinary upward resolution satisfies AC-961 **even if `mainCheckout` were entirely broken**. So the
  strongest claim the story makes about this code — that a linked worktree and the main checkout read
  the *identical* store — is asserted nowhere, and a regression in the commondir parsing would be
  caught or missed depending on which checkout CI ran in. Three of the five branches are unexecuted
  by any test.
- **Corrective action**: add one acceptance criterion and its UATs over the resolution anchor,
  asserting each `.git` shape against temporary fixture directories and asserting that the directory
  resolved from a linked worktree equals the one resolved from the main checkout. No runtime code
  change is required — the behaviour is correct as shipped and is authoritative — so this is
  **reconciliation**, not upgrade.
