## Problem

`1c deploy --sandbox` reads from the throwaway `storage/sandbox/` tree but writes
to the **same R2 keyspace as a real site**. The local store carefully separates
the two roots; the R2 layout flattens them.

`--sandbox` is honoured everywhere locally — `commands.ts:36` resolves
`root: Root = opts.sandbox ? 'sandbox' : 'sites'`, and `deploy.ts:118-123` passes
it to `cmdRender`, `readHistory`, `draftDir` and `revisionDir`. It then stops
mattering. Every R2 key is built with no root component:

| Location | Key |
|---|---|
| `tools/generate/src/deploy/manifest.ts:39` | `` `sites/${slug}/manifest.json` `` |
| `tools/generate/src/deploy/deploy.ts:131` | `` `sites/${slug}/preview/${sha}` `` |
| `tools/generate/src/deploy/deploy.ts:132` | `` `sites/${slug}/rev/${padRevision(live)}` `` |
| `tools/generate/src/deploy/deploy.ts:285` | `` client.list(`sites/${slug}/`) `` (prune) |
| `apps/public-site/src/site-store.ts:89` | `` `sites/${slug}/preview/${preview.sha}/out` `` |
| `apps/public-site/src/site-store.ts:93` | `` `sites/${slug}/rev/${padRevision(manifest.live)}/out` `` |

Found by code reading, not by execution — the destructive paths were not run
against the live bucket.

## Consequences, in order of severity

1. **A sandbox deploy can silently replace a real site's published output.**
   `1c deploy --sandbox <slug> --channel published` computes `live` from the
   *sandbox* history and uploads to `sites/<slug>/rev/NNNN/`, then sets
   `manifest.live`. Sandbox revision 1 overwrites the real site's revision 1
   bytes, and `/site/<slug>/` starts serving throwaway content.
2. **Throwaway experiments become world-readable.** With no collision at all, any
   `1c deploy --sandbox <slug>` publishes to
   `https://1stcontact.io/site/<slug>/draft/<sha>/`. `storage/sandbox/` is
   gitignored and documented as scratch space; nothing about it suggests its
   contents become publicly servable.
3. **Manifest cross-contamination.** `readManifest(client, slug)` (`deploy.ts:141`)
   reads the real site's manifest, appends the sandbox snapshot as a legitimate
   preview, and writes it back. No entry is lost, but the real site's manifest now
   references sandbox content.
4. **`--prune` enumerates the wrong site.** `deploy.ts:285` lists the shared
   `sites/<slug>/` prefix, so a sandbox prune walks the real site's keys.

Latent today: no sandbox site currently shares a slug with a real one, and no
`--sandbox` deploy has been run. The failure mode is silent when it does happen.

## Root cause

The R2 key layout omits the root that every other layer preserves. [[DOC-12]] §3.1
makes the two roots a stated invariant, and `distDir(ctx, slug, channel)` already
namespaces rendered output as `storage/dist/<root>/<slug>/<channel>/`.

The R2 mapping specified in [[REQ-110]] had no root component either, so the
implementation is faithful to a spec that was wrong. [[DOC-12]] §7 inherited the
same omission and needs the same correction.

## Fix

**Invariant to restore: sandbox content is never publicly servable, and sandbox
keys never collide with real ones.**

- Namespace every R2 key by root: `sites/<slug>/…` and `sandbox/<slug>/…`.
  Thread `root` through `manifestKey`, the snapshot prefix, and the prune listing.
- `SiteStore` in the Worker resolves **only** `sites/`. There is no route that can
  reach a `sandbox/` key.
- Correct the [[DOC-12]] §7 mapping table to show the root in the key layout.

**Resolved: option (b) — namespace, do not refuse.** The `Fix` bullets above and
every acceptance criterion below describe a namespaced sandbox root, so that is
what landed. It also keeps `--sandbox` uniform across every command rather than
adding a one-command refusal, which is the simpler shape once the root is
threaded (~20 lines). Refusing outright (option (a)) remains a small follow-on if
the sandbox root proves to be dead weight.

Neither option lets sandbox exercise the *serving* path — that still needs a
throwaway slug under `storage/sites/` (`harbor-cafe` already has a published
revision and is fictional). The CLI help now says so.

## What changed

- `manifestKey(root, slug)`, `readManifest(client, root, slug)` and
  `writeManifest(client, root, slug, …)` take the root; `cmdDeploy` passes
  `ctx.root`. The snapshot prefix and the `--prune` listing are built from it too.
- `DeployResult` gains `root`, and `url` becomes `string | null`: a sandbox
  deploy uploads and indexes normally but reports **no URL**, because nothing can
  serve it. `formatDeployReport` prints the prefix and
  `(sandbox — not publicly reachable)` in its place.
- The Worker's servable root is now the named constant `SERVABLE_ROOT = 'sites'`.
  No root is ever derived from a request, so a sandbox key is unreachable **by
  construction** rather than by a check that could be missed.
- CLI help for `1c deploy` documents the sandbox root and points at the throwaway-
  slug workaround for exercising serving.
- [[DOC-12]] §7's mapping table now shows `<root>` in the key layout, with a note
  that only `sites/` is servable.

## Acceptance

All five UATs live in `tests/bug31-sandbox-r2-namespace.test.ts` and drive the
real `cmdDeploy` and the Worker's real `fetch` entry point, with R2 faked only at
the upload boundary and the binding:

- `test_UAT_FC_BUG-31_sandbox_keys_are_namespaced` — a sandbox deploy writes no
  key under `sites/`; the bytes land under `sandbox/`; `url` is null and the
  report says the snapshot is not publicly reachable.
- `test_UAT_FC_BUG-31_sandbox_cannot_overwrite_real_published` — a real and a
  sandbox site share a slug and both publish revision 1; `--sandbox --channel
  published` leaves the real site's `manifest.live`, its `rev/0001/` bytes, and
  what `/site/<slug>/` serves entirely unchanged.
- `test_UAT_FC_BUG-31_sandbox_manifest_is_separate` — a sandbox deploy leaves the
  real manifest byte-identical, and each root indexes only its own preview.
- `test_UAT_FC_BUG-31_worker_never_serves_sandbox` — a slug deployed only to
  sandbox 404s on every route the grammar admits, including a path that names the
  sandbox key itself.
- `test_UAT_FC_BUG-31_prune_scoped_to_root` — with an orphan in each root, a
  sandbox prune deletes only the sandbox orphan and leaves the real one in place.

Regression scope run green: the five new UATs plus `req110-r2-deploy`,
`req111-public-site-serving`, `req113-worker-extensionless-urls`,
`deploy-workflow`, `public-site`, `control-app` (28 tests). `tsc --noEmit` clean
for `tools/generate` and `apps/public-site`.
