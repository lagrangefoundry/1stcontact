## What the user sees

On xgd.dev, moving the mouse across a band that paints the brown hairline grid
lights the grid lines **teal-petrol** inside a rough, roughly-circular region
~150–200px across, centred on the cursor. The region is **stable while the
pointer is still** and its **edges deform/flutter as the pointer moves** — the
"leaves appearing on the digital trees" effect from sycamore.so.

Nothing else changes: the surface fill, the brown grid, spacing and thickness are
untouched, and the accent never paints on a page with no pointer.

## Why free-coded

One typed L1 axis plus a small renderer-owned script, following the shape REQ-100
(scroll reveal) already established. No design document needed.

## Design

**This is an L1 capability, not a behavior module.** It is pure presentation with
no user-facing behaviour and no instance data in JS — exactly REQ-100's case: a
typed value bag the renderer alone knows how to compile, plus one vetted script
identical for every site.

1. **Schema** — `l1PatternSchema` gains a strict, bounded optional sub-object:
   `pointerAccent: { color, radiusPx, blobs?, softnessPx? }`. `color` goes through
   `l1Color`; the numbers are envelope-bounded. It nests inside `pattern` because
   the accent *redraws the same texture in a second colour* — it is meaningless
   without one.

2. **Renderer** — when a node's pattern carries `pointerAccent`, emit an `::after`
   overlay on that node (inset 0, `pointer-events: none`, non-authorable
   selector) carrying the *same* pattern layers in the accent colour, masked by a
   union of N radial blobs whose centres are CSS custom properties. The overlay is
   gated on a `data-l1-pointer` attribute the script alone sets, so:
   - no JS / no pointer / reduced motion / coarse pointer → the attribute is
     absent, the rule never matches, the band paints exactly as it does today;
   - the captured (headless, pointerless) page is unchanged, so the L1 round-trip
     gate is unaffected.

3. **Roughness and flutter, without randomness** — N blobs sit at fixed angular
   offsets around the cursor, so their union is a *lumpy* region rather than a
   neat circle, and that shape is deterministic and stable at rest. Each blob
   **lags the cursor with its own spring constant**, so while the pointer moves
   the blobs spread and the boundary deforms; when it stops they converge to the
   stable rough shape. The rAF loop runs only while blobs are still settling.

4. **Script** — one `L1_POINTER_SCRIPT`, emitted only when the document actually
   uses the axis, carrying no instance data. Declines (returning before setting
   the marker) on `prefers-reduced-motion: reduce`, on a non-hover/coarse pointer,
   or when the required APIs are missing.

5. **Site edit** — set `pointerAccent` on `#problem` and `#close` in
   `storage/sites/xgd/draft/pages/home.json`: teal-petrol `#2e86a3`, radius ~90px
   (~180px diameter).

## Explicitly out of scope

The **hero** band's grid is an SVG asset (`xgd-grid-hero.svg`), not the `pattern`
axis, so this axis does not reach it. Extending the accent to an asset-drawn
texture (using the SVG as an alpha mask over the accent colour) is a follow-on
decision, not part of this ticket.

## Test plan

New UATs in `tests/req108-l1-pointer-accent.test.ts`, named
`test_UAT_FC_REQ-108_*`:

- a pattern carrying `pointerAccent` renders an overlay drawing the same grid
  geometry in the accent colour, masked to a pointer-positioned region;
- the overlay is gated on the script-set marker, so a document with the axis and
  no script renders byte-identically to one without it (fail-visible);
- reduced motion leaves the accent inert;
- the script is emitted only when the axis is used;
- the envelope rejects out-of-range / freeform / non-colour input on the new axis;
- a document that declares no `pointerAccent` renders exactly as before.

Regression scope: `tests/req103-l1-texture.test.ts`, `tests/req100-*`, plus the
L1 round-trip / render suites.
