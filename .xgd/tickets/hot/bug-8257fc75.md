## Found in review of REQ-415 / REQ-416 before the next test run (2026-10-20)

Four defects, all in the build-sooner / visual-check path the next run depends on.

1. **Stage tracker contradicts the new method (REQ-416).** `set_stage` marks any
   other in-progress stage done when a later one starts (`plan-core.ts` ~2062).
   Under build-sooner, starting the first draft marks "Getting to know you" done
   — and shows "Looking at other sites" as skipped — just as the talker's
   interview begins. Fix: "Getting to know you" stays in progress while a later
   build stage starts (two stages may be in progress; REQ-398's banner shows the
   furthest one expanded and the other in its in-progress colour). More
   generally, starting a stage never marks an earlier one done; only an explicit
   done does. The REQ-398 skipped rule is unchanged (an in-progress stage is
   never skipped).
2. **Stop building can be overridden by a layout continuation (REQ-415 × REQ-409).**
   In `continuedTurn` (`host-core.ts` ~4404) the `unfinished` check skips only
   `exhausted` and `error`. A round the client stopped, with layout faults owed,
   starts a layout continuation anyway. A stopped round must never continue, by
   either path. Also: a Stop pressed between continuation rounds (before the next
   round polls) must stop the next round, not be discarded.
3. **The clean-check line says the opposite of the truth (REQ-415).** When the
   layout check finds nothing, the report says "The check finds faults; …"
   (`host-core.ts` ~1500). It should say the check found no layout faults, and
   that whether the page is what the client asked for is what the picture is for.
4. **No browser means the final stages can never close (REQ-415).** `unlooked` is
   wired whenever a plan exists, but looks can only be recorded with a browser.
   Without one, the `NOT_LOOKED` refusal must not apply (and the plan notice
   should not list pages as unlooked); say instead that pages couldn't be looked
   at.

Also:
5. **Opening message (REQ-403 stock text) still says** "That's the usual order"
   for the stages. Under build-sooner it should say that a first draft comes
   early and getting to know the business carries on while it's built.
6. **Withhold UAT is partly hard-coded (REQ-416).** Make it derive from each
   granted tool's declared `effect`: any tool that writes the site or a stage
   must be withheld, so a new site-writing tool can't silently reach the talker.
7. Comments in `chat.js` (~1058, ~1090) call the consultant "she"; DOC-66 says
   "the consultant" / "it".

## Test plan
- Starting `first_draft` while `getting_to_know_you` is in progress leaves both in
  progress; the banner shows neither as done or skipped.
- A stopped round with owed layout faults ends; no continuation round runs. A stop
  recorded between rounds prevents the next round.
- A clean layout check's report contains no "finds faults" claim.
- With no browser binding, `set_stage` to ready_to_publish is not refused for
  unlooked pages.
- The opening text no longer says "the usual order" and describes building early.
- The talker-withhold UAT fails when a tool with a site-writing effect is added to
  the allow list.
