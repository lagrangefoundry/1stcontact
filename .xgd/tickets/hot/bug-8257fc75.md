## Found in review of REQ-415 / REQ-416 before the next test run (2026-10-20)

Four defects, all in the build-sooner / visual-check path the next run depends on.

1. **Stage tracker contradicts the new method (REQ-416).** `set_stage` marks any
   other in-progress stage done when a later one starts (`plan-core.ts` ~2062).
   Under build-sooner, starting the first draft marks "Getting to know you" done
   — and shows "Looking at other sites" as skipped — just as the talker's
   interview begins. Fix: "Getting to know you" stays in progress while a later
   build stage starts (two stages may be in progress; REQ-398's banner shows the
   furthest one expanded and the other in its in-progress colour). More
   generally, starting a stage never marks an earlier one done; only an explicit
   done does. The REQ-398 skipped rule is unchanged (an in-progress stage is
   never skipped).
2. **Stop building can be overridden by a layout continuation (REQ-415 × REQ-409).**
   In `continuedTurn` (`host-core.ts` ~4404) the `unfinished` check skips only
   `exhausted` and `error`. A round the client stopped, with layout faults owed,
   starts a layout continuation anyway. A stopped round must never continue, by
   either path. Also: a Stop pressed between continuation rounds (before the next
   round polls) must stop the next round, not be discarded.
3. **The clean-check line says the opposite of the truth (REQ-415).** When the
   layout check finds nothing, the report says "The check finds faults; …"
   (`host-core.ts` ~1500). It should say the check found no layout faults, and
   that whether the page is what the client asked for is what the picture is for.
4. **No browser means the final stages can never close (REQ-415).** `unlooked` is
   wired whenever a plan exists, but looks can only be recorded with a browser.
   Without one, the `NOT_LOOKED` refusal must not apply (and the plan notice
   should not list pages as unlooked); say instead that pages couldn't be looked
   at.

Also:
5. **Opening message (REQ-403 stock text) still says** "That's the usual order"
   for the stages. Under build-sooner it should say that a first draft comes
   early and getting to know the business carries on while it's built.
6. **Withhold UAT is partly hard-coded (REQ-416).** Make it derive from each
   granted tool's declared `effect`: any tool that writes the site or a stage
   must be withheld, so a new site-writing tool can't silently reach the talker.
7. Comments in `chat.js` (~1058, ~1090) call the consultant "she"; DOC-66 says
   "the consultant" / "it".

## Test plan
- Starting `first_draft` while `getting_to_know_you` is in progress leaves both in
  progress; the banner shows neither as done or skipped.
- A stopped round with owed layout faults ends; no continuation round runs. A stop
  recorded between rounds prevents the next round.
- A clean layout check's report contains no "finds faults" claim.
- With no browser binding, `set_stage` to ready_to_publish is not refused for
  unlooked pages.
- The opening text no longer says "the usual order" and describes building early.
- The talker-withhold UAT fails when a tool with a site-writing effect is added to
  the allow list.

## What changed (as implemented)

1. **Stages.** `set_stage` changes the named stage only — starting a stage never
   ticks, resets or otherwise moves any other stage, forward or backward. Several
   stages may be in progress at once; `checkPlan` no longer refuses that, and the
   result no longer carries `moved_from`/`marked`. Only an explicit `done` ticks a
   stage. `currentStage` returns the furthest stage in progress. The client's
   banner names (label, `aria-current`, spinner) only the furthest in-progress
   stage; any other in-progress stage keeps its in-progress colour without a
   label. The skipped rule is unchanged. The plan surface's `set_stage` and
   overview text say so.
2. **Stop.** A round that ended `aborted` (the client's Stop) is never continued,
   neither by REQ-409's budget continuation nor by REQ-415's layout continuation.
   Before any continuation round starts, the host takes the session's pending
   Stops; a build Stop (not one naming a talker reply) pressed since the client's
   message began ends the request instead of starting the round. The talker desk
   of a continuation round also counts Stops from the client's message start, not
   its own round start, so a Stop between rounds is never discarded.
3. **Clean check line.** A builder result with no layout faults ends "The layout
   check found no layout faults. Whether the page is what your client asked for
   is what the picture is for."
4. **No browser.** The plan surface's `unlooked` (and so the `NOT_LOOKED`
   refusal) and the plan entry's unlooked list are wired only where the
   consultant has a browser to record looks with. Without one, near publishing,
   the plan entry says instead: "The pages couldn't be looked at: this deployment
   has no browser to take screenshots with. Don't tell your client the pages have
   been checked by eye."
5. **Opening message** now says: "I'll build a first draft early, so you have
   something real to react to, and we'll carry on getting to know your business
   while it's built. We can move around freely — just tell me what you'd like to
   look at."
6. **Withhold UAT** (REQ-416) derives the tools that must be withheld from the
   surface declarations: every `write` on a surface that holds the site (L1,
   image, library, fidelity, DNS, settings), plus the two plan writes that reach
   past the plan (`set_stage`, `choose_look`). Plan and ledger writes (story
   board, asks, record) remain the talker's.
7. `chat.js` comments say "it" for the consultant.

## Design decisions made during implementation

- **Explicit supersession of BUG-221 / REQ-390's marker move.** BUG-221 made
  starting a later stage tick the one moved off and starting an earlier one reset
  the later to not started. Both are removed, not only the forward tick: under
  build-sooner, reopening an earlier stage (e.g. back to Getting to know you)
  while the first draft is in progress must not reset the draft either. BUG-221's
  two marker-move UATs are deleted; REQ-390's any-order UAT is updated to expect
  two stages in progress. BUG-221's passed-over plan-entry UAT is unchanged.
- **"Effect" alone cannot classify the talker's tools**: plan-surface writes such
  as `pin_notes` are allowed to the talker. The derivation therefore keys on the
  surface a write is declared on, naming only the two plan writes that reach the
  site or the stage. Framework-declared tools (Delegate, CreateImage, …) are still
  classified by the either-list check.
- A stopped round is recognised by the framework's terminal `status: 'aborted'`
  (a clock- or call-exhausted round ends `complete` with `exhausted: true`, so it
  is unaffected).
