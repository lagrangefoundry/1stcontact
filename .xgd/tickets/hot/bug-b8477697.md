## Symptom

Every recapture of **faelan.com** and **joyfulculinarycreations.com** has failed since [[BUG-161]] landed (2026-09-29 18:39). The repro console reports:

```
Iteration N failed at gate.
gate failed (exit 1):
offset is out of bounds
```

Capture, refold, render, the values diff and the region crops all complete (their files are in `iteration-N/diff/`). Only `regions.json` and `gate.json` are missing, so the iteration has no verdict. gigabytealchemy.ai passes because none of its image boxes has a fractional size.

Faelan's last successful gate was 2026-09-29 17:56, 43 minutes before BUG-161 landed.

## Root cause

BUG-161 (issue 3) added `unpaintedImages` (`tools/generate/src/cli/perceptual-core.ts:795`). For each element or section that carries an image, it takes the reference manifest's box through `toRegionBox` (`:387`), which **rounds to two decimals rather than to whole pixels**, and then calls `cropVariance` → `extractRect` (`:589`).

`extractRect` assumes integer `w`/`h`. Given `h = 205.7`:

- `new Uint8Array(w * h * c)` truncates its length to `floor(w·205.7·c)`
- the row loop runs `row = 0 … 205`, and the last `out.set(…, 205·w·c)` writes a full row past the end

`Uint8Array.set` throws `RangeError: offset is out of bounds`, and the whole gate dies.

Reproduced offline on both failed iterations with their own files (`faelan iteration-6`, `joyful iteration-5`): same throw, same frame, `extractRect ← cropVariance ← consider ← unpaintedImages`. The fractional boxes are real capture geometry:

- faelan element 5, height 205.70
- joyful elements 5, 47, 48, 49, 53 and 54, and section 4 (e.g. 66.28, 182.77, 2667.52)

Harness: `.xgd/tmp/unpaint-repro.mjs`.

## Fix

1. **`extractRect` accepts any finite box.** It snaps the box to whole pixels before allocating, keeping its existing clamp-not-throw contract: its doc comment already says an over-reaching box is clamped rather than failing the run, and a fractional one is the same class of input. The snap covers the edges (floor the start, ceil the end), so the crop covers every pixel the box touches. `extractRect` has four callers (`perceptual.ts:142` crop, `aligned-crops.ts:177`, `regionReadout` `:669`, `cropVariance` `:762`), and fixing it here protects all of them rather than only the one that tripped.
2. **A degenerate box costs only that box.** A box with a non-finite or non-positive size is skipped by `unpaintedImages`, never thrown. One bad record must not take down the gate, the same rule [[BUG-125]] applied to stored outcomes.

## Test plan

`tests/test_UAT_FC_BUG-<n>_fractional_image_box.test.ts`:

- `extractRect` with a fractional box (e.g. `h = 205.7`) returns a raster whose `data.length === width · height · channels`, with integer dimensions covering the box. Before the fix it throws.
- `unpaintedImages` over a synthetic source with a fractional-size image box returns a result rather than throwing.
- An existing whole-pixel crop is byte-identical before and after (the regression guard for the four callers).
- The real faelan bundle, main checkout only (bundles are gitignored): `1c gate repro-faelan-com --ref storage/references/faelan.com/index` writes `gate.json`.
