## Summary
REQ-157 (request-3f8737f2) AC6 says: "`capture_site` is refused for private address space, over-large responses and redirect loops; each refusal is journalled with the URL". Design section 6 and the Safety section say the guard applies on **both** hosts. STORY-159 (story-31204812) aligned its ACs to the code as landed (fix_plan iteration 6, code_frozen). The code is narrower than that intent in the ways listed below. Reconciliation review report-9ddac478 (BUNDLE-32, G1) asked for this to be filed.

## Gaps
1. **Over-large response is not refused.** On the Worker, once responses together exceed 32 MiB the egress guard trips (`response-cap`) and later requests are answered 403. But `capture_site` (`tools/generate/src/cli/ai/fidelity-core.ts`, `capture_site`) never checks `guard.tripped`. It returns a successful named reference with the trip listed only in `refusals`. (AC-2050)
2. **Redirect loop is not refused, and the cap counts the wrong thing.** The redirect cap counts every distinct origin the page touches, subresources included, not redirect hops (`egress-guard.ts`). An ordinary page with a font host, a CDN and analytics can trip it. When it trips, the capture still succeeds and returns a reference, with `redirect-cap` listed in `refusals`. (AC-2049; out-of-window BUG-127 touches the counting.)
3. **Node host has no byte cap, no loop detection and no redirect-hop guard.** `guardedPlaywrightDriver` checks only requests that `page.route` sees. Playwright does not route redirect hops, so a public URL that redirects into private or link-local space is followed unchecked (SSRF). The Playwright driver never calls `guard.record(bytes)`, so Node captures are unbounded in size. The redirect cap is only exercised on the Worker. (AC-2048, AC-2050)
4. **The 60 s time cap is declared but never applied.** `MAX_CAPTURE_MS = 60_000` (`egress-guard.ts:72`) is documented as "passed to the session lease", but nothing passes it anywhere.

Related, found while adding the AC-2051 assertion in reconciliation:
5. **Mid-capture refusals are not journalled with their URL.** The Toolbox audit record for a `capture_site` call carries `params.url` (the typed address) and an outcome. A request refused at the driver seam during an otherwise successful capture appears only in the result's `refusals`, which the model sees. The audit record has `outcome.ok: true` and `outcome.summary: null`, because `capture_site`'s `returns` declares no `summary` projection. So the refused URL never reaches the journal. Only pre-flight (typed-address) refusals are journalled as refusals today.

## Required behaviour (REQ-157 AC6)
- On **both** hosts, a capture that exceeds the response-size cap, or that is caught in a redirect loop (counted as redirect hops of the navigation, not subresource origins), is **refused**. That means it returns the surface's declared `REFUSED` error and offers no reference.
- On Node, redirect hops are checked by the same address rule as on the Worker. Either intercept hops, or disable automatic redirects and follow them under the guard.
- The declared time cap is applied to the capture on both hosts.
- **Each refusal is journalled with the URL.** That covers the typed address, every request refused at a driver seam, and every cap trip. The minimum is a declared `summary` projection of `refusals[].url` / `reason` on `capture_site`, or an equivalent audit field.

## Acceptance
- UATs in `tests/test_reconciliation_capture_site_egress.test.ts` drive each case on both hosts (`workerHost`, `nodeHost`). They assert a `REFUSED` answer with no new entry in `list_references` for size and loop trips. They also assert the audit record carries each refused URL.
- STORY-159 ACs AC-2048, AC-2049, AC-2050 and AC-2051 are restored to the refusal wording once this lands.

## Decisions (2026-10-31, operator-agreed scope for the free-coded fix)
Re-checked against the code as of this date. Gaps 1 and 2 were overtaken by later work; gaps 3–5 stand.

- **Gap 1 (size cap) — dropped; superseded by BUG-172.** BUG-172 deliberately removed the 32 MiB whole-capture byte cap because it refused ordinary photo-heavy sites (each ladder width reloads the page). BUG-172 is the later intent, so "over-large responses" in REQ-157 AC6 is superseded. The `capture_site` description in `fidelity-surface.json` stops claiming that "an enormous one is not brought back".
- **Gap 2 (redirect loop) — already met by BUG-127.** The cap counts hops along one navigation chain (`MAX_REDIRECTS = 5`), not origins, and a page whose own document is refused (including by the redirect cap) answers `REFUSED` with no new reference. This fix makes the same behaviour hold on the Node host (gap 3), where the hop depth was previously always 0.
- **Gap 3 (Node redirect hops) — fixed.** Verified empirically: Playwright's `page.route` handler is only called for the first URL of a redirect chain; later hops go straight to the network unchecked. The guarded Playwright driver now intercepts with Chromium's CDP `Fetch` domain instead, which pauses on every hop (`redirectedRequestId`, stable `networkId`). Every hop is checked by the same address rule as the Worker, with its depth counted per chain, so:
  - a public URL that redirects into private / link-local space is refused before the hop is fetched, and the capture answers `REFUSED`, offering no reference;
  - a redirect chain longer than `MAX_REDIRECTS` on Node is refused as a redirect loop and answers `REFUSED`.
  A guarded driver on a non-Chromium engine refuses to run (fails closed) rather than capturing unguarded.
- **Gap 4 (time cap) — applied per page load.** `MAX_CAPTURE_MS` (60 s) is applied as the ceiling on each page load (navigation timeout) in the guarded capture on both hosts, rather than on the whole multi-width capture, which could legitimately exceed it. A load that exceeds it fails the capture with a message naming the cap.
- **Gap 5 (journalling) — fixed.** `capture_site` declares a `summary` projection, so the audit record for each call carries the refusal summary: total refused, count per reason, and up to five examples with URL (shortened) and reason. That's the same summary the model sees (REQ-361). Pre-flight (typed-address) and in-capture document refusals keep journalling through the `REFUSED` error, which names the URL.

## As implemented (2026-10-31)
- **A refused capture is never stored.** A technical consequence of "offers no reference": `cmdCapturePage` takes a `verdict` hook. `capture_site` passes one that throws `REFUSED` if any main-frame document was refused. It is asked after the first pass, so a refused page does not spend the rest of the ladder, and again after the last pass, before anything is written. All bundle writes now happen after the final verdict. So a refused capture does not appear in `list_references` and does not replace an earlier good capture of the same address.
- **Node interception.** The guarded Playwright driver uses a CDP session with `Fetch.enable` (Request stage), not `page.route`. Hop depth is the depth of `redirectedRequestId` + 1. `kind` is `document` only for the main frame's Document. A refused request is fulfilled `403 refused by egress policy`. A guarded browser also launches with site isolation off (`--disable-features=IsolateOrigins,site-per-process`), so cross-origin iframes stay in the page's process where the interception sees them, and blocks service workers. A guarded driver on a non-Chromium engine throws instead of capturing.
- **Page-load ceiling.** `EgressGuard.pageLoadMs` (default `MAX_CAPTURE_MS` = 60 000, overridable via `egressGuard({ pageLoadMs })`). The Worker driver uses it as its default navigation timeout when guarded. The Node driver passes it to `goto`, and on timeout fails with "the page did not load within N s, the ceiling on one page load in a capture: <url>".
- **Audit summary.** `capture_site` `returns.summary` (access `navigated`) lifts `bundle`, `url`, `refused_total` (= `refusals.total`) and a `refused` list of `{url, reason}`. The framework's projection cannot index into `refusals.examples`, so the same examples ride on the result as a non-enumerable `refused` property. The audit projection reads it, but the serialised result the model sees does not include it (no token cost, REQ-361).
- **Surface text.** The `capture_site` description, the `REFUSED` error message and the private-address absence note no longer claim an enormous page is refused. The description now says a public page's redirect into private space is refused and a page taking over a minute to load is given up.
