## Story
**As a** site reproducer using the L1 pipeline, **I want** an end-to-end acceptance
gate that decides whether a reproduced site definition is good enough — checking that
it matches the captured original at the sampled widths, stays laid-out-sanely at
widths that were never sampled, and survives changes to its content — and that
repairs structure only where the checks fail, **so that** a clean verdict is a
trustworthy sign the reproduction is both faithful and robust, and each failure points
me at the specific framework gap to fix rather than a per-site patch.

## Description
This story documents the reproduction **acceptance boundary** that ties the L1
pipeline (capture → fold → render) together behind three probes and a demand-driven
structure-recovery step.

A browser-free, deterministic layout evaluator resolves every leaf's box at a given
width — mirroring the renderer's per-viewport `interpolate|snap` geometry and CSS
flow stacking, and estimating a text run's natural height so content growth is
expressible — and reports envelope violations (sibling overlap, horizontal clip
beyond the viewport, and pinned-box content overflow).

The evaluator mirrors the renderer on three axes that the naive model got wrong:

- **Flow direction.** A row container tiles its children along the main axis: each
  child takes its own width (a declared fixed width, else an equal share of the
  gap-aware leftover extent), the cursor advances by that width, and the row's height
  is its tallest child. A stack/box container stacks children vertically at full
  width; grid is modelled conservatively as a stack. Without the row branch every
  child took the full parent width and rows false-flagged overflow.
- **Breakpoint intervals.** A geometry track resolves a width against **half-open**
  per-segment intervals `[a.at, b.at)`, mirroring the renderer's stacked `min-width`
  rules where the highest breakpoint ≤ width wins. At an exact interior breakpoint the
  segment *starting* there is active, not the one ending there — a `snap` segment
  ending at a captured breakpoint no longer returns the held pre-reflow keyframe and
  cascade stale geometry down the rest of the page.
- **Responsive type axes.** A numeric type axis (font size, line height, letter
  spacing) that varies across the ladder is carried as a per-width track, and the
  evaluator resolves it by the *same* half-open cascade as geometry. An expectation
  projected from a reproduced document is therefore per-viewport: a heading that folds
  36px at 320 and 72px at 1440 is expected at 36 on mobile. Resolving only the
  document's flat axis expected desktop type at every width and reported a phantom
  delta on a correct responsive reproduction.

On top of the evaluator sit three acceptance probes and their combined gate:

- **sample-fidelity** — the reproduced document's leaf boxes match the retained
  capture oracle at each captured width, within tolerance. The oracle is the capture's
  **width ladder**: the first projection at a `(width, state)` key defines that width's
  samples, and a later projection at the same key — a height probe re-shooting a ladder
  width at a second viewport height — is *evidence* and contributes none. Admitting a
  probe as a second ladder cell hands the measure a second full set of oracle rows
  whose reproduced-leaf queues are already drained, and every text run on the page
  surfaces as a coverage gap on a reproduction that has not changed.
  Correspondence is established by **stable occurrence identity**: text leaves pair
  within a normalized-text key (the k-th oracle sample carrying a given text pairs with
  the k-th reproduced run carrying that text, both sides in document order); image and
  box leaves — which carry no text — pair by the same document-order occurrence
  mechanism keyed by leaf **kind**. The oracle is projected through the fold's own
  element classifier, so a sample exists exactly where the fold emits a leaf and
  controls / empty runs are excluded from the measure. Repeated labels/CTAs therefore
  each compare against their own box (no phantom deltas at sampled widths); an oracle
  occurrence with no remaining reproduced leaf surfaces as an unmatched coverage gap
  rather than being masked by an already-consumed box; and drift on one occurrence of
  a repeated key is still attributed to that occurrence.
- **off-sample** — the layout envelope holds (no overlap / clip) at intermediate
  widths the capture never sampled.
- **content-robustness** — the envelope holds when content is perturbed (text runs
  grown, pinned heights grown).

A **painted backing surface** (a card/section/panel fill folded as a childless `box`
leaf behind the content it backs) is excluded from the sibling-overlap check — a
background sitting under its own content is by design, not a collision — while
remaining subject to the horizontal-clip check.

**What the gate is not the instrument for, it says out loud.** A page is L1 layout
plus the behaviours mounted into its slots, so part of a reproduction's text is
rendered by a behavior module rather than emitted by L1. Oracle text with no reproduced
leaf to pair with, sitting inside a behaviour slot's evaluated rect, is **set aside and
counted** — a third reporting class beside residuals and unmatched, surfaced on the
gate's sample-fidelity line. Grading it fails a correct reproduction; dropping it
quietly turns every mounted region into an ungraded hole nobody can see.

The gate runs all three probes on an **absolute-base / structure-overlay split**:
fidelity is measured on the absolute base (which reproduces the oracle exactly), while
the envelope probes are measured on a structure-recovered overlay. **Demand-driven
recovery** is region-aware and recursive: at each node the direct pinned children that
collide under perturbation are grouped into connected components of the
perturbed-overlap graph, and each component becomes its own flow stack container with
its own interior gap derived from the absolute measurements. A node that needs recovery
flows **all** of its children — regions as sub-stacks, survivors as flowed items — so
no pinned sibling is left behind for a grown region to overrun. A node with no
colliding group stays fully absolute. This is what makes the envelope probes hold on a
real multi-region page (hero / grid / footer); single-level promotion of one flat pile
kept one median gap for the whole page and left the probes failing at every width.

Beyond the probe reports, the combined gate carries the **fold's residuals** — the
elements the folder cannot yet express as L1 leaves — as a channel distinct from the
fidelity probe's residuals and unmatched entries, so a folder-power gap is legible as
a framework gap rather than mistaken for mispairing.

The fidelity verdict rests on an **idempotence identity**: the analytic value-render
of the absolute-base fold is deterministic (re-evaluating the same document at the
same width is identity) and per-occurrence faithful (N elements sharing a text at a
width yield N distinct reproduced runs, each matching its own oracle box) — i.e.
`value-render(value-render(X)) == value-render(X)`. Without it a clean fidelity
report would be unfalsifiable.

**In scope**: the analytic evaluator's flow model (row tiling, stack stacking,
conservative grid), its breakpoint-interval semantics and its per-viewport resolution
of responsive type-axis tracks; its envelope findings and the backing-surface
exception; the three probes and their report shapes, including the sample-fidelity
pairing contract for text and non-text leaves, the ladder-vs-evidence partition over
repeated projections, and the set-aside-and-counted class for oracle text a mounted
behaviour covers; the combined gate over the absolute-base/overlay split and its
separate fold-residual channel; region-aware recursive promotion of failing pinned
groups to flow.

**Out of scope**: the browser-backed `capture(render(L1)) ≈ L1` round-trip check
(the round-trip spine, separate — this story owns only the evaluator the expectation
is projected through); the fold itself, including which responsive tracks it emits and
which residuals it emits (CAP-71); the L1 track/axis vocabulary and the renderer's own
media-query emission (CAP-70); binding behaviour modules into L1 slots and what a
mounted module renders (page composition / CAP-72); running the gate on any particular
real site.

## Technical Context
- Depends on the L1 substrate + safe renderer/validator (CAP-70, plan item 1) and
  the capture→L1 fold + retained oracle (CAP-71, plan item 2).
- The evaluator is deliberately **analytic (browser-free)** so every probe is an
  always-run, deterministic piece of evidence rather than a cross-engine skip; it
  sits on top of, and does not replace, the browser-backed round-trip spine.
- **The row width model is an analytic stand-in, not a flex implementation.** Equal
  shares of the leftover extent stand in for flex-grow / natural content width — the
  probe only needs the *behaviour* (does a well-formed row tile without overlap or
  overflow?). Grid is modelled as a stack for the same reason: envelope-conservative,
  and the folder does not emit grid yet. Both are deliberate approximations of the
  renderer, not claims of fidelity to it.
- **Half-open interval resolution mirrors the renderer's cascade, and is the only
  correct reading of it.** The earlier closed upper bound was diagnosed as an
  *evaluator* defect, not a fold defect: capture and fold were always emitting a
  keyframe at the reflow breakpoint. No fold change was required to close it. The
  responsive type-axis track reuses that same resolution rule rather than a second
  one, so the two cannot drift apart.
- **The ladder/evidence partition is one rule shared by every ladder consumer.** A
  projection key is `(engine, width, state)` — deliberately height-free, because a
  *responsive* comparison is not about viewport height — so a same-width height probe
  is exactly a projection whose key is already claimed. The gate's oracle applies the
  rule structurally on `(width, state)` (it carries no engine and re-folds for one
  engine anyway); the appearance scoreboard applies the engine-keyed form. Diagnosed
  from a page-wide false failure: 55 phantom unmatched on an unchanged reproduction.
- **The mounted set-aside is a reporting class, not a suppression.** Only oracle text
  that has no reproduced leaf *and* falls inside a slot rect is set aside; anything
  unpairable elsewhere is still an unmatched coverage gap. The count is surfaced on
  the gate line precisely so the ungraded region has a visible size — the same
  blind-spot shape the gate-calibration work (REQ-94) exists to close.
- **Fidelity cost knowingly accepted upstream.** Lifting the reference's own submit
  chip into a form's slot drops its page-absolute keyframes (they would resolve
  against the slot's origin), so that control's exact per-width position becomes
  flow-approximate. That trade belongs to page composition, not to this gate; the
  gate's obligation is only to report the region as set aside rather than fail it.
- Demand-driven promotion returns a **validated** L1 document — a recovery that would
  produce an invalid document is rejected rather than returned, preserving the CAP-70
  safety envelope.
- `promoted` paths are reported in the rewritten tree: a single region covering all of
  a node's children reports the node's own path; multiple regions report their nested
  paths under it.
- Fidelity is measured on the untouched absolute base, so recovery can never regrade
  `sampleFidelity`.
- The intent frames each probe residual as a **framework gap** (a missing L1 axis /
  hint / a region needing promotion) to be filed and fed back, not a per-site patch;
  the reports are therefore diagnostic (offending leaf identity + magnitude), not a
  bare boolean. The fold-residual channel serves the same growth loop for folder power
  specifically — the fold decides *what* it cannot express (CAP-71); this story owns
  only the gate's obligation to keep that channel separate and legible.
- Surfaces the fold synthesizes to back text runs (section bands, section images,
  cards) carry no oracle counterpart — their source elements are classified as text and
  are already measured through their own text leaves — so the fidelity measure excludes
  them from the non-text pairing queues. Leaving them in would shift every real box
  leaf by the number of surfaces before it.
- **Occurrence-index pairing is load-bearing across two stories.** The fidelity
  correspondence is valid only while the fold keeps building one leaf per
  responsive-table row in FIFO document order per key (CAP-71 / the fold story).
  BUG-5's intent asked for "a stable identity (index path / node id carried through
  the fold)"; the implementation deliberately narrowed that to the occurrence index
  the fold's responsive table **already** assigns, adding no new node-id field to L1
  nodes — a narrowing recorded in the intent ticket's own implementation note, so
  the matrix describes occurrence-index pairing, not node ids. The AC states the rule
  in terms of document order on both sides, making the dependency explicit. Non-text
  pairing extends the same mechanism with `kind` as the key in place of text.
- **Not to be conflated with the `1c values-diff` duplicate-text pairing** (CAP-72),
  which pairs repeated text by rendered position in a different subsystem. Both
  pipelines handle duplicate text; neither AC covers the other. The two do share the
  ladder/evidence partition rule, which is stated for each pipeline in its own story.
