## What happened
The consultant used `Delegate` (role `builder`) to build one home page of about 9 sections, from a blank page with a placeholder heading. The brief was detailed: full copy, image handles, palette and type direction, and 6 `accept` checks.

- **Pass 1:** `outcome: exhausted` after 64 operations. It built 7 sections but never added the `contact-form` component. That was the key requirement, and the worker's reason for skipping it was that the "brief specified building home page structure, not adding form", which is wrong. Its `last_words` show it read the L1 vocabulary/schema several times over ("I need to understand the page vocabulary better…", "I need to read the L1 vocabulary carefully…", "Let me read the L1 schema outline…") before it wrote anything.
- **Pass 2** (10 follow-up fixes): `outcome: exhausted` after 90 operations. Its final `ReportResult` was refused with `unasked_check` because it paraphrased the check wording, so the summary was only partly recorded. It created palette entries and text styles but never pointed any element at them (see the separate ticket on attention detection). It never set the site title or SEO description.
- **Pass 3** (5 small edits): completed cleanly. However, 2 of its 3 worker-answered checks came back `unreported`, even though its summary answered both of them.

## Expected
A one-page build from a complete brief should finish within one worker's budget. If it can't, the worker should spend its budget on the required content first, not on repeated vocabulary reads.

## Suggestions (the gap is the budget versus the cost of orientation; these are possible fixes, not the only ones)
- Prime the builder with a condensed L1 vocabulary, so it doesn't fetch it piecemeal.
- Allow a larger operation budget for builds that create a page.
- Make `ReportResult` match checks more leniently, or return the exact check strings for the worker to echo back, so a correct answer isn't lost on wording.

## Reproduce
On a blank site, delegate one brief asking for a ~9-section page that includes a contact-form, a palette and text styles. Watch `operations` and `outcome`.

## Root cause (investigation, 2026-10-03)
- **Budget:** the builder runs on `claude-haiku-4-5` with the framework's hard-coded `MAX_TOOL_ITERATIONS = 50` per run, plus one nudge turn that also gets 50 (64 = 50+14, 90 = 50+40). Raising it waits on lagrange-framework REQ-203 (`max_iterations` per backend); `backends.json` already notes `claude_builder` should get 100.
- **Orientation cost:** the builder's priming carries its role text, the *summary* tool manual (no parameter shapes, REQ-171) and, with a system KB, the KB map. The element vocabulary exists only in `kb/system/REF-l1.md` (~40k chars), reachable one KB search/read at a time. On a blank page there is no existing element to copy a shape from, so the whole orientation cost lands on the 50-call budget.
- **Check matching:** framework `delegation_toolbox.js` matches checks nearly exactly, refuses a whole report on one unmatched `passed` entry, and silently drops unmatched `failed` entries (→ `unreported`). Framework-side.

## Scope of this ticket (1stcontact only)
Prime the builder with the page vocabulary so it no longer has to fetch it piecemeal. The budget (REQ-203) and check-matching fixes belong to lagrange-framework and are out of scope here.

### Behaviour
1. Every builder worker's system prompt carries a **page vocabulary** entry, in both declared orders (with and without a system KB), inside the cached prefix (before the cache boundary), so it costs one cache write per deployment rather than a fetch per delegation.
2. The entry is **generated from the L1 element schemas** (`@1stcontact/site-schema`), the same source `REF-l1` is projected from — never authored — so it cannot drift from what the validator accepts. It lists:
   - the page document's keys;
   - every element kind in the node union with the fields it declares (type in words, `required` marked); fields every kind shares are listed once rather than repeated per kind;
   - every named shape those fields reach, one line each, with its fields and their types.
3. It is **condensed**: no per-field prose, and well under half the size of `REF-l1`.
4. It works in both hosts (CLI and Worker): it reads no files at runtime.
5. Only the builder gets it — the consultant's, settings and coordinator priming are unchanged.

## Test plan
- `tests/test_UAT_FC_BUG-182_builder_vocabulary.test.ts`: the vocabulary names every element kind and document key from the schema, every named shape reachable from the kinds, and is under half the size of the projected `REF-l1`; the entry sits before the cache boundary in both builder orders and appears in no other role's priming.
- `tests/test_UAT_FC_BUG-182_builder_is_primed_with_the_vocabulary.workers.test.ts`: driving a real delegation in workerd, the worker's system prompt contains the vocabulary, with and without a system KB, and the consultant's prompt does not.
