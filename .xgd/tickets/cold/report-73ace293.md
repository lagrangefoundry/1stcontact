## Structural Rebalance — Halted: mis-triggered on corrupt data; no valid rebalance exists

I did not execute any splits or merges. Doing so would have mutated a valid capability matrix on the basis of a bug. Here is the full investigation and why.

### What the health check reported vs. reality

The `structural_health_check` (REPORT-867) flagged **all 11 capabilities as `under_min` with `actual_count: 0`**. That is not a real signal — it is an **error** (missing derived state), per the failure/error taxonomy in CLAUDE.md.

**Root cause:** `.xgd/uat_index.json` is **gitignored** (`.gitignore:27`) and per-worktree. It's regenerated by `xgd quality rebuild-uat-index`, but the auto-rebuild only fires after a *hard revert* — **not** when a regression worktree is cut from `main`. So this worktree had no index; `UATCountIndex` loaded nothing and returned 0 for every AC → phantom all-zero counts → `structural_rebalance` was triggered on garbage data. (The `main` worktree's index is intact with 67 UAT tests.)

I regenerated the index in this worktree (`xgd quality rebuild-uat-index` — harmless, gitignored). **Real per-capability counts:**

| Capability | UATs | | Capability | UATs |
|---|---|---|---|---|
| values_diff_fidelity | 10 | | framework_responsive_dials | 0 |
| gradient_fidelity | 5 | | reproduction-module-treatments | 2 |
| size_aware_diffing | 17 | | l1-layout-substrate | 5 |
| 1c CLI Arg Parsing | 5 | | capture-to-l1-fold | 8 |
| framework_value_system | 1 | | capability-modules | 8 |
| | | | reproduction-gate-3probe | 6 |

**Total: 67 UATs across 11 capabilities (~6 each).**

### Why no rebalance can fix this

- **No splits possible:** the max capability is 17 UATs — nothing is near the `max_uats: 200` ceiling.
- **Merges can't satisfy min-20 without destroying the matrix:** with only 67 UATs total and a `min_uats_per_capability: 20`, at most **⌊67/20⌋ = 3** capabilities can clear the minimum. The only groupings that reach ≥20 everywhere collapse the 11 into **2–3 mega-buckets** (e.g. "all 1c toolchain" ≈37, "all framework/L1/capture" ≈30). That fuses genuinely unrelated concerns and destroys the capability boundaries that mirror the documented architecture (L1 substrate, capability modules, 1c diff axes, 3-probe gate…). It directly violates this task's own requirement that new capabilities have *"clear, non-overlapping scope"* and *"accurate descriptions that reflect actual scope."*

There is no semantically coherent rebalance here. The imbalance is not a partitioning problem that moving stories can solve.

### The real resolutions (outside rebalancing's remit)

1. **Fix the bug:** regression-worktree setup (or the health-check prerequisite) must run `xgd quality rebuild-uat-index` before counting UATs, so the check never sees phantom zeros. I've already rebuilt it in this worktree.
2. **Reconcile the threshold with project maturity:** `min_uats_per_capability: 20` is miscalibrated for a 67-UAT project (~6 UATs/cap). Either lower the minimum to fit the project's size or grow UAT coverage — a config/coverage decision, not a story-reassignment. (Side note: `.xgd/config.yaml`'s `structural_validation` block also emits an "Unknown field … will be ignored" warning — worth checking whether the intended override is even taking effect; the value happens to equal the hardcoded default of 20.)
